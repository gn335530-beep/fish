# 助手在地工具改由模型判斷路由

**Source:** 2026-11-23 對話中的診斷與設計收斂。
**Status:** ready-for-agent

## 問題陳述

使用者問「今天海上情況」時，助手回了「你是想賣魚，還是想找魚？也可以直接說『我要賣魚』或『今天有什麼魚』」這句無關的通用引導。

「海上情況」是「海況」的口語說法，但助手的在地問題判定目前只認得「海況」等少數精確字眼。因為沒有認出這是地區問題，後端不會帶入縣市、不會強制海況工具，還因為「今天」命中時效規則，在開啟網路搜尋時反而被強制導去網路搜尋。最後模型給不出有效回覆，前端就落到規則引擎的通用引導句。

## 解決方案

讓模型自行判斷一則訊息是不是天氣／海況問題，並自行呼叫在地工具 `get_local_conditions`；工具在模型沒有帶縣市時，改用使用者的設定縣市。後端不再只用精確關鍵字把關「是不是地區問題」，但仍保留既有的數字接地、天氣回覆不得混入海況、釣魚建議護欄等安全檢查。

使用者角度看：口語的「海上情況」也能得到與「海況」相同的回答——有設定縣市就查該縣市海況；沒設定就反問海域。

## 使用者故事

1. 作為使用者，我想用口語「今天海上情況」問海況時，得到與「今天海況如何？」相同的海況回答，以便不用記特定關鍵字。
2. 作為使用者，我想在已設定縣市時，問「海上情況」自動用我的縣市查海況，而不是被問無關的賣魚／找魚。
3. 作為使用者，我想在訊息裡明確指定縣市時，以訊息中的縣市優先於設定縣市。
4. 作為使用者，我想在訊息裡明確指定海域時，優先使用該海域，而不是縣市預設海域。
5. 作為使用者，我沒設定縣市時，希望助手先反問我（例如「你想問哪個海域？」），而不是猜錯或答非所問。
6. 作為使用者，我想問海況時看到浪高、浪向、浪週期、海溫、風速陣風、該海域天氣與當日滿乾潮，以便判斷要不要出海。
7. 作為使用者，我想問天氣時只看到天氣，不要混入海況、浪或潮汐。
8. 作為使用者，我想確保回覆裡的海況／天氣數字、日期與潮汐時間都來自當輪工具結果，不要出現憑空編造的數字。
9. 作為使用者，我問國外地點天氣時，仍走網路搜尋，不拿台灣的海況或潮汐資料冒充。
10. 作為使用者，我在做平台動作（賣魚、找魚、行情、取消、修改）時，助手仍由規則引擎處理，不被誤導去查天氣或海況。
11. 作為使用者，我問「適合釣魚嗎？」時，仍能拿到依完整海況包給的一般建議，而不是只有數字。
12. 作為釣客，我用口語問海況時，不影響我上架草稿的流程或既有規則式上架。
13. 作為維護者，我想清楚記錄「非地區問題也可能把縣市送給外部服務」這條新的隱私界線，並保留稽核用的 log，以便日後追蹤模型誤判。
14. 作為維護者，我想 ADR、spec、API 文件與詞彙表都同步這項界線變更，避免文件與程式不一致。
15. 作為使用者，當海況工具查不到資料時，我想看到「查不到海況與天氣」或「潮汐暫無資料」的明確說明，而不是空回覆或編造。

## 實作決策

- **模型自行判斷在地問題**：後端不再對「非地區問題誤用在地工具」直接回 `LLM_GUARD_REJECTED`。模型可以在它認為是天氣／海況問題時呼叫 `get_local_conditions`。
- **縣市 fallback 移到工具層**：`get_local_conditions` 在模型沒有提供縣市或海域時，改用使用者的設定縣市（對照 `get_market_price` 的縣市 fallback 行為）。縣市只在工具實際被呼叫時才送到中央氣象署／Open-Meteo，不常駐在 prompt 裡。
- **移除時效性強制工具**：第一輪工具路由不再因為「今天／現在／目前」就強制 `web_search`。網路搜尋工具仍可供模型選擇，由模型自行判斷是否使用。
- **保留精確關鍵字的既有路徑**：對「海況」「天氣」等已認得的地區問題，維持原本的強制工具、縣市注入與反問流程不變；這次改動是加法，讓口語變體也能被模型處理。
- **保留數字與模式護欄**：數字接地、在地單位與方向對照、日期與潮汐時間同組、天氣回覆不得混入海況／潮汐、釣魚建議護欄等安全檢查全部保留；它們依附於工具是否被呼叫，不受這次移除防線影響。
- **國外地點不受影響**：國外地點天氣仍停用在地工具並走網路搜尋。
- **隱私界線變更**：放寬後，模型若誤判（例如把非地區問題拿去查在地），會把使用者的縣市送給中央氣象署／Open-Meteo。這是「動隱私界線」的直接後果，需在 log 記錄模型自行發起的在地工具呼叫，供日後稽核。
- **與 ADR-0013 的關係**：這項變更放寬了 ADR-0013「非地區問題不送縣市」的界線，需要在 ADR-0013 補記取捨與遷移說明，而不是默默覆蓋。

## 測試決策

- **只測外部行為，不測實作細節**：斷言「今天海上情況」得到海況回覆、有設定縣市時用設定縣市、沒縣市時反問海域；不斷言內部 guard 是否存在或錯誤碼字串。
- **主 seam：後端服務層 AI 回覆測試骨架**。用假模型與假上游（Open-Meteo、中央氣象署）走完整 `ai.reply()` 流程，驗證模型自行呼叫 `get_local_conditions` 後的結果。既有同型測試：`ai-tools-sea`、`ai-region-classification`、`ai-local-mode`。
- **次 seam：第一輪工具路由單元測試**。驗證「今天海上情況」不再被強制導去 `web_search`，以及在網搜開啟／關閉兩種設定下的行為。
- **更新既有測試**：目前斷言「非地區問題若模型呼叫在地工具會 fallback／`LLM_GUARD_REJECTED`」的測試要改寫成新行為（允許模型呼叫，並驗證接地回覆）。
- **新增測試**：
  - 口語海況（「今天海上情況」）→ 模型呼叫 `get_local_conditions(mode=sea)` 且不帶縣市 → 用使用者設定縣市查海況 → 回覆含浪況／海溫等接地數字。
  - 同上但沒有設定縣市 → 回「你想問哪個海域？」。
  - 口語天氣（例如「今天外面狀況如何」）→ 模型呼叫 `get_local_conditions(mode=weather)` → 用設定縣市。
  - 明確縣市或明確海域在訊息中 → 優先於設定縣市。
- **不測**：模型在「吳郭魚怎麼煎」這類非地區問題上是否偶爾誤呼在地工具（屬模型品質，非本 spec 行為契約）。

## 不在此範圍

- LLM 關閉或金鑰失效時的規則引擎 fallback 行為（維持現狀：海況／天氣問題在離線時仍回通用引導）。
- 繼續擴充海況／天氣的關鍵字同義詞清單。
- 把縣市常駐放進每一則 prompt（本 spec 選擇工具層 fallback，而非 prompt 層注入）。
- 國外海況與潮汐。
- 區或地址層級的地區問答。
- 把縣市暫存流程（`regionStore` 反問與 30 分鐘暫存）擴充到新的口語變體；這些口語變體的反問主要靠模型與對話歷史接續。

## 其他備註

- 文件同步（依專案規範）：更新 ADR-0013、`docs/spec/03-flows.md`、`docs/api/README.md`、`README.md`，必要時補 `GLOSSARY.md` 的「地區問題／在地模式」定義，反映「模型可自行判斷在地問題並呼叫工具、工具缺少縣市時改用設定縣市」。
- 追問流程：沒縣市時，後端 `regionStore` 的「反問縣市＋暫存 30 分鐘」只對已認得的地區問題自動生效；口語變體靠模型＋歷史接續，使用者接著給縣市或海域時，模型需自行帶入。
- 隱私提醒：放寬後，模型自行呼叫在地工具會把縣市送給中央氣象署／Open-Meteo；如需保守，可先在 log 標記這類呼叫做觀測。
