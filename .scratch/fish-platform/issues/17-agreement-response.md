# 17: 同意、退回、取消與成交

**What to build:** 協議送出後，對方可以同意、退回或取消。同意即成交：各項目計入已售、雙方完成數 +1、協議卡轉已成交；退回進入協商中並保留 15 分鐘，退回方可改條件重送；取消需選原因並立即釋放保留尾數，房內留下系統訊息。（規格：G-11、F7）

**Blocked by:** 16（協議提案與協議卡）

**Status:** resolved

- [x] 非發起方按「同意」後訂單成交，各商品 `sold_quantity` 增加，可售尾數與商品狀態重算正確。
- [x] 成交後雙方 `completed_deals` 各 +1，協議卡顯示已成交。
- [x] 按「退回」後訂單進入協商中，保留 15 分鐘，協議卡顯示已退回。
- [x] 退回方可修改整單金額、地點或時間後重送，重新進入待回覆。
- [x] 任一方取消時必須選原因；取消後保留尾數立即釋放，協議卡顯示已取消。
- [x] 所有狀態變化都在交易房留下對應的系統訊息。

## Comments

- 2026-10-25：後端新增 `POST /api/deals/respond`、`POST /api/deals/cancel`（`routes/deal-response.js`、`lib/deal-status.js`）。`AGREE` 只限非發起方：各項目累加 `sold_quantity`、雙方 `completed_deals + 1`、寫 `confirmed_at`、最新協議卡轉 `confirmed`；`REJECT` 轉 `NEGOTIATING`、`rejected_by` 記下退回方、保留 15 分鐘、卡片轉 `rejected`。取消接受四種原因，轉 `CANCELLED` 並立即釋放（保留量由狀態推導）。
- 2026-10-25：重送沿用 `POST /api/deals/propose`；`NEGOTIATING` 時只有 `rejected_by` 本人能送，成功後重新 `PENDING_REVIEW`、發起方換人、另一方簽核歸零。重送的可售檢查會把這筆訂單自己的保留加回來，整批都保留在同一筆訂單時也能重送。`syncDealCard` 改為只更新最新一張協議卡，舊卡保留退回當時的狀態。
- 2026-10-25：前端協議卡加入「同意／退回」與取消原因選單；只有非發起方能同意或退回，只有目前這張有效的卡會顯示動作。取消前必須先選原因，沒選會提示且不送出。退回方在訂單摘要看到「修改條件並重送」，表單會預填上次的金額、地點與時間；取消原因存在 state，輪詢重繪不會跳回空白。
