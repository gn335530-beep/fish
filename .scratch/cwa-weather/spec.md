# CWA 天氣切換

**Source:** 2026-11-21 CWA 天氣切換討論；原始 `local-conditions` tickets 01–09 已完成。
**Status:** ready-for-agent

## Problem Statement

助手目前的一般天氣走 Open-Meteo，不是中央氣象署官方預報；「現在氣溫」也是模型預報值，不是實際觀測。使用者希望天氣回答改用中央氣象署官方預報，並以自動氣象站觀測提供目前氣溫。海況、浪高、海溫與潮汐維持現狀，避免這次變更同時改動兩個資料來源。

## Solution

一般天氣問題改用中央氣象署 `F-D0047-091` 取得 7 日縣市預報，並用 `O-A0001-001` 取得最近自動氣象站的目前氣溫。天氣回覆保留既有欄位與換行格式；目前氣溫標明觀測時間。CWA 預報失敗時直接回「查不到即時天氣」，不 fallback 回 Open-Meteo。海況、海溫與潮汐不變。

## User Stories

1. 作為助手房使用者，我想問「今天天氣如何？」時看到中央氣象署官方預報，以便和官方資訊一致。
2. 作為助手房使用者，我想看到自動氣象站觀測的目前氣溫，以便知道實際觀測值，而不是模型估計。
3. 作為助手房使用者，我想看到目前氣溫的觀測時間，以便判斷資料新舊。
4. 作為助手房使用者，我想看到中央氣象署的今日最高／最低溫、降雨機率、風向與風速，以便安排當天活動。
5. 作為助手房使用者，我想問「明天天氣」或「這週天氣」時看到對應日期的中央氣象署預報，以便提前安排。
6. 作為助手房使用者，我想系統預設使用設定頁縣市，以便不用每次說地點。
7. 作為助手房使用者，我想在訊息中明確說「花蓮」時以花蓮為準，以便查詢其他縣市。
8. 作為助手房使用者，我沒設定縣市時，希望助手先問「你所在的縣市是哪裡？」，以便不猜錯地區。
9. 作為助手房使用者，我希望回答縣市後只在目前對話記住，不寫回個人設定，以便保留控制權。
10. 作為助手房使用者，我希望天氣問題只回天氣，不混入海況、浪或潮汐，以便快速得到答案。
11. 作為助手房使用者，我希望 CWA 預報查不到時明確看到「查不到即時天氣」，而不是被 Open-Meteo 或模型猜測取代。
12. 作為助手房使用者，我希望只有自動氣象站觀測失敗、但預報成功時，仍能看到預報，並標示「目前氣溫暫無資料」，以便不要整則失去天氣資訊。
13. 作為助手房使用者，我希望目前氣溫不會拿 12 小時平均預報溫度冒充觀測值，以便資訊誠實。
14. 作為助手房使用者，我希望天氣回答的數字都來自當輪 CWA 工具結果，以便避免編造的氣溫、降雨機率或風級。
15. 作為助手房使用者，我希望回答開頭寫出縣市，例如「高雄市的天氣」，以便知道系統用了哪個縣市。
16. 作為助手房使用者，我希望天氣回答保留換行，以便閱讀多個欄位。
17. 作為助手房使用者，我希望預設不顯示來源卡、回覆文字沒有 URL，以便畫面乾淨。
18. 作為助手房使用者，我想在下一句問「來源是哪個網站？」時看到中央氣象署預報與觀測來源，以便查證。
19. 作為助手房使用者，我希望來源卡最多 3 個合法連結，且不混入模型自行產生的網址。
20. 作為助手房使用者，我希望海況、浪高、海溫與潮汐維持原本行為，以便這次改動不影響海邊活動查詢。
21. 作為助手房使用者，我希望「今天適合釣魚嗎？」仍使用完整海況包，不受 CWA 天氣切換影響。
22. 作為助手房使用者，我希望國外地點天氣仍走 Tavily，不誤用台灣 CWA 天氣，以便查詢東京等城市。
23. 作為助手房使用者，我希望平台操作（賣魚、行情、取消、修改）完全不受天氣切換影響，以便交易流程穩定。
24. 作為助手房使用者，我希望系統只把我的縣市送給 CWA，不送區、地址、電話或 Email，以便保護隱私。
25. 作為維護者，我希望 CWA 預報與觀測的失敗路徑沿用既有 fallback 與錯誤碼，以便不新增第二套錯誤處理。
26. 作為維護者，我希望天氣工具結果維持既有欄位形狀，只新增觀測資訊，以便 prompt、前端與來源流程不用大改。
27. 作為維護者，我希望 CWA API 的地點篩選即使被上游忽略，後端仍會在本地過濾正確縣市，以便結果可預測。
28. 作為維護者，我希望自動氣象站選擇規則明確：同一縣市、有有效溫度、靠近縣市代表點、優先低海拔測站，以便不同縣市結果穩定。
29. 作為維護者，我希望缺少 `CWA_API_KEY` 時天氣明確不可用，不偷偷 fallback 回 Open-Meteo，以便來源單一。
30. 作為維護者，我希望測試只注入假 CWA、假 Open-Meteo、假 Tavily 與假 Gemini，不呼叫真實網路，以便測試穩定。
31. 作為維護者，我希望新增與修改的程式碼檔案不超過 200 行，以便符合專案規範。
32. 作為維護者，我希望 ADR、spec、README 與 `GLOSSARY.md` 同步更新，以便文件與程式一致。
33. 作為維護者，我希望這次不修改海況、潮汐、國外天氣、來源暫存或平台寫入流程，以便變更範圍可審。
34. 作為維護者，我希望先完成 `local-conditions-review-followup` 或在其之上實作，以避免天氣模式與數字防護衝突。

## Implementation Decisions

- **天氣預報**使用中央氣象署 `F-D0047-091`，以縣市名稱查詢，取 `T`、`Wx`、`MaxT`、`MinT`、`PoP12h`、`WS`、`WD`。
- `F-D0047-091` 的 `T` 是 12 小時平均溫度，不作為「目前氣溫」；目前氣溫只來自自動氣象站觀測。
- **目前觀測**使用中央氣象署 `O-A0001-001`；後端取得回應後，依 `GeoInfo.CountyName` 在本地過濾，不依賴上游 `StationName` 或 `locationName` 篩選。
- 測站選擇：同縣市、`AirTemperature` 不是 `-99`、靠近縣市代表點，優先低海拔測站；回傳測站名稱、觀測時間、氣溫。
- 目前天氣現象與風速風向優先使用自動氣象站觀測；觀測缺項時才用 `F-D0047-091` 的 `Wx`、`WS`、`WD`。陣風優先使用觀測的 `GustInfo.PeakGustSpeed`，沒有就留空。
- 今日高低溫、降雨機率與未來 7 日預報全部來自 `F-D0047-091`；12 小時分段在後端整理成每日資料。
- 天氣工具結果維持既有 `weather` 欄位形狀，新增 `observation` 與 `observation_error`；`current_temperature_c` 只放觀測值，觀測失敗時為 `null`。
- `F-D0047-091` 失敗、缺少 `CWA_API_KEY`、格式錯誤或逾時：`weather` 為 `null`，沿用既有「查不到即時天氣」回覆；**不 fallback 回 Open-Meteo**。
- 只有 `O-A0001-001` 失敗：仍回 `F-D0047-091` 預報，`current_temperature_c` 為 `null`，回覆標示「目前氣溫暫無資料」；不編造目前氣溫。
- 天氣問題只使用天氣模式；海況、潮汐、釣魚建議仍使用既有海況包。
- **海況包裡的天氣維持 Open-Meteo**；這次只切換單純天氣問題。這是刻意縮小範圍，避免同時改動海況與海溫。
- 來源卡：天氣回答可列中央氣象署天氣預報與中央氣象署自動氣象站觀測兩個來源；預設不回傳，使用者明確要求時才回傳，最多 3 個合法 URL。
- 回覆文字中的 URL 一律移除；來源只由後端工具結果產生。
- 目前日期仍使用 Asia/Taipei；回覆開頭使用縣市名稱。
- 不新增頂層 API 欄位或新卡片型別；只擴充既有 `tool_results.local.weather` 的觀測子欄位。平台意圖與交易房行為不變。
- 新增 ADR-0014 記錄「天氣改 CWA、海況維持 Open-Meteo、CWA 失敗不 fallback」；更新 ADR-0013 的交叉引用與資料來源描述。
- `CWA_API_KEY` 是唯一新增設定；不需要新的 provider key。

## Testing Decisions

- 好測試只驗外部行為：`POST /api/ai/reply` 的 `handled`、`intent`、`reply_text`、`sources`、`tool_results.local.weather`、`error_code`，以及前端使用者看到的訊息與來源卡。
- 不測私有 helper、不鎖定 prompt 全文；需要確認工具是否被呼叫時，看假上游收到的請求。
- 每個失敗路徑都要有成功對照：預報成功／失敗、觀測成功／失敗、來源要求／無來源、天氣／海況。
- 使用既有 seam：後端 `POST /api/ai/reply` 搭配假 Gemini、假 CWA、假 Open-Meteo、假 Tavily；前端既有助手流程搭配 mock 端點。不新增第三個 seam。
- **假 CWA 是一個 upstream，內含預報與觀測兩個端點**；測試依請求 URL 分辨 `F-D0047-091` 與 `O-A0001-001`，可分別模擬成功、逾時、5xx、格式錯誤與缺資料。
- 假 Gemini 用於提供固定的 tool call 與最終 JSON，並模擬模型自行產生未支持數字、錯誤 intent、格式錯誤與逾時；不測 Gemini 的語言品質。
- 假 Open-Meteo 只用於海況與「天氣不應呼叫 Open-Meteo」的回歸；假 Tavily 只用於國外地點天氣、一般網路與來源請求的回歸。
- 必要案例：
  - CWA 預報＋觀測成功：回覆含觀測氣溫、觀測時間、今日高低溫、降雨機率、風速風向。
  - 明確縣市優先於設定縣市。
  - 缺縣市時反問；回答後只在對話暫存。
  - CWA 預報逾時、5xx、格式錯誤或缺少金鑰：回「查不到即時天氣」，不呼叫 Open-Meteo。
  - 只有觀測逾時、無測站或溫度缺值：仍回預報，標示「目前氣溫暫無資料」。
  - 天氣問題不含海況、浪或潮汐。
  - 海況問題仍使用 Open-Meteo Marine／Weather 與 CWA 潮汐。
  - 天氣後下一句要求來源：重查 CWA 並顯示來源卡，不呼叫模型。
  - 模型自行產生 99°C、90%、8 級等未支持數字時被數字防護擋下。
  - 國外地點天氣仍走 Tavily。
  - 前端保留換行、來源卡最多 3 個、平台意圖不被地區反問覆蓋。
- Prior art：既有天氣工具、海況工具、潮汐工具、地區上下文、來源請求、數字防護與國外天氣測試。
- 完成前跑 `npm test`，確認全綠；測試不呼叫真實 Gemini、Tavily、Open-Meteo 或 CWA。
- 真實 API 的欄位變動、Gemini 語言品質與 Tavily 搜尋品質不放在 `npm test`；以一次性手動 smoke test 確認，使用真實金鑰與真實 API。

## Out of Scope

- 海況、浪高、海溫改用 CWA。
- 海況包裡的天氣改用 CWA。
- 潮汐資料集或潮位站變更。
- 國外地點天氣行為變更。
- 天氣或海況快取。
- 來源暫存。
- 新卡片型別或新頂層 API 欄位。
- 平台動作、交易房、訂單、協議或評價流程。
- 區或地址層級的天氣問答。
- `local-conditions-review-followup` 的 8 張 ticket；那是另一個變更，建議先完成或在其之上實作。
