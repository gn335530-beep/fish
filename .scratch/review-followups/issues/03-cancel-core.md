# 03: 取消核心統一使用者取消與逾時取消

**What to build:** 使用者主動取消與逾時掃描目前各寫一份欄位更新。後端抽出一個取消核心，接受操作者（使用者或系統）、取消原因代碼、要同步的卡片狀態與要留下的系統訊息；兩者都呼叫這個核心，差異只剩參數。逾時掃描仍以「狀態＋到期時間」判斷，狀態一旦離開待回覆／協商中就不再重複處理。取消原因代碼與既有系統訊息文字維持不變。後端狀態常數模組只放狀態清單與「進行中」判定；狀態轉移模組改名為可與常數區分的名稱，所有引用同步更新，不留舊名別名。卡片同步模組的匯出語句獨立成行。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 使用者取消與逾時取消產生相同的訂單狀態、保留釋放、商品可售量與卡片狀態，但操作者與系統訊息不同。
- [x] 重複掃描不會重複取消，也不會重複寫入系統訊息。
- [x] 取消原因代碼與使用者看到的系統訊息文字不變。
- [x] 狀態常數模組不再包含狀態轉移邏輯；狀態轉移模組名稱可與常數區分，且沒有舊名別名。
- [x] 卡片同步模組的匯出語句獨立成行。
- [x] 訂單回應、逾時掃描與交易歷史測試全綠。

**Source:** `.scratch/review-followups/spec.md` 的「訂單生命週期」。
