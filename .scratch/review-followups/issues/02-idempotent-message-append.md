# 02: 訊息串接冪等：共用狀態層取代與追加

**What to build:** AI 一次回覆多則訊息時，3 秒輪詢可能把同一則訊息再顯示一次，且「已讀到第幾則」的游標可能落後。前端共用狀態層新增兩個公開動作：以完整清單取代訊息，以及追加訊息。追加時以訊息序號去重，序號缺漏時退回以訊息識別碼去重；重複訊息不改變順序，也不重複計入未讀。游標取清單中最大序號，而不是最後一筆陣列的序號。AI 回覆流程與輪詢都只透過這兩個動作改動訊息；清除歷史後只留新訊息走取代路徑。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 追加重複序號的訊息不會增加清單長度，游標停在最大序號。
- [x] 訊息缺漏序號時，以識別碼去重。
- [x] 追加以外的訊息順序穩定；重複訊息不重排，也不重複計入未讀。
- [x] 輪詢與 AI 回覆同時發生時，畫面不出現重複訊息，順序穩定。
- [x] 清除歷史後只保留新訊息，且不走去重路徑。
- [x] 共用狀態層的公開動作測試涵蓋追加去重、游標前進與清單取代；既有房間與同步測試全綠。

**Source:** `.scratch/review-followups/spec.md` 的「訊息串接」。
