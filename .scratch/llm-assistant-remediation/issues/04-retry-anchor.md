# 04: 重試錨定原始訊息

**What to build:** 重試永遠回答被重試的那一則訊息。即使使用者在按重試前又送出新訊息，模型也不會看到更新內容，回覆不會被寫成新訊息的重試結果，也不會重複寫入使用者訊息。

**Blocked by:** 01（後端 AI service 拆分與錯誤一致化）

**Status:** resolved

- [x] 對訊息 A 呼叫回覆時，即使同房已有較新的訊息 B，provider 收到的最後一則 user turn 是 A，且 B 不在歷史中。
- [x] 歷史只取錨定訊息以前、同一間助手房的最近 10 則使用者／助手訊息；若錨定訊息因限制缺席，後端要補回最後一則。
- [x] 重試沿用原本的 `message_id`，不新增使用者訊息，也不信任前端文字。
- [x] 交易房仍然完全不呼叫 LLM。
- [x] 端點測試涵蓋「A → B → 重試 A」與重試不重複寫入訊息。
