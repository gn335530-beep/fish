# 交易房聊天室畫面重製

**Status:** ready-for-agent

**Source:** 2026-11-01 對話與手繪骨架。骨架包含商品卡面、詢價推薦小卡、行情小卡、聊天室、評價小卡、交易房、發送交易、加購、協議卡、確認取消卡、協議已被取消卡，以及交易房標題列的評價星星。

## Problem Statement

目前的交易介面是在既有 v7 浮動面板上層層加功能：交易房有電話橫幅、可展開訂單摘要、逐項加減、清空、協商完畢、協議卡同意／退回／取消與行內取消原因選單；商品卡是橫式小卡，完整資訊只能進商品詳情頁；行情卡用商品重量算參考整批；評價卡用下拉選星等、五個標籤。

使用者要的是一套照骨架重製的介面：

- 商品卡面直接放在首頁與今日漁獲，不再需要商品詳情頁。
- 交易房以浮動商品條為核心，加購與發送交易展開後取代商品條。
- 協議卡只留「確認／取消」兩個動作；取消原因改成自由文字，並送出一張「協議已被取消」卡。
- 交易房標題列直接顯示對方評價星星與電話。
- 價格在交易房、發送交易、加購一律顯示每台斤。
- 上架不再填重量；行情卡的重量欄位改成即時試算工具，台斤／公斤可切換。
- 聊天室訊息區使用 `paper-2` 米色底，底部加入語音輸入，送出改成圖示。

同時要刪掉骨架沒有用到的文字、按鍵與頁面，避免舊流程與新畫面並存。

## Solution

照骨架重製八個元件，並補上協議卡、取消卡、取消訊息卡與交易房評價星星：

1. **商品卡面**：首頁與今日漁獲使用大卡；移除商品詳情頁與「查看詳情」。
2. **詢價推薦小卡**：助手房搜尋結果使用橫式小卡。
3. **行情小卡**：保留平均價、走勢、日期與來源；重量改為使用者輸入並即時試算參考價格。
4. **聊天室**：標題列、`paper-2` 訊息區、語音／相機／輸入／送出圖示。
5. **評價小卡**：可點星等、四個標籤、評語、確認。
6. **交易房**：對方名稱＋評價星星＋電話；浮動置頂商品條；訊息流在下方捲動。
7. **發送交易**：展開後取代商品條；數量、售價、面交時間、面交地點、確認。
8. **加購**：展開後取代商品條；同一位釣客所有商品、批次確認。
9. **協議卡**：收件方看到取消／確認；發起人只看卡片；確認後等待確認變已確認。
10. **取消流程**：確認取消卡（自由文字原因）→ 取消訊息卡「協議已被取消」→ 交易房可重新發起協議。
11. **交易房標題列**：對方名稱下方顯示五顆星。

資料層同步調整：上架移除重量與自動計算整批、訂單項目補魚種與每台斤價格、取消原因補自由文字、取消後可重新建立草稿、加購改成批次加入。

## User Stories

1. 作為買家，我想在首頁直接看到完整商品卡，以便不必點進詳情頁就能判斷要不要買。
2. 作為買家，我想在今日漁獲看到同樣的商品卡，以便列表與首頁資訊一致。
3. 作為買家，我想在商品卡看到魚種、處理方式、尾數、每台斤售價、整批售價與地區，以便快速比較。
4. 作為買家，我不想在商品卡看到重量，以便畫面只留實際會用到的資訊。
5. 作為買家，我想按「洽談購買」直接開交易房，以便少一個跳頁。
6. 作為買家，我不想看到「查看詳情」與商品詳情頁，以便交易只走對話。
7. 作為買家，我想在助手房看到橫式推薦小卡，以便在對話中快速掃過多個商品。
8. 作為買家，我想在交易房上方一直看到目前商品與剩餘尾數，以便訊息捲動時不會失去上下文。
9. 作為買家，我想在商品條按「加購」看到同一位釣客的所有商品，以便一次加購多項。
10. 作為買家，我想在加購面板一次填多個數量並按確認，以便不必一項一項加入。
11. 作為買家，我想在商品條按「發送交易」填數量、售價、面交時間與地點，以便送出協議。
12. 作為買家，我想在只有一個商品時直接改數量，以便不必回到其他畫面。
13. 作為買家，我想在發送交易時看到整單總價，以便確認要付多少。
14. 作為買家，我想在協議卡看到魚種、販售數量、最終價格、面交時間與地點，以便確認內容。
15. 作為買家，我想只有收件方能按確認或取消，以便發起人不會誤按自己的協議。
16. 作為買家，我想對方確認後看到「已確認」，以便知道交易成立。
17. 作為買家，我想取消協議時填寫原因，以便對方知道為什麼取消。
18. 作為買家，我想在取消卡按取消就回到協議卡，以便改變心意時不會留下紀錄。
19. 作為買家，我想取消後雙方都看到「協議已被取消」卡與原因，以便對話有紀錄。
20. 作為買家，我想取消後留在交易房並能重新發起協議，以便不用重新找商品。
21. 作為買家，我想在交易房標題列看到對方評價星星，以便判斷要不要交易。
22. 作為買家，我想看到對方電話並可直接撥打，以便約面交。
23. 作為買家，我想在行情卡輸入重量就即時看到參考價格，以便估算整批金額。
24. 作為買家，我想在行情卡切換台斤與公斤，以便用習慣的單位輸入。
25. 作為買家，我想行情卡只顯示平均價與來源，以便畫面乾淨。
26. 作為買家，我想在成交後用星星與標籤評價對方，以便留下紀錄。
27. 作為買家，我想最多選三個評價標籤，以便評價不過於發散。
28. 作為釣客，我想上架時不用填重量，以便少一個欄位。
29. 作為釣客，我想直接填整批售價與每台斤售價，以便不用等系統換算。
30. 作為釣客，我想在交易房看到每台斤價格，以便與買家討論單價。
31. 作為使用者，我想在聊天室用語音輸入，以便不方便打字時也能傳訊息。
32. 作為使用者，我想在瀏覽器不支援語音時看到明確提示，以便知道不是按鈕壞掉。
33. 作為使用者，我想聊天室訊息區是 `paper-2` 米色底，以便閱讀訊息。
34. 作為維護者，我想刪除商品詳情頁與相關連結，以便不再維護兩套商品呈現。
35. 作為維護者，我想取消原因以自由文字保存，以便不再受限於固定選項。
36. 作為維護者，我想取消後能重新建立草稿，以便交易房可重複使用。
37. 作為維護者，我想加購用批次端點，以便只留一則系統訊息。
38. 作為維護者，我想協議卡有魚種快照，以便不解析商品長標題。
39. 作為維護者，我想所有程式碼檔案不超過 200 行，以便符合專案規範。
40. 作為維護者，我想 spec、API 文件與測試同步更新，以便畫面與資料模型一致。

## Implementation Decisions

### 1. 範圍與頁面

- **商品卡面**只出現在 `pages/index.html` 的今日漁獲與 `pages/products.html` 的漁獲列表。
- **其餘七個元件**都在右下角 chat bot 面板內。
- **商品詳情頁刪除**：`pages/product-detail.html`、`assets/js/pages/product-detail.js`、所有指向 `product-detail.html` 的連結與「查看詳情」按鈕。
- 商品詳情頁上的「釣客評價」與「今日其他漁獲」一併移除；評價只保留在交易紀錄與評價卡。
- `GET /api/products/:id` 保留，供對話與内部使用，不再有對應頁面。

### 2. 商品卡面（首頁、今日漁獲）

- 直式卡片，圖片在上（`aspect-ratio: 3/2`），內容在下。
- 內容順序：
  1. 魚種（大字，使用 `fish_species`）
  2. 處理方式徽章（圓形或膠囊，標「處理方式」＋`condition`）
  3. `共 N 尾`（使用商品 `quantity`）
  4. `每台斤售價：NT$X`（`price_per_taijin` 有值才顯示）
  5. `整批售價：NT$X`（`price`）
  6. 地區＋地點（`region`＋`location`；缺漏顯示「地區未提供」）
  7. 按鈕列：`賣家資訊`、`洽談購買` 兩個按鈕並排；`洽談購買` 為主要按鈕，`賣家資訊` 為次要按鈕
- **移除**：重量、`每尾均價`、釣獲／上架日期、`查看詳情`、數量下拉、`自動計算`標記。
- 可售狀態：
  - `available > 0`：按鈕列顯示 `賣家資訊` 與 `洽談購買`。
  - `available <= 0` 且 `reserved_quantity > 0`：保留 `賣家資訊`，`洽談購買` 換成「洽談中，暫無法購買」。
  - `available <= 0` 且沒有保留：保留 `賣家資訊`，`洽談購買` 換成「已售出」。
- `洽談購買` 以 `data-deal-product` 啟動交易，預設數量 1；數量在發送交易面板調整。
- **賣家資訊按鈕**：
  - 只顯示，不綁定任何行為；不開面板、不導頁、不顯示 toast。
  - 保留 `data-action="seller-info"` 供後續接賣家資料。
  - 與 `洽談購買` 等寬並排；窄版卡片可換行。
- 用語：骨架的「每斤售價」一律寫成「每台斤售價」；「共 N 尾」使用「尾」。

### 3. 詢價推薦小卡（助手房）

- 橫式卡片：左側縮圖（72px），右側內容。
- 內容：魚種＋處理方式、`共 N 尾`、`每台斤售價`（若有）、`整批售價`、地區、`洽談購買`。
- **移除**：重量、`深入諮詢`、`每尾均價`、數量下拉、`自動計算`標記。
- 可售狀態：`available > 0` 顯示 `洽談購買`；`available <= 0` 顯示「洽談中，暫無法購買」或「已售出」，不顯示按鈕。
- 推薦小卡沒有 `賣家資訊` 按鈕。
- `洽談購買` 以 `data-action="start-deal"` 啟動交易，預設數量 1。

### 4. 行情小卡（助手房）

- 卡片標題：`行情卡`。
- 主資訊：魚種（`species_name`）＋平均價（`price_per_taijin` 元／台斤）。
- 範圍：縣市平均或全國平均（沿用 `marketScope`）。
- 走勢切換：`7日`／`30日`（沿用 `data-action="market-days"`）。
- 走勢圖：顯示最高／最低標記。
- 日期：交易日期＋`近 7／30 個交易日`；切換 7／30 日後分別顯示「近7個交易日」與「近30個交易日」。
- 重量試算：
  - 重量輸入框（數字，可空白）。
  - 單位切換：`台斤`／`公斤`，預設台斤。
  - `參考價格 = round(平均價 × 重量台斤)`。
  - 重量空白或非正數時，參考價格顯示 `—`。
  - 切換單位不換算重量數字，只以新單位重新計算參考價格（例如 2 台斤 NT$400 ↔ 2 公斤 NT$667）。
  - 即時計算，不打 API。
  - 標籤：`參考價格`，下方小字 `（依重量計算整批價格）`。
- 底部右下：`資料來源：農業部 漁業署`（固定官方來源文字）。
- **移除**：`行情價參考`、`養殖價格`、官方名稱獨立行、`參考整批`標籤。
- 狀態：每個訊息各自保存重量與單位，切換 7／30 日不重置。

### 5. 聊天室外殼

- 面板尺寸（助手房與交易房相同）：
  - 桌機：寬 `clamp(320px, calc((100vw - 64px) / 3), 400px)`，高 `min(520px, calc(100vh - 120px))`。
  - 視窗 ≤ 760px：全螢幕。
  - **移除** `fm-panel--wide` 與 440×760 交易房尺寸。
- 標題列：
  - 助手房：頭像、`AI 聊天小幫手`、`☰`、`─`、`✕`。
  - 交易房：頭像、對方名稱、名稱下方五顆評價星星、`撥打電話`＋電話號碼、`☰`、`─`、`✕`。
  - 收件匣沿用助手房標題。
  - **移除** `v7` 版本標記與狀態副標。
- 對方評價星星：
  - 依 `peer.rating_score` 顯示 5 顆星，半星以 0.5 為單位。
  - `review_count` 為 0 或 `rating_score` 為 0 時顯示空心星＋`尚無評價`。
  - 星星不可點；`aria-label` 為「評價 X 分，Y 則」。
  - 資料使用房間摘要的 `peer`（`publicUser` 已含 `rating_score`、`review_count`）。
- 電話按鈕：
  - 使用 `tel:` 連結，文字「撥打電話」＋號碼。
  - 沒有電話時顯示「電話未提供」，不可點。
- 訊息區：
  - 背景 `paper-2`（米色）。
  - 標題列、頁尾、卡片、按鈕仍可使用品牌色。
- 頁尾：
  - 由左至右：語音輸入、相機、文字輸入框、送出圖示。
  - 送出改成圖示按鈕，`aria-label="送出"`；移除「送出」文字。
  - 文字輸入上限 500 字。
- 語音輸入：
  - 使用 `window.SpeechRecognition || window.webkitSpeechRecognition`。
  - 語言 `zh-TW`，單次辨識，結果附加到輸入框。
  - 按下時按鈕顯示錄音中狀態（`aria-pressed`）。
  - 不支援或權限被拒時顯示提示，不送出空訊息。

### 6. 交易房外殼與浮動商品條

- 交易房標題列如第 5 節：對方名稱、評價星星、電話。
- **移除**電話橫幅、可展開訂單摘要、狀態說明文字。
- **浮動商品條**：
  - 位於訊息區頂端，`position: sticky; top: 0`，有背景、邊框與陰影。
  - 訊息往上捲時商品條固定在最上方；訊息從下方通過。
  - 商品條與其下開面板同屬一個置頂容器；面板展開後取代商品條，訊息仍在下方捲動。
  - 多商品時每個商品一列。
  - 每列內容：魚種、處理方式（若有）、`剩 N 尾`、`N 元/台斤`。
    - `剩 N 尾` 使用該商品目前可售尾數。
    - `N 元/台斤` 優先使用 `price_per_taijin`；沒有時顯示 `整批 NT$X`。
  - 右側動作：`加購`、`發送交易`。
  - 面板展開時取代商品條，面板內提供 `收起`。
  - 沒有商品時顯示「尚未加入商品」，`發送交易`停用。
- **移除**：逐項加減、刪除、清空、`協商完畢`、`修改條件並重送`、狀態 pill、項目數／總尾數／小計摘要列。
- 商品條不提供逐項移除；要調整商品組合時，取消協議後重新發起（見第 11 節）。

### 7. 發送交易面板

- 由商品條的 `發送交易` 展開，展開後取代商品條，位於訊息區頂端。
- 面板內提供 `收起`；按 `收起` 只收合面板，不送出。
- 上方商品摘要：魚種、處理方式（若有）、`剩 N 尾`、每台斤或整批價格；與浮動商品條使用同一套摘要。
- 欄位：
  1. `數量`：
     - 只有一個商品時：可編輯數字，範圍 1 到該商品可售尾數。
     - 多個商品時：唯讀，顯示整單總尾數。
  2. `售價`：整單總價，預填目前訂單小計（`items_total`），可修改。
  3. `面交時間`：`datetime-local`。
  4. `面交地點`：文字，最多 100 字。
  5. `確認`：送出協議。
- 沒有 `取消` 按鈕；收起即可離開。
- 驗證：
  - 數量必須是正整數且不超過可售。
  - 售價必須大於 0。
  - 面交地點必填。
  - 面交時間必填且有效。
- 送出流程：
  1. 若只有一個商品且數量有變，先 `PATCH /api/deals/items/:itemId` 更新數量。
  2. `POST /api/deals/propose`，帶 `final_price`、`meetup_location`、`meetup_time`。
  3. 收起面板，重新載入房間。
  4. 協議卡出現在訊息流；發起人看到無按鈕版本。
- 面板草稿值在收起後保留，送出成功或切換房間後清空。

### 8. 加購面板

- 由商品條的 `加購` 展開，展開後取代商品條，位於訊息區頂端。
- 面板底部提供 `取消` 與 `確認`；`取消` 只收合面板，不送出。
- 清單：同一位釣客的所有商品（`listProducts({ seller_id, limit: 100 })`），**包含已加入訂單的商品**。
- 每列內容：
  - 魚種
  - 處理方式（若有）
  - `剩 N 尾`（目前可售）
  - `N 元/台斤`（沒有時顯示整批價）
  - `加購數量` 數字輸入（0 到可再加購尾數）
- 可再加購尾數 = 商品可售 − 該商品已在草稿中的尾數；0 時停用輸入。
- 底部：`取消`、`確認`。
- `取消`：收起面板，不改訂單。
- `確認`：
  - 收集所有數量大於 0 的列。
  - 呼叫批次端點一次加入；只留一則系統訊息。
  - 收起面板並重新載入房間。
- 沒有可加購商品時顯示「目前沒有可加購的商品」。

### 9. 協議卡

- 卡片標題：`協議`。
- 狀態徽章：
  - `等待確認`（coral）
  - `已確認`（accent）
  - `已取消`（muted）
  - `已逾時`（沿用既有逾時狀態）
- 內容：
  - 魚種：每個項目一行；單項顯示一個魚種，多項逐行顯示。
  - `販售數量：N 尾`（整單總尾數）。
  - `最終價格：NT$X`（`final_price`）。
  - `面交時間：…`
  - `面交地點：…`
- 按鈕權限：
  - 收件方（`initiator_id !== user.id`）且狀態為等待確認：`取消`、`確認`。
  - 發起人：不顯示按鈕。
  - 已確認／已取消／已逾時：雙方都不顯示按鈕。
- `確認`：
  - 呼叫 `POST /api/deals/respond`，`action: "AGREE"`。
  - 雙方輪詢後看到徽章 `等待確認` → `已確認`。
- `取消`：
  - 不直接送出；在協議卡位置換成「確認取消」卡（見第 10 節）。
- **移除**：`退回`、`NEGOTIATING` 重新送出流程、行內取消原因下拉選單。
- 卡片狀態文案：`CARD.confirmed` 由「已成交」改為「已確認」；訂單列表仍使用「已成交」。
- 舊資料若已有 `rejected` 狀態，仍可顯示「已退回」，但新流程不再產生。

### 10. 確認取消卡與取消訊息卡

**確認取消卡**（本地狀態，不是訊息）：

- 按下協議卡 `取消` 後，在協議卡位置顯示。
- 內容：
  - 標題 `確認取消`
  - 提示 `請填寫取消原因`
  - textarea（必填，最多 200 字）
  - `取消`、`送出`
- `取消`：移除確認取消卡，回到原本協議卡；協議卡仍可正常操作。
- `送出`：
  - 原因空白時顯示提示，不送出。
  - 呼叫 `POST /api/deals/cancel`，帶 `deal_id` 與 `note`。
  - 後端設定 `cancel_reason: "OTHER"`、`cancel_note: note`、`deal_status: CANCELLED`。
  - 同步最新協議卡狀態為 `cancelled`。
  - 新增一張 `deal_cancelled` 卡片訊息。
  - 雙方重新載入後都看到取消訊息卡。
- 確認取消卡只對按取消的人顯示；對方在看到取消訊息卡前不會看到這個本地卡片。

**取消訊息卡**：

- 卡片型別：`deal_cancelled`。
- 標題：`協議已被取消`。
- 內容：`取消原因`＋自由文字；空白時顯示「未填寫」。
- 雙方都看得到。
- 顯示在協議卡之後，作為這次取消的紀錄。

### 11. 重新發起協議

- 取消後畫面留在交易房。
- 商品條顯示最後一筆訂單的商品（魚種、剩餘尾數、每台斤價格）。
- 按 `發送交易` 時：
  - 若目前沒有進行中的草稿，呼叫 `POST /api/deals/reinitiate`，帶最後一筆訂單的 `deal_id`。
  - 後端在同一個交易房建立新的 `DRAFT` 訂單，複製原項目與數量。
  - 每項數量上限為目前可售；可售 0 的項目略過並提示。
  - 只留一則系統訊息。
  - 建立成功後展開發送交易面板。
- 若沒有任何項目可重新發起，顯示「目前沒有可重新發起的商品」。
- 重新發起後，商品條與協議流程回到一般狀態。

### 12. 評價小卡

- 卡片標題：`評價`。
- `整體評分`＋五顆可點星星：
  - 預設 5 顆。
  - 點擊設定 1–5 星。
  - 可用鍵盤操作（按鈕或 radio group）。
- 四個標籤，2×2 排列：
  - `魚貨新鮮`
  - `準時守約`
  - `溝通良好`
  - `臨時放鳥`
  - 最多選 3 個。
- 評語 textarea，placeholder `留下你的評價吧！`，最多 100 字。
- `確認` 送出。
- **移除**：`已評價／待評價` pill、`包裝完善` 標籤。
- 已送出後：
  - 顯示「你已經送出評價。」
  - 對方已評：「雙方都完成了。」
  - 對方未評：「等待對方評價。」
- 前端與後端標籤清單同步為四個；`臨時放鳥` 仍是 `NO_SHOW_TAG`。

### 13. 重量與價格規則

- **上架不再填重量**：
  - 移除上架流程的重量提問、草稿卡 `總重`、商品卡重量、推薦卡重量、交易房重量、加購重量。
  - `weight_kg` 改為選填／legacy；新商品可省略，舊資料保留但不顯示。
- **整批售價必填**：
  - 上架填 `整批售價`（`price`）與可選的 `每台斤售價`（`price_per_taijin`）。
  - 只填每台斤時，因沒有重量可換算，回傳「請提供整批售價」。
  - 不再產生新的 `price_auto`；舊資料的 `price_auto` 可保留但不顯示。
- **商品標題**：
  - 格式改為 `{魚種}（{尾數}尾 / {處理}）`。
  - 商品卡、推薦卡、交易房、協議卡只顯示魚種，不顯示長標題。
  - 長標題只留在系統訊息與訂單摘要。
- **價格顯示**：
  - 商品卡面保留 `每台斤售價` 與 `整批售價`。
  - 交易房商品條、發送交易、加購只顯示每台斤價格。
  - 發送交易的 `售價` 是整單總價，不是每台斤。
- **訂單項目快照**：
  - 補 `fish_species` 與 `price_per_taijin`（可為 null）。
  - 協議卡用 `fish_species` 顯示魚種。
  - 商品條用 `price_per_taijin`；null 時顯示整批價。

### 14. 資料與 API

- `POST /api/products/create`：
  - 移除重量必填驗證。
  - `price` 必填；`price_per_taijin` 選填。
  - 不再自動計算整批。
  - 標題改用新格式。
- `POST /api/deals/cancel`：
  - 接受 `note`（自由文字，最多 200 字）。
  - 寫入 `cancel_reason: "OTHER"`、`cancel_note: note`。
  - 同步協議卡狀態。
  - 新增 `deal_cancelled` 卡片訊息。
- `POST /api/deals/items/batch`（新增）：
  - Body：`{ deal_id, items: [{ product_id, quantity }] }`。
  - 驗證同賣家、可售量、草稿狀態。
  - 一次加入／累加多個項目。
  - 只留一則系統訊息。
- `POST /api/deals/reinitiate`（新增）：
  - Body：`{ deal_id }`，帶最後一筆已取消訂單。
  - 建立新的 `DRAFT` 訂單，複製項目與數量（上限為目前可售）。
  - 只留一則系統訊息。
- `GET /api/deals/:id` 與房間摘要的 `peer`：
  - 補 `rating_score`、`review_count`、`username`。
  - 房間摘要已使用 `publicUser`，確認欄位存在。
- 協議卡 payload：
  - 項目補 `fish_species`、`price_per_taijin`。
- 評價標籤：
  - 前端 `REVIEW_TAGS` 與後端 `REVIEW_TAGS` 同步為四個。
  - 移除 `包裝完善`。
- 行情卡重量：
  - 純前端 state，不打 API。
  - 後端既有 `weight_kg`／`weight_taijin`／`estimated_total` 可保留，但畫面不再依賴。

7. 發送交易面板可填數量、售價、面交時間、地點並送出；協議卡出現在訊息流。
8. 協議卡收件方看到 `取消`／`確認`；發起人看不到按鈕；確認後徽章變 `已確認`。
9. 協議卡 `取消` 顯示確認取消卡；按取消回到協議卡；按送出後雙方看到「協議已被取消」卡與原因。
10. 取消後交易房可重新發起協議。
11. 加購面板列出同一位釣客所有商品；批次確認後商品條更新，只留一則系統訊息。
12. 評價小卡可用星星評分、選最多三個標籤、填評語、按確認送出。
13. 行情卡可輸入重量、切換台斤／公斤，參考價格即時更新；底部顯示資料來源；沒有行情價參考與養殖價格。
14. 聊天室訊息區為 `paper-2` 米色底；頁尾有語音、相機、輸入、送出圖示；語音不支援時有提示。
15. 上架流程不再詢問重量；整批售價必填；不再自動計算整批。
16. 交易房、發送交易、加購只顯示每台斤價格；發送交易的售價是整單總價。
17. 商品卡、交易房、協議卡只顯示魚種，不顯示含重量的長標題。
18. 所有程式碼檔案不超過 200 行；`npm test` 通過。
19. `docs/spec` 相關章節與 `06-ui.md` 已同步。
20. 商品卡面顯示 `賣家資訊` 與 `洽談購買` 兩個按鈕；`賣家資訊` 目前不執行任何動作。

## Out of Scope

- 金流、物流與實際面交流程。
- 行情預測（昨天／今天／預測）。
- 商品多圖相簿。
- 逐項數量遞減或逐項移除（取消後重新發起即可調整組合）。
- 語音輸入的後端語音辨識；只使用瀏覽器 Web Speech API。
- 會員、登入、權限流程變更。
