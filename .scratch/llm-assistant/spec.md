# 助手房 LLM（Beta）

**Status:** ready-for-agent

**Source:** 2026-11-10～14 的設計對話、Roadmap M6，以及現有助手房規則引擎、行情與商品流程。

## Problem Statement

助手房目前只會處理少數固定關鍵字：使用者說「我要賣魚」「今天有什麼魚」「花枝行情」時，規則引擎可以運作；但只要換一種說法、問一句「吳郭魚口感如何」或「今天天氣如何」，助手就只能回「你是想賣魚，還是想找魚？」。助理無法理解自然語言、無法上網查資料，也無法依使用者的需求介紹平台商品。

同時，釣客與買家已經習慣在助手房完成上架、查行情與找魚。任何 LLM 導入都不能破壞這些既有流程、不能讓模型自己編造價格或庫存，也不能把交易房的私人對話送給外部服務。

這個版本要做的是 **beta／soft launch**：用 Google AI Studio 免費層與 Tavily 免費層，讓助手房能聽懂自然語言、回答一般知識與有時效性的網路問題、推薦平台商品，並在 LLM 或搜尋服務不可用時安全地回到原本的規則引擎。

## Solution

- 助手房新增 LLM 回覆路徑：使用者訊息仍先寫入，前端再呼叫後端 AI 回覆端點；後端讀取最近對話、遮蔽個資、呼叫 Gemini 與唯讀工具，回傳結構化結果。
- LLM 負責理解自然語言、一般知識、網路問答與商品推薦；既有規則引擎仍負責上架草稿、行情卡、商品卡、訂單／協議與所有平台動作。
- 支援三個唯讀工具：官方行情、平台公開商品、Tavily 網路搜尋。
- 網路回答最多附三個「資料來源」，以新卡片顯示；平台資料與網路資料清楚區分。
- 嚴格限制平台數字：價格、庫存、行情、日期只能來自工具結果或使用者輸入；模型不得自行產生或改寫。
- 發生逾時、5xx、格式錯誤或數字防護失敗時，靜默回到規則引擎；Gemini 或 Tavily 配額用完／429 時，顯示提示與重試按鈕，平台功能照常。
- AI 只存在於助手房；交易房完全不呼叫 LLM。
- 定位為軟啟動 beta：不強制邀請名單、不設 app 使用額度、不承諾正式上線的 SLA；免費層的資料使用與 Tavily 額度限制寫在文件中。

## User Stories

1. 作為使用者，我想用自然語言說「我要賣花枝」，助手就能開始上架，以便不用記固定指令。
2. 作為釣客，我想一次說「2 尾、放血冰鎮」，助手就能填入上架草稿，以便少回答幾個問題。
3. 作為釣客，我想助手只追問還缺的非價格欄位，以便不重複提供相同資訊。
4. 作為釣客，我想在填完非價格欄位後看到行情卡，以便參考官方平均價再定價。
5. 作為釣客，我想用一句話修改草稿的魚種、尾數、處理方式、照片或售價，以便不用重新上架。
6. 作為釣客，我想在取消上架前看到確認，以便不會誤刪草稿。
7. 作為使用者，我想問「今天花枝行情如何」並看到行情卡，以便取得官方行情而不是網路謠言。
8. 作為使用者，我想問「吳郭魚口感如何」時直接得到一般知識回答，以便快速了解魚種。
9. 作為使用者，我想問「今天天氣如何」時得到附來源的即時回答，以便安排面交或出海。
10. 作為使用者，我想在網路回答下方看到最多三個資料來源，以便自行查證。
11. 作為買家，我想說「想找適合乾煎、500 元以內的白肉魚」，助手就能推薦平台商品，以便快速找到適合的魚。
12. 作為買家，我想推薦結果只包含目前買得到的商品，以便不會看到已下架或已售出的品項。
13. 作為買家，我想在助手房看到商品卡，以便直接從推薦進入交易房。
14. 作為買家，我想知道助手為什麼推薦某個商品，以便比較不同品項。
15. 作為使用者，我想清楚分辨「平台資料」與「網路資料」，以便知道哪個價格是官方行情。
16. 作為使用者，我想助手永遠不要編造價格、庫存或行情，以便我能信任回答。
17. 作為使用者，我想在一句話同時提到賣魚與其他問題時，助手先處理賣魚，以便上架流程不中斷。
18. 作為使用者，我想問「那第 2 個呢」時助手能接續上一批商品卡，以便不用重說商品名稱。
19. 作為使用者，我想助手記得這間助手房最近的對話，以便多輪問答能延續。
20. 作為使用者，我想每間助手房有各自的上下文，以便不同上架草稿不會混在一起。
21. 作為使用者，我想助手用繁體中文、簡短友善的語氣回覆，以便和平台其他文案一致。
22. 作為使用者，我想在等待助手回覆時看到「小幫手正在輸入…」，以便知道系統還在處理。
23. 作為使用者，我想在 Gemini 或 Tavily 配額用完時看到提示與重試按鈕，以便稍後再試。
24. 作為使用者，我想在網路搜尋不可用時仍能買魚、賣魚、查行情，以便平台功能不被外部服務拖累。
25. 作為使用者，我想在 LLM 逾時或暫時故障時安靜地回到原本的助手，以便對話不會中斷。
26. 作為使用者，我想交易房永遠不會出現 AI 回覆，以便私人交易對話不會被送給外部模型。
27. 作為使用者，我想電話、地址、Email 與身分證字號在送給模型或搜尋服務前被遮蔽，以便保護個資。
28. 作為使用者，我想助手不要在回覆中重複我的個人資料，以便避免在對話中外洩。
29. 作為使用者，我想助手不要自行發布商品、修改草稿、建立訂單或送出協議，以便平台動作仍由我控制。
30. 作為使用者，我想助手把網路內容視為不可信資料，以便惡意網頁不能改變平台規則。
31. 作為使用者，我想網路回答標明資料來源，以便我知道哪些內容不是平台官方資料。
32. 作為使用者，我想助手回答魚種口感、烹調與營養等穩定知識時不要每次都上網，以便回覆更快。
33. 作為使用者，我想助手在問題有時效性時才上網，以便「今天」「最新」這類問題得到即時資訊。
34. 作為使用者，我想平台查無行情時助手說「暫無行情」而不是猜一個數字，以便不會誤導。
35. 作為使用者，我想助手只顯示公開且可購買的商品卡，以便不會看到已下架、已刪除或已售出的商品。
36. 作為使用者，我想助手依我的縣市推薦商品，以便找到距離較近的釣客。
37. 作為使用者，我想問「附近有什麼魚」時看到商品卡，以便直接瀏覽。
38. 作為使用者，我想在 LLM 關閉時仍能用原本的助手完成上架、找魚與查行情，以便功能不依賴外部服務。
39. 作為使用者，我想助手在平台意圖下不要重複產生 LLM 文字與規則回覆，以便對話不會出現兩套答案。
40. 作為使用者，我想只有網路回答才顯示資料來源，以便平台答案保持乾淨。
41. 作為使用者，我想在不同助手房之間切換時仍保有自己的對話與草稿，以便多個上架流程並行。
42. 作為使用者，我想在手機上使用助手房與資料來源卡，以便隨時買賣。
43. 作為維護者，我想用環境變數開啟或關閉 LLM，以便出問題時快速退回規則引擎。
44. 作為維護者，我想單獨開關網路搜尋，以便控制 Tavily 額度與外部依賴。
45. 作為維護者，我想用環境變數更換模型，以便升級模型而不改程式。
46. 作為維護者，我想在測試中注入假的 LLM 與 Tavily，以便測試不打真實網路。
47. 作為維護者，我想 AI 失敗有明確分類（逾時、429、格式錯誤、數字防護），以便除錯。
48. 作為維護者，我想 log 只記錄 token 數、耗時、工具名稱與錯誤碼，不記錄訊息內容，以便保護隱私。
49. 作為維護者，我想 beta 採軟啟動、不強制邀請名單，以便快速開始測試。
50. 作為維護者，我想免費層與 Tavily 的限制寫在文件，以便測試者知道 beta 的界線。
51. 作為維護者，我想 spec、API 文件、GLOSSARY 與 ADR 同步更新，以便行為與文件一致。
52. 作為維護者，我想缺少 API key 時助手自動退回規則引擎，以便本機開發不需要金鑰。
53. 作為維護者，我想 LLM 只能使用唯讀工具，以便不可能透過模型修改資料。
54. 作為維護者，我想 system prompt 固定，以便品牌語氣與防護規則一致。
55. 作為維護者，我想 beta 在文件與版本說明中標示清楚，以便使用者不期待正式 SLA。
56. 作為使用者，我想助手不提供法律、醫療或投資的專業建議，以便不會被誤導。
57. 作為使用者，我想助手顯示行情時標明官方來源，以便我知道數字的依據。
58. 作為使用者，我想助手回覆簡短、友善、容易閱讀，以便在手機上快速看完。
59. 作為使用者，我想助手在問題模糊時先問清楚，以便不要亂猜。
60. 作為使用者，我想助手在執行任何破壞性動作前先確認，以便不會失去草稿。

## Implementation Decisions

### 1. 定位與範圍

- 這個版本是 **beta／soft launch**，不是正式上線；不承諾 SLA、稽核、資料落地或正式隱私政策。
- 軟啟動、不強制邀請名單：任何註冊使用者都能使用 LLM；接受 Tavily 每月額度可能提早用完的風險。
- AI 只存在於助手房；交易房完全不呼叫 LLM。既有「`sender_type:"ai"` 只允許助手房」的檢查維持不變。
- 使用者看到的身分仍是「小幫手」；不新增模型選擇器或 persona 設定。

### 2. 平台、模型與設定

- LLM 使用 Google AI Studio 免費層（Gemini Developer API），預設模型為 `gemini-3.5-flash-lite`，可用 `LLM_MODEL` 更換。
- 網路搜尋使用 Tavily 免費層（每月 1,000 credits，basic search 每次 1 credit）；不使用 Google Search grounding，也不使用 Vertex AI。
- 不需要 `gcloud`、ADC 或 Google Cloud 專案；需要 `GEMINI_API_KEY` 與 `TAVILY_API_KEY`。
- 主要開關：
  - `LLM_ENABLED`：預設關閉；關閉時助手完全走規則引擎。
  - `LLM_WEB_SEARCH`：預設關閉；關閉時不呼叫 Tavily，只能回答一般知識與平台資料。
  - `LLM_MODEL`、`LLM_TIMEOUT_MS`（一般 8,000）、`LLM_SEARCH_TIMEOUT_MS`（有搜尋 15,000）、`LLM_HISTORY_LIMIT`（10）、`LLM_MAX_TOOL_CALLS`（2）。
- 缺少金鑰、金鑰無效或 `LLM_ENABLED` 關閉時，AI 回覆端點回傳未處理，前端直接走規則引擎；不顯示錯誤。
- 免費層內容可能被 Google 用於改善產品；這件事只寫在 README 與 beta 說明，不在 UI 顯示。

### 3. 後端 AI 回覆端點

新增 `POST /api/ai/reply`，由登入使用者呼叫，只接受助手房。端點不持有對話狀態；`context` 由前端提供，後端只驗證與摘要，不寫回資料庫。

請求欄位：

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `conversation_id` | string | 必填；必須是助手房，且目前使用者是參與者 |
| `message_id` | string | 必填；前端已寫入的使用者訊息；後端驗證它屬於這間房與目前使用者 |
| `context` | object | 必填；前端目前持有的助手房 context；必須是純物件，大小有上限 |

回應欄位：

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `handled` | boolean | `true` 表示 LLM 產生可用結果；`false` 表示前端應走規則 fallback |
| `intent` | string | `SELL`、`BUY`、`MARKET`、`CANCEL`、`EDIT`、`CHAT`、`WEB`、`PRODUCT_RECOMMEND`、`UNKNOWN` |
| `slots` | object | LLM 有把握的欄位：魚種、官方代碼、尾數、處理方式、整批售價、每台斤售價、地區、修改欄位與新值 |
| `reply_text` | string 或 null | `CHAT`、`WEB`、`PRODUCT_RECOMMEND` 的自然語言回覆；平台意圖為 null；長度需符合現有訊息上限 |
| `sources` | array | 最多 3 個 `{ title, url }`；只有網路回答才有 |
| `tool_results` | object | 可含 `market`（既有行情卡資料）與 `products`（公開商品陣列，最多 5 筆） |
| `error_code` | string 或 null | `LLM_DISABLED`、`LLM_NOT_CONFIGURED`、`LLM_TIMEOUT`、`LLM_UPSTREAM_ERROR`、`LLM_INVALID_OUTPUT`、`LLM_GUARD_REJECTED`、`LLM_RATE_LIMITED`、`SEARCH_RATE_LIMITED`、`SEARCH_QUOTA_EXHAUSTED` |
| `retryable` | boolean | 只有配額／429 類錯誤為 true；前端顯示提示與重試 |

- 權限與房間錯誤沿用既有 API 風格：未登入、非參與者、非助手房、找不到訊息都回 4xx。
- AI 失敗一律回 200 與 `handled:false`，讓前端能無縫 fallback；不要用 5xx 讓前端誤以為整個請求失敗。
- 端點不寫入任何訊息；AI 訊息仍由前端用既有訊息端點寫入。這保留現有協議，也讓 fallback 走同一條路。
- 端點不修改 `context`；前端依 intent 與工具結果自行更新。

### 4. 對話歷史與 context 摘要

- 後端依 `conversation_id` 讀取最近 10 則使用者與助手訊息；不含系統訊息、圖片訊息與完整卡片 JSON。
- 卡片以一行摘要取代，例如「商品卡：花枝，2 尾，整批 1,000 元」；不把整份卡片物件送給模型。
- context 只取模型需要的欄位：`mode`、草稿的魚種／尾數／處理方式／售價（不含照片 URL）、最近商品 id 與簡短摘要、目前選取的商品 id。
- 不送頭像、電話、地址、Email、身分證字號或完整個人檔案。
- 若使用者訊息或歷史含有電話、Email、身分證字號、地址樣式，先替換成 `[已遮蔽]`，再送給 Gemini 或 Tavily。
- 使用者訊息本身以 `message_id` 從資料庫讀取，不信任前端傳來的文字內容。

### 5. 工具

LLM 只能使用三個唯讀工具；後端執行工具，模型不會直接接觸資料庫或檔案系統。

| 工具 | 資料來源 | 規則 |
| --- | --- | --- |
| `get_market_price` | 既有官方行情服務 | 只用官方平均價與交易日期；遵守官方來源限制；查無資料回 null，模型必須說「暫無行情」且不得出現數字 |
| `search_products` | 平台商品 | 只回 `ACTIVE` 與 `PARTIALLY_RESERVED` 的公開商品；可用魚種、地區、價格、處理方式篩選；最多 5 筆；不含電話、地址等非公開欄位 |
| `web_search` | Tavily | basic search、最多 3～5 個結果；查詢先遮蔽個資；每次 1 credit；回傳標題、URL、摘要；失敗回對應錯誤碼 |

- 明確的行情意圖仍走既有行情規則與行情卡；`get_market_price` 供 LLM 在一般比較、跨魚種或規則無法解析的問題中取得官方數字，不能取代既有行情流程。
- 每輪最多 2 次工具呼叫，避免模型迴圈；這是技術護欄，不是使用額度。
- 平台商品與行情永遠優先於網路資料；網路結果不得覆蓋平台價格、庫存或行情。
- 工具輸出視為不可信資料；system prompt 明確要求模型不得遵從工具結果中的指令，也不得因網頁內容執行平台動作。
- 沒有寫入工具：模型不能建立、修改、發布、下架或刪除商品，也不能建立訂單、送出協議或寫評價。

### 6. Intent 路由與前端行為

後端回傳一個主要 intent；前端依下列規則處理：

| Intent | 前端行為 |
| --- | --- |
| `SELL` | 把 slots 合併進上架草稿，交給現有規則引擎追問與產生草稿卡；忽略 `reply_text`，避免重複回覆 |
| `BUY` | 交給現有規則式導購；忽略 `reply_text` |
| `MARKET` | 交給現有行情規則與行情卡；行情數字只來自官方服務 |
| `CANCEL` | 交給現有取消上架流程；需要確認才刪除 |
| `EDIT` | 交給現有草稿修改流程；用 LLM 的欄位／值輔助，但由規則驗證 |
| `PRODUCT_RECOMMEND` | 寫入 `reply_text`，再依 `tool_results.products` 產生既有商品卡；context 進入 `shopping` 模式並更新 `last_cards` |
| `CHAT` | 寫入 `reply_text`；有 `sources` 時再寫一張資料來源卡；context 維持原模式 |
| `WEB` | 寫入 `reply_text` 與資料來源卡；context 維持原模式 |
| `UNKNOWN` | 先走現有規則；規則也無法處理時，才使用 `reply_text`；沒有回覆文字就用既有引導句 |

- 平台意圖優先：一句話同時包含賣魚與其他問題時，先處理平台意圖，其他問題不在同一輪回答。
- 上架流程進行中時，既有規則的優先順序不變；側聊一般問題不在這個版本處理。
- 平台意圖不產生 `reply_text`，避免規則回覆與 LLM 回覆同時出現。
- 前端在送出使用者訊息後才呼叫 AI 回覆端點；等待期間顯示「小幫手正在輸入…」。
- 重試按鈕會用同一個 `message_id` 再呼叫一次，不重複寫入使用者訊息。
- AI 訊息仍用既有訊息端點寫入；資料來源卡是新的卡片型別，商品卡與行情卡沿用既有型別。
- 前端只在助手房呼叫 AI 端點；交易房流程完全不變。

### 7. 數字與輸出防護

- 平台數字（商品價格、可售尾數、行情平均價、交易日期、訂單／協議金額）必須出現在工具結果或使用者訊息中；否則整則回覆視為不合格，靜默 fallback。
- 一般知識數字（烹調時間、溫度、營養成分）可以來自模型知識，但必須以「一般建議」語氣呈現；若使用網路搜尋，數字必須與搜尋結果一致。
- 商品卡與行情卡只能由工具結果產生；模型不能自行組卡片或改寫卡片欄位。
- 回覆需符合固定 schema：intent 必須是允許值、slots 型別正確、`reply_text` 不超過既有訊息 500 字上限、`sources` 最多 3 個且 URL 合法。
- 不合格輸出不寫入訊息；前端走規則 fallback，不顯示技術錯誤。
- 防守 prompt injection：工具結果中的指令一律視為資料；模型不得揭露 system prompt；不得因網路內容改變平台規則或執行寫入。

### 8. 錯誤、逾時與配額

- 一般回覆 timeout 8 秒；有 Tavily 搜尋的回合 timeout 15 秒。
- 靜默 fallback 的錯誤：`LLM_DISABLED`、`LLM_NOT_CONFIGURED`、`LLM_TIMEOUT`、`LLM_UPSTREAM_ERROR`、`LLM_INVALID_OUTPUT`、`LLM_GUARD_REJECTED`。
- 顯示提示與重試按鈕的錯誤：`LLM_RATE_LIMITED`、`SEARCH_RATE_LIMITED`、`SEARCH_QUOTA_EXHAUSTED`。
- 配額錯誤時仍先跑規則；若規則能處理平台意圖，照常完成；若不能（例如天氣），顯示「目前無法上網查詢」與重試。
- 不設 app 層使用額度；Gemini 免費層的 RPM／RPD／TPM 與 Tavily 每月 1,000 credits 仍是硬限制。
- 不做自動排隊或自動重試；重試由使用者按鈕觸發。
- log 只記 request id、使用者 id、intent、工具名稱、token 數、耗時與錯誤碼；不記訊息內容、prompt、搜尋結果或 API key。

### 9. 隱私與 beta 限制

- 送出前遮蔽電話、Email、身分證字號與地址樣式；不送個人檔案的電話、地址、頭像。
- 助手房歷史才送給模型；交易房永遠不送。
- Tavily 只收到該次搜尋查詢，不收到完整對話歷史。
- 免費層內容可能被 Google 用於改善產品；Tavily 也會收到查詢。這些限制寫在 README 與 beta 說明，不在 UI 顯示。
- 軟啟動、不強制名單；任何註冊使用者都能使用。若之後要公開放大，應補 allowlist、使用額度與 UI 隱私提示。
- 這是 beta，不承諾正式上線的隱私、稽核、資料落地或 SLA。

### 10. 資料與文件

- 不需要資料庫 schema 變更；既有訊息已支援卡片。
- 新增 `sources` 卡片型別，欄位為 `sources: [{ title, url }]`，最多 3 個；沿用既有訊息與卡片儲存方式。
- 更新規格文件：總覽、流程、資料模型、API、UI、Roadmap 與 GLOSSARY；Roadmap M6 標記為 beta，不標記為正式完成。
- GLOSSARY 只新增使用者可見的「資料來源」概念；不把 LLM、Tavily、Gemini 等實作名詞放進 glossary。
- 新增 ADR-0011，記錄混合式 LLM 助手、唯讀工具、免費層 beta 與 Tavily 的取捨，以及未來升級到付費 AI Studio／Vertex AI＋Google Search grounding 的遷移路徑。
- 後端與前端模組依職責拆分，單一程式碼檔案不得超過 200 行。

### 11. 驗收情境

- `LLM_ENABLED=false` 時，助手房仍可用規則完成上架、找魚與行情；沒有任何外部請求。
- 使用者說「我要賣花枝 2 尾 放血冰鎮」時，助手合併 slots 並追問缺少的欄位，不重複詢問已提供的內容。
- 使用者問「今天天氣如何」時，助手回覆附來源的天氣摘要，最多 3 個資料來源。
- 使用者問「吳郭魚口感如何」時，助手直接回答一般知識，不消耗 Tavily credits。
- 使用者問「有什麼適合乾煎、500 元以內的白肉魚」時，助手顯示符合條件的公開商品卡與推薦理由。
- 模型試圖產生不存在的價格或庫存時，回覆被丟棄，前端走規則 fallback。
- Gemini timeout 時，使用者不會看到錯誤；規則回覆照常出現。
- Gemini 429 或 Tavily 額度用完時，使用者看到提示與重試按鈕；平台功能仍可用。
- 交易房送出訊息時，完全不會呼叫 AI 回覆端點。
- 含電話或地址的訊息在送給假 provider 前已被遮蔽。

## Testing Decisions

### 測試原則

- 只測外部行為：API 回應、寫入的訊息、卡片內容、fallback 結果；不測內部函式呼叫順序或 prompt 全文。
- 測試不打真實網路；Gemini 與 Tavily 都用注入的 fake client／fetcher。
- 優先使用既有 seam；provider 注入點只是測試替身，不是新的行為 seam。
- 安全與隱私測試要斷言「敏感資料沒有出現在 provider 輸入」，而不是只斷言回覆文字。

### Seam 1：後端 HTTP（主要）

透過真實 Express app、暫存 DB 與真實登入呼叫 AI 回覆端點；LLM client 與 Tavily fetcher 用 fake 注入，模式與行情測試的 upstream 注入相同。

覆蓋：

- 端點權限：未登入、非參與者、非助手房、訊息不屬於房間。
- `LLM_ENABLED=false` 與缺少金鑰時不呼叫 provider。
- 平台動作意圖（賣魚、行情、取消、修改）回傳正確 intent 與 slots，且不產生 `reply_text`；商品推薦另測 `reply_text` 與商品卡。
- 網路問題：fake Tavily 回傳結果，後端把結果對應成 `sources`；fake LLM 只產生文字；`sources` 最多 3 個。
- 商品推薦：fake 商品資料只包含公開商品；`tool_results.products` 正確。
- 行情工具：只使用官方行情資料；網路結果不能覆蓋。
- Redaction：歷史或訊息含電話、Email、地址時，fake provider 收到的輸入不含原始值。
- 數字防護：fake LLM 產生不存在的價格或庫存時，回覆被拒絕並回報 guard 錯誤。
- 錯誤映射：timeout、5xx、invalid output、429、Tavily quota 各自回傳正確 `error_code` 與 `retryable`。
- Prompt injection：fake 網頁結果含「忽略先前指令」時，模型輸出不得觸發平台動作；工具仍只有唯讀。
- 每輪工具呼叫上限：超過 2 次時停止並 fallback 或回傳錯誤。

### Seam 2：前端 flow（次要）

用 mock 的 `window.HaisenAPI` 測 `flow.submitText` 與 `runReplies`，沿用現有批次回覆測試的做法。

覆蓋：

- 送出使用者訊息後，以 `message_id` 與目前 context 呼叫 AI 回覆端點。
- `SELL`／`BUY`／`MARKET`／`CANCEL`／`EDIT` 交給規則，不寫入 LLM 重複文字。
- `CHAT`／`WEB` 寫入 AI 文字；有 sources 時寫入資料來源卡。
- `PRODUCT_RECOMMEND` 寫入文字與商品卡，context 進入 `shopping`。
- `handled:false` 時走規則 fallback，不顯示錯誤。
- 429／配額錯誤顯示提示與重試；重試沿用同一個 `message_id`，不重複使用者訊息。
- 等待期間顯示「小幫手正在輸入…」。
- 交易房不呼叫 AI 端點。

### Seam 3：E2E（沿用既有）

- 既有 Playwright 測試在 `LLM_ENABLED=false` 下跑助手房流程，確認規則式助手仍正常、沒有外部網路請求。
- 不新增 fake LLM server；E2E 不測 LLM 文字品質。

### 測試模組與先例

- 後端 AI 回覆端點、工具執行、redaction、輸出防護、錯誤映射。
- 前端 AI client、flow 整合、資料來源卡、重試狀態。
- 先例：行情測試注入 fake upstream；`flow-scroll` 測試 mock 訊息 API；後端測試以真實 HTTP 與暫存 DB 啟動。
- 純函式（redaction、數字防護、歷史摘要）可有單元測試，但主要行為仍以兩個 seam 的整合測試為準。

## Out of Scope

- 交易房的 AI 回覆或 AI 助理。
- LLM 直接發布、修改、下架、刪除商品，或建立訂單、送出協議、寫評價。
- Google Search grounding、Vertex AI、付費 AI Studio 層。
- 邀請制名單、邀請碼、app 層使用額度或 billing dashboard。
- UI 的免費層隱私提示（只寫文件）。
- 串流回覆；只做等待指示。
- 圖片、語音或多模態理解；照片仍走既有上架流程。
- 一次處理多個平台意圖；平台動作優先，其餘下一輪再說。
- 上架流程進行中的側聊一般問題。
- 模型選擇器、persona 設定、admin 用量後台、analytics。
- 自動重試、排隊、快取網路搜尋結果。
- 推薦平台以外的商品，或把外部價格當成平台價格。
- 正式上線的 SLA、稽核、資料落地、法遵審查。
- 多語言回覆；beta 只回繁體中文。

## Further Notes

- **Beta 定位**：這是 soft launch，不是正式上線。免費層內容可能被 Google 用於改善產品；Tavily 每月 1,000 credits；不強制名單；任何註冊使用者都能使用。若之後要公開放大，應先補 allowlist、使用額度與 UI 隱私提示。
- **遷移路徑**：若 beta 驗證成功，優先升級到 AI Studio 付費層＋Google Search grounding，或 Vertex AI＋Google Search grounding；web search adapter 與 LLM provider 應保持可替換，讓遷移只改設定與認證。
- **前置條件**：申請 AI Studio API key 與 Tavily API key，放進後端環境變數；不需要 `gcloud` 或 Google Cloud 專案。
- **安全**：所有工具唯讀；網路內容不可信；平台數字嚴格防護；不記錄訊息內容；API key 只在後端。
- **文件同步**：Roadmap M6 標記 beta；新增 ADR-0011；更新 API、流程、UI、資料模型、GLOSSARY 與各 README。
- **命名**：使用者可見名稱維持「小幫手」「助手房」「交易房」「商品」「行情」「資料來源」；避免在 UI 使用「LLM」「Tavily」「Gemini」等實作名詞。
