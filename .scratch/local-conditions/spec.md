# 助手在地區性天氣與海況

**Source:** 2026-11-17 對話中的 grilling 與設計收斂；tickets 01–09。
**Status:** resolved

## 背景

助手房目前沒有使用設定頁的縣市；天氣問題走 Tavily，查詢字串由模型自行產生，不保證帶入使用者所在地。既有設定頁縣市只用於行情與商品工具。使用者要求助手能依設定縣市回答在地問題，例如「今天天氣如何？」，且預設不附連結，只有明確要求時才顯示來源。

## 目標

- 地區相關問題預設使用設定縣市；訊息中明確指定的地點優先。
- 天氣與海況分開：問天氣只回天氣；問海況回海況＋風浪＋天氣＋潮汐；問「適合釣魚嗎」回完整數據與一般建議。
- 預設不顯示來源卡、回覆文字不出現 URL；使用者明確要求時才重新查詢並顯示最多 3 個來源。
- 維持平台動作由規則引擎處理、數字防護、交易房不呼叫 LLM 的既有規則。

## 使用者故事

1. 作為使用者，我想問「今天天氣如何？」時得到設定縣市的天氣，以便安排當天活動。
2. 作為使用者，我想問天氣時只看到天氣，不要混入海況或潮汐。
3. 作為使用者，我想問海況時同時看到浪況、風浪、天氣與潮汐，以便判斷要不要去海邊。
4. 作為使用者，我想問「適合釣魚嗎？」時得到依數據給的一般建議，而不是只有數字。
5. 作為使用者，我想預設不要看到一堆連結，需要時再要求來源。
6. 作為使用者，我想在下一句問「有連結嗎？」時拿到剛剛那份資料的來源。
7. 作為使用者，我沒設定縣市時，希望助手先問我，而不是猜錯地區。
8. 作為使用者，我想問國外地點天氣時，助手仍能用網路搜尋回答。
9. 作為維護者，我想文件、ADR 與詞彙表清楚記錄地區、天氣、海況與來源的規則。

## 行為矩陣

| 問題 | 回覆 |
| --- | --- |
| 今天天氣如何？ | 只回天氣：現象、現在氣溫、今日高低溫、降雨機率、風速風向 |
| 今天海況如何？ | 海況＋風浪＋天氣＋潮汐 |
| 今天適合釣魚嗎？ | 天氣＋海況＋潮汐＋依數據給一般建議 |
| 潮汐幾點？ | 海況包（含天氣與潮汐） |
| 東京天氣如何？ | Tavily 網路搜尋；不支援當地海況與潮汐 |
| 平台操作（賣魚、行情、找魚） | 維持原本規則引擎，不混入氣象回答 |

## 地區規則

- 預設值為設定頁的縣市（`city`）。
- 訊息中明確指定縣市時，以訊息為優先。
- 只使用縣市，不使用區或地址；不把區、地址、電話、Email 或身分證字號送給模型。
- 只有地區相關問題（天氣、海況、潮汐、在地新聞、交通、活動、附近、這裡、縣市名稱）才把縣市放進 prompt；一般知識與平台操作不送。
- 沒有有效縣市時先問「你所在的縣市是哪裡？」。
- 使用者回答的縣市只在目前對話暫存，不寫回個人設定；暫存按對話隔離、有期限、刪除對話時清除。
- 使用者在訊息中指定另一個縣市時，不改變暫存的所在地。

## 資料來源

| 資料 | 來源 |
| --- | --- |
| 天氣 | Open-Meteo Weather API |
| 浪高、浪向、浪週期、海溫 | Open-Meteo Marine API |
| 風速、陣風、風向 | Open-Meteo Weather API（海域代表座標） |
| 潮汐 | 中央氣象署潮汐開放資料（`CWA_API_KEY`） |
| 其他在地時效問題（新聞、交通、活動、颱風消息） | Tavily `web_search` |
| 國外地點天氣 | Tavily `web_search` |

- 缺少 `CWA_API_KEY` 時，海況仍可回答，但潮汐顯示「潮汐暫無資料」。
- 目前日期（Asia/Taipei）放進 system prompt，讓「今天」有依據。
- 上游逾時、無資料或格式錯誤時，明確說明缺少什麼，不產生未經工具支持的數字。

## 海況包與海域

- 海況問題包含浪高、浪向、浪週期、海溫、風速、陣風、天氣與潮汐。
- 天氣問題不包含海況、風浪或潮汐。
- 海況問題優先使用訊息中明確的海域；否則使用縣市主要海域。
- 內陸縣市或無法對應海域時，先反問「你想問哪個海域？」。
- 使用預設海域時，回覆寫出海域名稱。

## 來源與連結

- 預設不顯示來源卡，回覆文字中也不出現 URL。
- 只有使用者明確要求「連結、網址、來源、出處、哪裡看、哪個網站、資料哪來、引用、查證」時，才回傳並顯示來源。
- 同一則訊息要求就在同一則給；下一句才問就重新執行對應工具，不做來源暫存。
- 來源卡最多 3 個合法 http／https URL，只由後端工具結果產生；模型自行產生的來源一律丟棄。
- 平台行情卡原本的「資料來源：農業部 漁業署」維持文字，不算連結。

## 建議語氣

- 使用者問「適合嗎／要注意什麼」時，AI 可以依數據給一般建議（偏適合／需注意／偏不適合）。
- 不使用「保證安全」「一定可以」「絕對沒問題」等絕對說法。
- 不附加固定的免責句。
- 資料不足或上游失敗時，只說明缺少什麼，不做適合／不適合的判斷。
- 單純問天氣或海況時，不自動變成「適合嗎」的建議。

## 技術影響

- 新增一個唯讀工具 `get_local_conditions`，以 `mode: weather | sea` 一次取得天氣、海況與潮汐，避免超過每輪最多 2 次工具呼叫。
- 工具結果納入既有的數字依據；天氣、海況、潮汐數字不得被現有防護誤擋。
- 來源由後端工具結果產生。`CHAT` 預設不帶來源，但使用者要求且該輪有工具來源時可帶；模型自填來源丟棄。
- AI 文字氣泡保留換行；不新增卡片型別。
- 沒有縣市時的暫存放在後端記憶體，不寫資料庫；來源不做暫存。
- 新增 `CWA_API_KEY` 環境變數；缺少時潮汐降級，不影響天氣與海況。
- 新增與修改的程式碼檔案不超過 200 行；測試 mock 外部 API，不呼叫真實網路。

## 不做

- 國外海況與潮汐。
- 使用者自選氣象 provider。
- 氣象或海況快取。
- 來源暫存。
- 把商品、訂單、協議等寫入動作交給模型。
- 區或地址層級的地區問答。

## 驗收範例

**天氣**

> 高雄市的天氣：多雲短暫陣雨，現在 27°C，今天 26–31°C，降雨機率 40%，東南風 3 級。

**海況**

> 高雄市外海（台灣海峽南部）海況：浪高約 1.5 公尺，西南浪，浪週期 6 秒，海溫 27°C；東南風 4 級、陣風 6 級。天氣多雲短暫陣雨，26–31°C，降雨機率 40%。潮汐：滿潮 09:12、21:30；乾潮 03:05、15:20。

**建議**

> 以目前浪高與陣風來看，近岸釣魚需注意風浪與午後陣雨。
