# 商品卡地區顯示：去重、文件對齊與快取收尾

**Status:** ready-for-agent

**Source:** 2026-11-10 對未提交工作區（HEAD `5c244bf`）的 Standards／Spec 雙軸 review；工作目錄已有一版地區去重邏輯、測試與三份文件更新。這份 spec 以該變更為基礎，補齊文件精確度、測試強度與快取版本。

## Problem Statement

買家在首頁、今日漁獲、商品列表與個人資訊頁看商品卡時，地區欄位會出現重複縣市。`location` 由個人檔案的縣市、區與地址組成，通常已含縣市；畫面又先顯示 `region` 再串 `location`，於是變成「高雄市　高雄市鼓山區」。買家要多花力氣辨識地點，釣客的商品也顯得凌亂。

這次修正還有幾個收尾問題：

- 文件寫「`location` 已含縣市時只顯示一次」，程式只比對開頭；文件比實作寬。
- 測試只確認「有出現」，沒有確認「只出現一次」；`location` 等於 `region` 時，即使重複也會通過。
- 商品卡顯示模組改了，但載入它的頁面仍用舊的 `?v=`；部署後回訪買家可能拿到舊檔。
- 交易房 spec 同節仍寫「賣家資訊」，與 UI 規格、程式及 `GLOSSARY.md` 的「釣客」用語不一致。

這些不是新功能，而是一個顯示規則的收尾：讓畫面只顯示一次縣市，文件與程式說同一件事，測試能抓到回歸，回訪買家拿得到新檔。

## Solution

- 商品卡的地區欄位只顯示一次縣市：`location` 以縣市開頭時直接顯示 `location`；否則用 `region`＋全形空格＋`location` 補上。
- `region` 或 `location` 任一缺漏時，維持顯示「地區未提供」。
- 比對前把兩邊的「臺」正規化為「台」，並去掉前後空白。
- 同步交易房 spec、UI 規格與路線圖 AC-21，把「已含縣市」改成「以縣市開頭」。
- 把商品卡 HTML 測試改成抓地區那一行的完整文字，驗證次數與邊界。
- 更新所有載入商品卡顯示模組的頁面的快取版本，並把該模組納入既有快取版本 e2e 檢查。
- 順手把交易房 spec 同節的「賣家資訊」改成「釣客資訊」。

## User Stories

1. 作為買家，我想在商品卡只看到一次縣市，以便快速讀出地點。
2. 作為買家，我想在 `location` 已含縣市時看到完整地址，以便知道區與街路。
3. 作為買家，我想在 `location` 缺縣市時看到補上的縣市，以便仍能判斷地區。
4. 作為買家，我想在 `region` 或 `location` 缺漏時看到「地區未提供」，以便知道資料不完整。
5. 作為買家，我想讓「臺」正規化成「台」，以便不同資料來源顯示一致。
6. 作為買家，我想讓地區文字去掉前後空白，以便畫面整齊。
7. 作為買家，我想在首頁、今日漁獲、商品列表與個人資訊頁看到同一條地區規則，以便換頁不會看到不同格式。
8. 作為釣客，我想讓我的商品卡只顯示一次縣市，以便上架資訊看起來乾淨。
9. 作為維護者，我想在交易房 spec 看到「以縣市開頭」而不是「已含縣市」，以便文件與程式說同一件事。
10. 作為維護者，我想在 UI 規格與路線圖 AC-21 看到同一條規則，以便實作與驗收有共同依據。
11. 作為維護者，我想讓商品卡測試精確比對地區行，以便重複縣市回歸時測試會失敗。
12. 作為維護者，我想讓測試覆蓋 `location` 等於 `region` 的情況，以便不會只驗「有出現」而漏掉重複。
13. 作為維護者，我想讓測試覆蓋缺漏、臺／台與空白邊界，以便第一線資料不規則時仍可預期。
14. 作為回訪買家，我想在部署後拿到新的商品卡模組，以便看到修正後的地區顯示。
15. 作為維護者，我想讓所有載入商品卡模組的頁面使用同一個新版本，以便不會有些頁面新、有些頁面舊。
16. 作為維護者，我想讓既有快取版本 e2e 檢查鎖定這個模組，以便未來改動不會忘記提版。
17. 作為維護者，我想讓交易房 spec 使用「釣客資訊」而不是「賣家資訊」，以便用語符合 glossary。
18. 作為開發者，我想讓這次只改前端顯示與文件，以便不需要動 API 或資料庫。
19. 作為開發者，我想讓非縣市開頭的 `location` 維持「region + location」的明確規則，以便不要用模糊比對猜地址。
20. 作為審查者，我想看到測試、文件與快取版本一起完成，以便這個小修正可以安全提交。

## Implementation Decisions

### 顯示規則

- 商品卡的地區行是唯一顯示 `region` 與 `location` 的地方；規則集中在既有的商品卡顯示模組，不新增抽象或第二個 helper。
- 先對 `region` 與 `location` 做「臺」→「台」正規化，再去頭尾空白。
- 任一為空時顯示「地區未提供」。
- `location` 以正規化後的 `region` 開頭時，只顯示 `location`。
- 否則顯示 `region`＋全形空格（U+3000）＋`location`。
- 前綴比對是刻意選擇：後端建立 `location` 時以個人檔案的縣市、區、地址依序串接，正常資料一定以縣市開頭；不做「縣市出現在字串任何位置」的模糊去重，避免誤刪不同行政區或路名。
- 不改 `region`／`location` 的資料格式、API 契約或資料庫欄位；這是純前端顯示修正。
- 不改其他卡片欄位、排版、照片比例、按鈕或交易流程。

### 文件

- 交易房 spec 的商品卡地區條目改寫為「`location` 以縣市開頭時只顯示一次；否則補上 `region`；缺漏顯示『地區未提供』」。
- UI 規格同一條目同步。
- 路線圖 AC-21 保留「不重複縣市」，不新增技術細節。
- 交易房 spec 同節的「賣家資訊」改為「釣客資訊」，與 `GLOSSARY.md` 的 `Avoid: 賣家` 及現行 UI 規格一致；不改其他歷史 ticket 的內文。

### 快取

- 商品卡顯示模組修改後，所有載入它的頁面把 `?v=` 從 `v13` 升到 `v14`；同一模組跨頁版本必須一致。
- 既有快取版本 e2e 檢查把這個模組加入鎖定清單，最低版本 `v14`；若檢查頁面沒有涵蓋所有載入頁，至少讓四個載入頁的版本一致，並在 ticket 說明中記錄未納入自動檢查的頁面。
- 不提升其他未修改模組的版本。

### 測試

- 主要 seam 是既有商品卡 HTML 渲染測試：用 `productCardHTML` 的輸出驗證使用者看到的文字，不直接測 `placeOf`。
- 測試抓 `.catch-card__place` 的文字做精確比對；若測試環境沒有 DOM parser，至少用卡片 HTML 中該段落的完整字串比對，不用整張卡片的全域計數。
- 快取版本用既有 e2e 快取檢查；不新增第二個測試框架。

## Testing Decisions

- 好測試只驗外部行為：給定商品資料，渲染出的地區行文字是什麼；不驗內部變數、不比對實作分支。
- 主要測試模組：商品卡 HTML 渲染測試。
- 快取測試模組：既有快取版本 e2e 檢查。
- 必測案例：
  1. `region=高雄市`、`location=高雄市鼓山區` → 地區行只有一個「高雄市」，文字為「高雄市鼓山區」。
  2. `region=高雄市`、`location=鼓山區` → 「高雄市　鼓山區」。
  3. `region=高雄市`、`location=高雄市` → 只有一個「高雄市」。
  4. `location` 空 → 「地區未提供」。
  5. `region` 空 → 「地區未提供」（維持既有契約）。
  6. `region=臺北市`、`location=台北市信義區` → 只顯示一次台北市。
  7. `location` 前後有空白 → 去重後只顯示一次。
  8. `location` 不以縣市開頭（例如「鼓山區・高雄市」）→ 依契約補上 `region`，不做事後模糊去重；此案例可選，但要與文件一致。
- 快取測試：載入頁面的商品卡模組版本都是 `v14`，且同檔跨頁一致。
- 既有 prior art：商品卡測試已用 `productCardHTML` 渲染 HTML；快取版本已有 Playwright 檢查本地 CSS／JS entry 的版本與跨頁一致性。
- 不在測試中斷言完整的卡片 HTML；只斷言地區行與必要的回歸欄位，避免每次改文案都要重寫測試。

## Out of Scope

- 不改後端 `region`／`location` 的產生方式、驗證或資料庫格式。
- 不做「縣市出現在字串任何位置」的模糊去重，也不處理非戶籍地址的自由文字。
- 不改商品卡其他欄位、視覺設計、照片比例、按鈕或交易流程。
- 不新增商品詳情頁，不改 API。
- 不重寫歷史 ticket 的完成紀錄；只修現行交易房 spec 的用語。
- 不處理其他頁面或模組的快取版本，除非該頁載入商品卡顯示模組。
- 不新增 `placeOf` 的單元測試 seam。

## Further Notes

- 工作目錄已有一版去重邏輯；本 spec 以它為基礎，補齊文件、測試與快取，不要求重寫。
- Review 時 `npm test` 已是 573 passed；本 spec 的改動應維持全綠。
- 商品卡顯示模組同時供首頁、今日漁獲、商品列表與個人資訊頁使用；設定頁也會載入此模組。任何一頁的版本沒升，回訪買家都可能看到舊行為。
- dev server 使用 `no-store`，所以本機看不到快取問題；正式靜態站或 CDN 才是風險。
- 交易房 spec、UI 規格與路線圖 AC-21 是三個要一起改的文件；三者對地區規則的敘述必須一致。
- 若 `location` 的來源改成不含縣市，前綴比對會自然退回 `region + location`，不需要改程式。
