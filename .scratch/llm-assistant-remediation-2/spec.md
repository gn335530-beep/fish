# 助手房 LLM Beta 第二輪 review 修正：遮蔽、用詞與重複邏輯

**Status:** ready-for-agent

**Source:** 2026-11-15 對 `20985e6..HEAD`（LLM assistant tickets 01–08＋第一輪 remediation 01–11）的 Standards／Spec 雙軸 review。行為契約以 `docs/adr/0011-hybrid-llm-assistant.md`、`GLOSSARY.md` 與 `docs/spec/` 為準；前一輪 spec 位於 `.scratch/llm-assistant-remediation/spec.md`。

## Problem Statement

助手房 LLM Beta 與第一輪修正已經上線，但第二輪 review 發現還有三類問題會直接影響使用者或維護者：

- **個資遮蔽同時漏遮與誤遮。** `+886` 開頭的市話與「頭份市中正路」這類以「市」結尾的鄉鎮市區地址會原樣送到 Gemini 與 Tavily；但「台北市區的網路很慢」這種一般句子又會被整段換成 `[已遮蔽]`。使用者會同時承擔外洩風險與看不懂的回覆。
- **用詞與文件漂移。** 刪除交易房的確認訊息仍說「聊天室」，與 GLOSSARY 明文 Avoid 的詞衝突；設定頁說明仍寫「地址」，但表單只有縣市與區；GLOSSARY 的「資料來源」條目把 `CHAT`、`WEB`、`web_search` 等實作名詞寫進領域文件；ADR-0011 被修改，違反前一輪「ADR-0011 不改」的決議。
- **同一種邏輯散落多處。** 請求期限在 provider、網路搜尋工具、行情工具、行情上游與行情快取各自實作一次，任一处漏接就會讓使用者一直看到「小幫手正在輸入…」；前端首次送出與重試幾乎是同一段程式貼兩次，重試前置條件與 pending 計數很容易改一處漏一處；AI 路由模組同時負責 intent 優先序、slot 合併與平台動作，新增 intent 時要讀完整個檔案。

這些問題不改變 beta 定位、API 形狀或資料模型，但會讓「遮蔽可信」「用詞一致」「逾時可預期」三個承諾開始失準。

## Solution

讓助手房回到單一、可驗證的實作：

- 遮蔽只處理真正的個資格式：地址必須有行政區錨點且街名不得是虛詞開頭；電話補上 `+886` 市話與常見分隔寫法；一般句子中的「路」「弄」「市區」不再被誤遮。
- 使用者可見字串與文件統一使用 GLOSSARY 的詞：助手房、交易房、訊息、未成交訂單、已成交訂單。GLOSSARY 只留使用者看得見的概念，實作名詞回到 API 與 ADR。
- 請求期限收成一份共用實作，所有 provider 呼叫與工具執行都吃同一個剩餘時間；工具不得自行建立更長的期限。
- 前端首次送出與重試共用同一個嘗試流程；AI 路由只做路由，平台意圖處理與共用文案各自獨立。
- 前端 AI 測試共用同一份 API stub、flow 初始化與訊息 factory。
- 行為保持不變，除了遮蔽輸出與使用者可見文案。既有測試的斷言不改。

## Implementation Decisions

### 遮蔽規則

- 遮蔽仍由單一 redaction 模組負責；輸入是訊息文字與 context 中的字串欄位，鍵名與非字串值不處理。
- **地址必須有行政區錨點**：縣市（「台」與「臺」互通）或鄉鎮市區（區、鄉、鎮、市）其中一層，再接街路名（路、街、大道），可選擇性接段、巷、弄、門牌與樓層。
- **鄉鎮市區層級新增「市」**，讓「頭份市中正路」成立；只有縣市層級或只有鄉鎮市區層級都算錨點。
- **街路段落不得以虛詞開頭**：至少第一個字必須是街名實詞；「的」「之」「和」「與」「在」「有」「很」等連接或語氣字不得出現在街名段落的起始位置。這讓「台北市區的網路」不再成立，但保留「復興南路」。
- 單獨出現的「路」「弄」「街」不得觸發遮蔽。
- 電話樣式在既有基礎上補上：`+886` 後接區碼（可有可無前導 0，可有 `-`、空白或括號分隔）再接市話號碼；行動電話維持 `09xx` 與 `+886 9xx` 兩種寫法；4 碼區碼維持支援並納入測試。
- Email 與身分證字號格式不變，但補邊界測試，確認前後文不會被吃掉。
- 遮蔽順序不變：身分證、Email、行動電話、市話、地址。
- 遮蔽後的字串才可送給 Tavily；對話歷史與 context 摘要送給 Gemini 前也要先遮蔽。
- 寧可保留一般句子的語意，也不要為了「一定遮到」而放寬錨點條件；漏遮靠固定格式清單補齊，並以測試案例固定。

### 請求期限

- 新增一份共用的期限工具，所有需要「剩餘毫秒」的地方都用它，不再各自建立 `AbortController` 與計時器。
- 期限工具提供兩種用法：
  - **中止訊號**：以剩餘毫秒建立 `AbortSignal`，回傳訊號與清理函式；provider 與網路搜尋工具使用。
  - **競速結果**：以剩餘毫秒與 promise 競速，逾時回傳呼叫端指定的結果；行情工具、行情上游與行情快取使用。
- 剩餘時間小於或等於零時，期限工具立即回逾時結果，呼叫端不得再呼叫下游。
- 逾時語意仍由呼叫端映射：行情工具與行情上游逾時 → `LLM_TIMEOUT`（靜默 fallback）；provider 中止 → `LLM_TIMEOUT`；網路搜尋中止 → `LLM_TIMEOUT`。
- 一個 AI 回覆只有一個期限：一般回覆 8 秒；一旦這一輪執行網路搜尋，期限延長為 15 秒。工具執行前以當下剩餘時間為準。
- 工具不得自行建立比收到的剩餘時間更長的期限；行情工具的查詢與上游抓取共用同一個剩餘時間。
- 計時器一律在結束時清理，包含成功、失敗與逾時路徑。

### 前端 AI 回覆流程

- 首次送出與重試共用同一個嘗試流程：清除或保留既有重試狀態 → 增加等待中的回覆數 → 呼叫 AI 回覆端點 → 決定是否顯示可重試提示 → 交付規則或 LLM 結果 → 減少等待中的回覆數。
- 差異只由參數表達：首次送出帶入剛寫入的訊息與文字；重試帶入既有的訊息與文字，並在成功後清除重試狀態。
- 重試前置條件集中在一處：必須有重試狀態、房間相同、且沒有其他等待中的 AI 回覆。
- 等待中的回覆數維持「等待中的 AI 回覆數」語意，不是使用者訊息數。
- 可重試提示仍只在「規則回覆是一般引導句」時顯示；平台回覆與 LLM 文字照常交付。
- 對外行為不變：重試沿用同一個訊息、不重寫使用者訊息、新訊息不影響重試結果。

### AI 路由拆分

- 路由模組只保留：上下文正規化、規則 intent 與 LLM intent 的優先序、上架流程進行中的特殊處理、商品推薦與回覆 intent 的判斷，以及最終 fallback。
- 平台意圖處理（賣魚、找魚、行情、取消、修改）移出獨立模組，維持同一個輸入與 `{ origin, result }` 輸出介面。
- 重置文案集中為單一常數，路由模組與既有規則服務共用，不再各自寫一份字串。
- 路由模組的對外函式簽名不變；呼叫端與測試不需要改。

### 測試樣板

- 前端 AI 測試共用一份 fixture：安裝假 API、初始化 flow、建立房間與訊息、重設 store。
- 每個測試檔只保留自己的假資料、假回應與斷言；不得再複製安裝與初始化樣板。
- 共用 fixture 的行為必須與原本各檔案的初始化等價，既有斷言不改。

### 用詞與文件

- 使用者可見字串不得出現「聊天室」。刪除確認沿用「交易房」與「訊息」，並區分「未成交訂單」「已成交訂單」與「交易紀錄」。
- 領域文件中的「聊天室」依語意改為「訊息區」或「對話」；ADR-0012 的標題與內文同樣改用「對話」，決策內容不變。
- 歷史文件（trade-room-redesign 的 spec 與 ticket、已完成的 review spec）不改，避免改寫歷史紀錄。
- GLOSSARY 的「資料來源」條目只保留使用者可見的描述；`CHAT`、`WEB`、`web_search`、意圖升級規則移到 API 或流程文件。
- 設定頁說明改成與表單一致：頭像、暱稱、電話、縣市、區。
- 移除工作區對 ADR-0011 的新增段落，維持凍結；強制工具的行為改記錄在流程或 API 文件。
- README 的環境變數清單維持只列真正支援的項目，不新增或恢復已移除的變數。
- 文件同步視為驗收條件：行為、文案、環境變數或卡片型別一有變動，就在同一個變更更新相關 spec、ADR、GLOSSARY 與 README。

### 相容性

- `POST /api/ai/reply` 的請求與回應形狀不變。
- 靜默 fallback、配額提示、重試按鈕與交易房隔離維持現行行為。
- 行情卡、商品卡與協議流程不改資料模型。
- 唯一可見的行為差異是遮蔽後的字串與刪除確認文案。

## Testing Decisions

好的測試只驗證外部行為：給定使用者訊息、歷史、context 與注入的外部服務結果，斷言 API 回應、送給 provider 的輸入、寫入的訊息與卡片。測試不斷言內部函式呼叫次數、模組結構或私有欄位。

只使用兩個既有接縫，不新增單元或 e2e 接縫：

- **後端接縫：AI 回覆端點。** 真實 Express app、暫存 DB、真實登入，注入假 provider、假 Tavily fetcher 與假行情上游。既有 AI 回覆、歷史、錯誤、防護、工具與逾時測試是直接前例。
- **前端接縫：送出訊息與重試流程。** 假 API 回應訊息端點與 AI 回覆端點，驅動送出與重試，斷言寫入的訊息、卡片與 context。既有 AI 流程、意圖、配額重試、工具卡片與推薦測試是直接前例。

後端要涵蓋的行為：

- 一般文字含「路」「弄」「市區」時原樣送給 provider；「台北市區的網路很慢」「網路上的天氣」「弄一桌好菜」不得被遮蔽。
- `+886` 行動與市話、括號區碼、4 碼區碼、含里鄰地址、以「市」結尾的鄉鎮市區地址、Email 與身分證字號都被替換成遮蔽字樣。
- 上述敏感值不得出現在 provider 輸入；Tavily 收到的查詢只含遮蔽後的字串。
- 行情上游延遲超過期限時，端點在期限內回未處理與逾時錯誤碼；含網路搜尋的回合可使用較長期限。
- 期限用盡時不得再呼叫下游：以假 upstream 斷言呼叫次數為零。
- 歷史輸入最多 10 則、每輪工具呼叫最多 2 次；即使把已移除的環境變數設成其他值，行為仍固定。這兩個測試是刻意的回歸護欄，需以註解說明。
- 既有的錯誤映射、數字防護、來源升級與行情模型視圖斷言不變。

前端要涵蓋的行為：

- 首次送出與重試都會呼叫 AI 回覆端點，且重試沿用原本的訊息；重試不新增使用者訊息。
- 重試期間送出的新訊息不影響重試結果。
- 可重試錯誤顯示提示；平台意圖不寫入 LLM 文字；商品推薦不被前端關鍵字否決；交易房不呼叫 AI 端點。
- 上述行為在改用共用 fixture 後仍以相同斷言通過。

文件沒有自動化測試接縫；以人工核對本次行為與相關 spec、GLOSSARY、ADR 與 README 是否一致，並在最終驗收列出核對結果。

## Out of Scope

- 變更 API 形狀、資料模型、卡片型別或錯誤碼詞彙。
- 在交易房加入 AI，或讓 AI 使用寫入型工具。
- 新增 redaction 專用單元接縫或 Playwright e2e；本次只沿用既有兩個接縫。
- 改寫規則引擎的 intent 判斷、行情卡視覺或商品推薦排序。
- 改寫歷史文件（trade-room-redesign 與已完成的 review spec）。
- 處理工作區中與本修正無關的對話刪除功能變更；該變更應分開提交。
- 升級到付費 AI Studio、Vertex AI 或 Google Search grounding。
- 新增 allowlist、app 層使用額度、UI 隱私提示、串流、多模態或模型選擇器。

## Further Notes

- **提交切分**：目前工作區同時包含對話刪除功能與本修正的變更；建議先切開，避免同一個 commit 混兩個功能。
- **遮蔽案例清單**：實作與測試請固定這組案例——「台北市區的網路很慢」「網路上的天氣」「弄一桌好菜」（不得遮蔽）；`+886912345678`、`+886-2-12345678`、`(02)12345678`、`037-123456`、`台北市大安區復興南路一段100號`、`頭份市中正路12號`、Email、身分證字號（必須遮蔽）。
- **取捨**：誤遮會直接破壞使用者看到的內容，漏遮則可能外洩；本 spec 選擇「先確保一般句子不被誤遮，再用固定格式清單補漏」，並以測試案例固定兩側邊界。
- **200 行限制**是硬規則。拆分後若任何檔案仍超過上限，應再依職責拆檔，而不是壓縮程式碼。
- **文件同步**是驗收條件；用詞修正與程式修正必須在同一個變更內完成。
