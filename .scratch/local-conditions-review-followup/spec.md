# 在地資訊 review follow-up

**Source:** 2026-11-21 `local-conditions` 01–09 code review（固定點 `5a2c214`）；對應 tickets 01、02、03、04、07、08、09 的驗收缺口與 Standards 的文件不一致。
**Status:** ready-for-agent

## 問題陳述

助手房的在地資訊 beta 已完成，但 review 發現幾個使用者可見的缺口：

- 國外地點天氣遇到 Tavily 逾時或上游錯誤時，回覆會變成靜默 fallback 或通用引導句，而不是「查不到國外地點天氣」。網路停用與查無結果已有正確回覆，只剩逾時與上游錯誤路徑不一致。
- 使用者在下一句用「來源是哪個網站」要求來源時，後端不把它視為純來源請求，會再呼叫模型並重新產生查詢，而不是重查上一則工具；使用者拿不到剛剛那份資料的來源。
- 缺少 CWA 金鑰或潮汐上游失敗時，「潮汐暫無資料」只靠 system prompt 提醒模型；模型若漏寫，後端不會補上。測試目前是假模型自己寫了這句話，沒有鎖住後端保證。
- 天氣、海況、潮汐數字只靠模型遵守 prompt；現有數字防護對「99 度」「90%」「8 級」「2 公尺」這類帶一般單位或小於等於 3 的數字會放行，模型可以產生未經工具支持的氣象數字。
- 天氣問題若模型誤傳海況模式，後端仍會查海況與潮汐；天氣只回天氣目前只有 prompt 約束，沒有後端強制。
- 「最新行情」這類平台問題會被地區分類誤判，後端先回「你所在的縣市是哪裡？」。目前前端規則優先序會蓋掉這個回覆，但這是靠前端補救；後端仍多一次無效呼叫，且端點被其他客戶端使用時會打斷平台操作。
- 流程規格對「在地新聞」與 timeout 的描述和程式不一致：一般新聞、「最新」會觸發縣市反問；氣象、潮汐逾時實際上回「查不到」，不是 `LLM_TIMEOUT`。

這些缺口讓使用者在不穩定網路、缺少金鑰或模型出錯時看到錯誤的資料、錯誤的引導句，或拿不到要求的來源。

## 解決方案

讓在地資訊的每一條路徑都有後端保證，而不是只靠 prompt：

- 問題分類分成「需要縣市的地區問題」與「只需要網路搜尋的在地資訊」；平台意圖永遠優先，不因「最新」「新聞」「天氣」等字樣被地區反問打斷。
- 國外地點天氣的網路逾時與上游錯誤，一律回 200 + `intent:CHAT` +「查不到國外地點天氣，請稍後再試。」；要求來源時附「目前沒有可提供的來源。」
- 下一句的來源請求只要以來源詞語為主，就重查上一則對應工具，不呼叫模型；支援天氣、海況、一般網路三種來源。
- 海況回覆缺少潮汐時，後端保證出現「潮汐暫無資料」；不編造潮汐時間。
- 在地工具回覆中的氣象、海況、潮汐數值必須有當輪工具依據；模型自行產生的數字沿用既有防護 fallback，不會顯示。
- 天氣與海況的模式由後端依問題類型決定；模型不能把天氣題改成海況題。
- 流程規格、API 規格、ADR、詞彙表與 README 同步上述行為。

## 實作決策

### 1. 問題分類與縣市上下文分開

- 把「在地資訊主題」與「需要縣市的地區問題」視為兩件事。在地資訊主題包含新聞、交通、路況、活動、颱風、即時與在地；需要縣市的地區問題包含天氣、海況、潮汐、釣魚建議、附近／這裡／這邊、在地新聞、地方新聞與縣市名稱。
- 單獨的「最新」不再觸發縣市上下文，也不再把「最新行情」當成地區問題；時間性問題仍可依既有規則走網路搜尋。
- 一般新聞沒有縣市時不反問；網路搜尋可用時走網路搜尋，停用時一般回答。有設定、暫存或訊息中的縣市時才帶入縣市。明確說「在地新聞」或「地方新聞」但沒有縣市時，才反問縣市。
- 交通、路況、活動、颱風視為需要縣市的地區問題；沒有縣市時維持反問。
- 平台意圖（行情、賣魚、取消、修改；與既有規則優先序一致）永遠優先：不反問縣市、不把縣市放進 prompt、不強制在地工具，也不因在地工具結果改寫平台意圖。即使訊息同時有「天氣」「新聞」「最新」也一樣。
- 縣市優先序維持：訊息中明確縣市 > 目前對話暫存縣市 > 設定頁縣市。只使用縣市，不使用區或地址。

### 2. 在地失敗文案的適用範圍

- 「你所在的縣市是哪裡？」只在該輪被判定為需要縣市的地區問題時使用。
- 非地區問題若模型誤呼叫在地工具，不反問縣市；以 `LLM_GUARD_REJECTED` 或等效的安全 fallback 結束該輪，不採用模型產生的在地文字，避免把一般問題或平台問題變成地區問題。
- 海況缺少海域時仍反問「你想問哪個海域？」；這個反問只在海況類問題發生。

### 3. 天氣與海況的模式由後端決定

- 該輪已判定為天氣問題時，在地工具只能使用天氣模式；模型傳入海況模式時，後端以天氣模式為準。
- 該輪已判定為海況、潮汐或釣魚建議時，在地工具只能使用海況模式，回傳完整海況包。
- 該輪沒有地區模式（例如只有明確縣市但問題不是天氣或海況）時，才允許模型選擇工具模式。
- 工具結果不得因為模型傳錯模式而出現不屬於該問題的資料；天氣結果不得含海況、浪或潮汐。

### 4. 國外地點天氣的逾時與上游錯誤

- 國外地點天氣回合中，網路搜尋逾時或上游錯誤時，回 200、`handled:true`、`intent:"CHAT"`、`reply_text:"查不到國外地點天氣，請稍後再試。"`，不呼叫模型產生替代答案。
- 要求來源時在同一則回覆加上「目前沒有可提供的來源。」；來源卡為空陣列。
- 回應的 `error_code` 維持 `null`；內部 log 保留上游錯誤碼（`LLM_TIMEOUT` 或 `LLM_UPSTREAM_ERROR`），方便除錯。
- 網路搜尋關閉、查無結果與上述逾時／上游錯誤使用同一套使用者可見文案。
- 配額用完與速率限制維持既有可重試行為，不套用這個直接回覆。

### 5. 下一句的來源請求

- 純來源請求的判定以「來源詞語為主」：移除來源關鍵詞、指示詞、語氣詞與常見動詞後，若沒有剩下新的問題內容，就視為純來源請求。像「來源是哪個網站」「這則的來源」「資料哪來，有網址嗎」都要算。
- 純來源請求不呼叫模型；依上一則使用者問題重跑對應工具：天氣走在地天氣工具、海況／潮汐／釣魚走海況包、一般網路與新聞走網路搜尋。
- 上一則問題無法對應到任何工具，或對應工具沒有合法來源時，回「目前沒有可提供的來源。」，不編造連結。
- 平台意圖的上一則問題不產生網路來源卡；行情卡原本的「資料來源：農業部 漁業署」維持文字。
- 不做來源暫存；伺服器重啟後再問會重新查詢。

### 6. 潮汐降級的後端保證

- 海況模式且潮汐缺少時，最終回覆一定要有「潮汐暫無資料」。模型已寫出這個片語時不重複追加；模型漏寫時由後端補上。
- 缺少 CWA 金鑰、潮汐逾時、無資料、格式錯誤與沒有代表潮位站都走同一個降級文案；不產生任何潮汐時間。
- 追加提示後若超過回覆長度上限，優先保留「潮汐暫無資料」，截斷模型文字，不丟掉提示。
- 釣魚建議的既有缺失清單（海況、天氣、潮汐）維持；不重複追加。

### 7. 在地數字的防護

- 該輪使用在地工具時，回覆中的氣象、海況、潮汐數值必須出現在使用者訊息或當輪工具結果中。
- 需要嚴格檢查的數值包含：氣溫、海溫、降雨機率、風速、陣風、風級、浪高、浪向、浪週期、潮汐時間與日期。帶「度」「℃」「%」「級」「公尺」「米」「秒」「節」等在地單位的數字，不得套用一般單位例外。
- 潮汐時間與日期也必須有工具依據，不能靠「小於等於 3」或一般單位例外放行。
- 工具依據加入預報天數，讓「未來 7 天」這類結構性數字有來源；一般知識的數字防護維持不變。
- 未通過防護時沿用既有 `LLM_GUARD_REJECTED` 靜默 fallback；不顯示模型產生的數字，也不新增錯誤碼。

### 8. 輸出契約

- 不新增 API 欄位，也不改動既有 `handled`、`intent`、`reply_text`、`sources`、`tool_results`、`error_code` 的語意。
- 直接回覆（國外天氣逾時、查無來源、缺縣市、缺海域）維持 200 與 `handled:true`。
- 來源卡仍只由後端工具結果產生，最多 3 個合法 http／https URL；回覆文字不出現 URL。
- 平台意圖仍不產生 `reply_text` 或網路來源卡。

### 9. 文件同步

- 流程規格要寫清楚：哪些問題需要縣市、哪些只需要網路；一般新聞沒有縣市時不反問；「最新」不再單獨觸發縣市。
- 流程規格與 API 規格要寫清楚 timeout 分工：模型與行情上游逾時回 `LLM_TIMEOUT`；國外地點天氣的網路逾時回 `handled:true` 的「查不到」；在地氣象、海況、潮汐逾時回缺少資料的說明或「潮汐暫無資料」。
- ADR-0013、`GLOSSARY.md` 與各 README 若提到「在地新聞」、國外天氣逾時或潮汐降級，要與新行為一致。
- 文件與程式不一致視為缺陷；文件更新算在這次完成條件內。

### 10. 實作紀律

- 新增與修改的程式碼檔案不超過 200 行；若接近上限，依職責拆檔，不壓縮程式碼。
- 測試只注入假的外部服務，不呼叫真實 Gemini、Tavily、Open-Meteo 或 CWA。
- 這次不順手做大型異味重構；只做支撐上述行為的必要整理。

## 測試決策

### 什麼是好測試

- 只測外部行為：`POST /api/ai/reply` 的回應（`handled`、`intent`、`reply_text`、`sources`、`tool_results`、`error_code`）與前端使用者看到的助手訊息。
- 不直接測私有 helper、不鎖定 prompt 全文；需要確認工具是否被呼叫時，看假上游收到的請求或工具結果，不看模型 prompt 的實作細節。
- 每個失敗路徑都要有成功對照：逾時要對照停用與空結果；缺潮汐要對照有潮汐；未支持數字要對照工具支持的數字。
- 測試必須決定性、不連網、不依賴真實時間；日期與潮汐資料用固定 fake payload。

### Seam

- **後端主 seam**：既有 `POST /api/ai/reply` HTTP 端點，搭配 fake provider、fake Tavily、fake Open-Meteo、fake CWA。所有後端行為都在這個 seam 驗證。
- **前端 seam**：既有 `flow.submitText` + mock `/api/ai/reply` 的流程測試，鎖住平台意圖優先序。
- 不新增第三個 seam；不直接測 guard、source-request、conditions 的私有函式。

### 要測的模組

- AI 回覆協調：國外天氣逾時、來源請求、在地失敗文案、潮汐補字、數字防護。
- 問題分類與地區上下文：平台優先、新聞類縣市規則、縣市優先序、模式判定。
- 在地條件工具：天氣／海況模式權威、潮汐缺少、工具結果欄位。
- 輸出驗證：在地數字嚴格依據、來源上限、URL 移除。
- 前端意圖路由：平台意圖不被後端地區反問覆蓋。

### 既有測試的 prior art

- 國外地點天氣與網路：`ai-foreign-weather`、`ai-tools-web`。
- 來源請求：`ai-source-requests`、`ai-source-requests-next`。
- 在地天氣／海況／潮汐：`ai-tools-weather`、`ai-tools-sea`、`ai-tools-tide`。
- 數字防護：`ai-reply-guard`。
- 地區上下文：`ai-region-context`。
- 前端平台意圖：`ai-intents`。

### 必要案例

- 國外地點天氣：Tavily 逾時、上游錯誤、停用、空結果四種都回同一句「查不到」；要求來源時附無來源提示；不呼叫模型產生答案。
- 來源請求：天氣後說「來源是哪個網站」不呼叫模型、回上一則天氣來源；網路問題後說「資料哪來」重跑 Tavily；平台問題要求來源時不產生網路來源卡。
- 潮汐：缺 CWA 金鑰、潮汐逾時、無資料、模型漏寫「潮汐暫無資料」時都由後端補上；模型已寫時不重複；不產生潮汐時間。
- 數字防護：工具回 27°C、40%、3 級、1.5 公尺時可通過；模型改寫成 99 度、90%、8 級、2 公尺時被擋下，回覆不顯示這些數字。
- 模式：天氣問題的假模型硬傳海況模式，工具結果仍是天氣，沒有海況、浪或潮汐；海況問題仍回完整海況包。
- 地區分類：「最新行情」不反問縣市；「NBA 新聞」沒有縣市時不反問；「今天有什麼新聞？」有暫存縣市時帶入縣市、沒有縣市時不反問；「在地新聞」沒有縣市時反問；天氣問題沒有縣市時仍反問。
- 前端：後端回 `intent:CHAT` 的「你所在的縣市是哪裡？」時，行情問題仍由平台規則完成，畫面不出現這句反問。
- 回歸：來源卡最多 3 個合法 URL、回覆文字無 URL、平台意圖不產生 `reply_text`、釣魚建議資料不足不做判斷。

### 既有測試預期變更

- `ai-region-context` 目前預期「今天有什麼新聞？」在沒有縣市時反問，也預期非地區問題誤呼叫在地工具時反問。新行為下，前者不反問、後者回 `LLM_GUARD_REJECTED` 或等效的安全 fallback；測試要改成預期新行為，並保留「有暫存縣市時帶入縣市」的案例。
- `ai-tools-tide` 目前的假模型會自己在回覆寫「潮汐暫無資料」；新案例要讓模型漏寫，證明後端會補上。
- `ai-foreign-weather` 要補 Tavily 逾時與上游錯誤；可以只擴充 fake Tavily 的錯誤模式，不新增 production seam。
- `ai-source-requests-next` 要補「來源是哪個網站」與「這則的來源」等自然說法。
- `ai-reply-guard` 要補在地數字的成功與失敗對照；一般知識的既有案例不變。
- `ai-intents` 要補後端回 `intent:CHAT` 地區反問時，平台規則仍優先的案例。

### 驗收範例

- 使用者：「東京天氣如何？」（Tavily 逾時）→ 助手：「查不到國外地點天氣，請稍後再試。」
- 使用者：「東京天氣如何？有連結嗎？」（Tavily 逾時）→ 助手：「查不到國外地點天氣，請稍後再試。\n目前沒有可提供的來源。」
- 使用者：「高雄天氣如何？」→ 助手回天氣；使用者：「來源是哪個網站？」→ 助手回上一則天氣來源卡，不呼叫模型。
- 缺少 CWA 金鑰，使用者：「高雄海況如何？」→ 助手回浪況與天氣，並有「潮汐暫無資料」。
- 天氣工具回 27°C，模型回「今天 99 度」→ 助手不顯示 99 度，走既有 fallback。
- 天氣問題，模型誤傳海況模式 → 工具結果只有天氣，沒有浪或潮汐。
- 使用者：「最新行情」→ 平台行情規則直接處理，不反問縣市。
- 使用者：「NBA 新聞」（網路搜尋可用）→ 直接走網路搜尋，不反問縣市。
- 使用者已有暫存高雄市，問「今天有什麼新聞？」→ 帶入高雄市；沒有縣市時則不反問，網路搜尋可用時直接走網路搜尋。
