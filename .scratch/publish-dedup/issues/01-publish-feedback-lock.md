# 01: 上架確認立即回饋、單次發布與房間隔離

**What to build:** 釣客在助手房按下「確認上架」後，不必等後端完成就立即看到「上架中…」，草稿卡的三個動作同時停用；在請求完成前重複點擊不會再送出第二次發布。成功時沿用現有結果：草稿卡消失，只留下「已上架：{標題}」訊息與 toast；失敗時草稿與按鈕恢復，並顯示看得見的錯誤提示。發布開始時先記住當下房間，等待期間切到其他助手房也不會把結果寫進別的房間。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 按下「確認上架」後，草稿卡主要按鈕在請求完成前立即顯示「上架中…」；「確認上架／修改草稿／取消上架」三個動作都停用，並帶 `aria-busy`。
- [x] 同一份草稿在極短時間內連續點擊「確認上架」，只送出一次建立商品請求，只建立一筆商品。
- [x] 發布進行中再次觸發發布會被直接忽略，不會排隊，也不會補送第二個請求。
- [x] 發布失敗時，草稿內容保留、三個動作恢復可用，並同時顯示面板提示與 toast 錯誤訊息。
- [x] 發布成功時，草稿卡消失，只留下「已上架：{標題}」訊息與含商品標題的 toast。
- [x] 發布開始時捕獲當下房間；成功或失敗都只更新原本那一間助手房。等待期間切到其他助手房時，其他房間的訊息與 context 不被改動。
- [x] 忙碌狀態只改變草稿卡的按鈕文字、停用狀態與 `aria-busy`，不改草稿欄位、其他卡片、版面或草稿修改／取消上架的既有語意。
- [x] 前端測試涵蓋：連點只送一次、忙碌狀態的按鈕文字與停用屬性、失敗後解鎖、切換房間不污染目前房間。
- [x] 修改的前端程式檔案不超過 200 行。
