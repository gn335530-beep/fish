# 02: 回覆防護放行「列表編號」

**What to build:** 助手用行首條列編號（例如「1. 清蒸 2. 紅燒」）回答料理方式時，編號數字不再被「數字接地防護」擋下。列表標記只在「該數字確實作為行首條列編號」時免接地，同一則回覆中其他位置的相同數字仍須通過接地檢查；同列連續條列（「1.清蒸 2.紅燒」）也應涵蓋。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 防護新增「行首條列編號」辨識，行首列表編號不進平台數字接地檢查。
- [x] 新增測試：條列編號回覆不再被拒。
- [x] 修正接地破口：列表編號免接地不得「整則放行」該數字，其他位置的相同數字仍須接地。
- [x] 補測：同列連續條列（「1.清蒸 2.紅燒」）不應仍被誤擋。
- [x] 補同步 `docs/spec/`：列表編號放行寫進 05-api 與 03-flows。

## Comments

- 2026-11-22：review 標出兩處缺口——(1) `listMarkerNumbers` 使數字在整則回覆任何位置都免接地，例「4. 煮湯」加「每台斤 4 元」會讓未接地的 4 也放行；(2) 正則只認行首，同列條列不匹配。兩者已修：改以 `stripListMarkers` 在接地前移除「數字後緊接列表符號且非小數」的編號，其餘數字仍受接地檢查，同列條列也涵蓋。
