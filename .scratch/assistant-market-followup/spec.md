# AI 助手回覆與行情歷史的後續修正

**Status:** ready-for-agent

**Source:** 2026-11-22 對工作目錄未提交變更（vs HEAD）的 Standards／Spec 雙軸 review。本批涵蓋五組修正：`LLM_PREFILL_TOOL` 預填、回覆防護列表編號放行、歷史截短與只答最新一句、CWA 潮汐 v2 格式、行情歷史改為日曆天。多數變更已實作於工作樹（未提交），本 spec 用於補齊文件、修正已知缺口並驗證契約。

## Problem Statement

釣客與買家在助手房使用 AI 助手、查看行情卡時，有幾處行為不如預期：

- 天氣／海況問題要等模型先決定工具、再執行、再回覆，多一輪模型呼叫，回覆較慢、token 較多。
- 助手用條列編號（例如「1. 清蒸 2. 紅燒」）回答料理方式時，編號數字被「數字接地防護」誤判成未接地的平台數字，整則回覆被丟棄。
- 助手會重複先前回覆、重提先前話題；歷史把長回覆完整送進模型，膨脹 context，助長重複與成本。
- 中央氣象署潮汐開放資料改了回應格式後，潮汐抓不到資料、只顯示「潮汐暫無資料」。
- 行情卡的「近 7／30 個交易日」語意與使用者直覺不符：長休市時點數對不上，使用者以為是「近 7／30 天」。

## Solution

- 在地天氣／海況由後端直接執行在地工具並預填結果，省一次模型決策回合；預設關閉，可用環境變數開啟。
- 條列編號不再被數字接地防護擋下，料理方式等條列回答正常通過。
- 助手每次只回答最新一句、不重複先前回覆；歷史中長回覆截短，減少 token 與重複。
- 潮汐改接中央氣象署新版回應格式，滿潮／乾潮時間照常顯示。
- 行情卡走勢改為「近 7／30 日（日曆天）」，顯示該範圍內所有有交易的日期，週末休市日不補。

## User Stories

1. 作為使用者，我想問天氣或海況時更快得到回覆，以便不用等太久。
2. 作為使用者，我想在預填開啟時，天氣／海況答案的內容與關閉時一致，以便得到一樣的正確資訊。
3. 作為維護者，我想在地天氣／海況由後端直接執行工具，以便省一次模型決策回合與 token。
4. 作為維護者，我想預填只套用在「後端已能決定在地模式與縣市／海域」的在地問題，以便 `web_search`／`search_products` 仍由模型產生查詢或魚種。
5. 作為維護者，我想預填預設關閉、由環境變數開啟，以便不影響既有行為。
6. 作為使用者，我想助手用條列編號回答料理方式時不會被擋下，以便看到完整的料理建議。
7. 作為維護者，我想只有「行首的條列編號」被視為列表標記、平台數字防護不擋，以便不誤傷一般數字。
8. 作為使用者，我想助手只回答我最新一句、不重提先前回覆與話題，以便對話聚焦。
9. 作為使用者，我想明確說「第二個」「那另外一種」時助手仍參照先前回覆，以便延續指涉。
10. 作為維護者，我想歷史中助手長回覆與使用者長訊息截短到固定上限，以便降低 token 與重複。
11. 作為使用者，我想潮汐滿潮／乾潮時間照常顯示，以便上游改版後仍看到潮汐。
12. 作為維護者，我想潮汐資料源解析新版回應結構（`TideForecasts`），以便對接上游格式。
13. 作為使用者，我想行情卡走勢顯示「近 7／30 日」，以便語意與我的直覺一致。
14. 作為使用者，我想行情走勢顯示該日曆天範圍內所有有交易的日期，以便週末休市日不會被硬湊。
15. 作為維護者，我想行情歷史抓取往回抓 N 個日曆天並多留緩衝，以便涵蓋休市日與資料落後。
16. 作為維護者，我想 `docs/spec/` 與各 README 反映這些行為變更，以便文件與程式一致。
17. 作為維護者，我想所有程式檔案維持在 200 行內，以便符合專案規範。

## Implementation Decisions

### 預填工具（`LLM_PREFILL_TOOL`）

- 新增環境變數 `LLM_PREFILL_TOOL`（預設關閉）。
- 只在「後端已決定在地模式與縣市／海域」時預填：當該輪被強制為在地工具、且在地 context 已就緒，工具迴圈開始前直接執行在地工具、把結果放進工具結果，模型只看結果輸出 JSON。
- `web_search`／`search_products` 仍需模型產生查詢或魚種，不預填。
- 預填執行同樣受單一回覆期限約束；開始前剩餘時間已用盡即逾時。

### 回覆防護列表編號

- 防護在接地檢查前移除「條列編號」：數字後緊接列表符號（`.`、`、`、`)`、`）`）且非小數（後不接數字），例如「4. 煮湯」與同一行的「1.清蒸 2.紅燒」。
- 條列編號移除後，同一則回覆中其餘位置的數字仍須通過接地檢查；不得因某數字當過列表編號就整則放行。

### 歷史截短與只答最新

- 歷史中助手回覆截短到 120 字、使用者訊息 300 字（卡片維持一行摘要）。
- system prompt 明示「每次只回答最新一句、不重複先前回覆與話題；使用者明確要延續時才參照先前回覆」。

### 潮汐 v2

- 潮汐資料源改解析新版 `TideForecasts`（每筆含 `Location` 與 `TimePeriods.Daily`）；滿潮／乾潮從 Daily 的 `Time` 讀取。
- 缺資料、格式錯誤或缺金鑰時仍回「潮汐暫無資料」，不編造時間。

### 行情日曆天

- 「近 N 個交易日」改為「近 N 個日曆天」：查詢以 endDate 往回 N 天過濾交易日，抓取多留 7 天緩衝。
- 前端卡片標籤「近 N 個交易日」→「近 N 日」，走勢切片同口徑（以最後交易日為錨往回 N-1 天）。
- 起算點維持以最後交易日為錨（非「今天」），前後端口徑一致。

### 文件

- 更新 `docs/spec/`（02／03／04／05／06）、`README.md`、`backend/README.md` 反映以上變更。
- 特別補上：`LLM_PREFILL_TOOL` 進環境變數清單、移除「每輪最多 2 次工具呼叫，沒有環境變數可調」的過時敘述、歷史截短與只答最新一句的行為、列表編號放行、潮汐 v2 結構。
- 任一程式檔案因新增邏輯逼近 200 行時，依職責拆分，不壓縮程式碼湊行數。

## Testing Decisions

好的測試只驗外部行為：HTTP 狀態與 JSON、回覆文字、`tool_results`、送進 provider 的訊息內容。不驗私有函式名稱、不驗內部呼叫堆疊，也不為了測試把模組拆得更細。

沿用既有 seam，不新增：

1. **AI 回覆（①②③④ 共用最高 seam）**：`POST /api/ai/reply`，測試用假 provider 注入，斷言模型呼叫次數、送進 provider 的 `messages`、與 `tool_results.local`。前例：`ai-reply-guard.test.js`、`ai-reply-history.test.js`、`ai-tools-tide.test.js`、`ai-prefill-tool.test.js`。
2. **行情（⑤）**：`GET /api/market/prices?include=history&days=N`（後端）＋ 行情卡建構器（前端 `market-card.test.js`）、e2e。

必測：

- 預填開啟：天氣／海況只呼叫模型一次、`tool_results.local` 有資料；關閉時維持工具決策＋回覆兩次呼叫。
- 列表編號：行首條列編號不觸發接地拒絕；並補「列表編號以外的相同數字仍須接地」與「同列連續條列」案例。
- 歷史截短：助手長回覆截到 120 字、短回覆保留、卡片摘要不變。
- 潮汐 v2：新格式 payload 解析出滿潮／乾潮；無資料／格式錯誤／缺金鑰仍回「潮汐暫無資料」。
- 行情日曆天：範圍內交易日依序回傳、休市日不補到 N 筆、標籤「近 N 日」。
- 完成後 `npm test` 全綠，所有程式檔案 ≤ 200 行。

## Out of Scope

- 預填套用到 `web_search`／`search_products`（仍由模型產生查詢或魚種）。
- 歷史截短上限的環境變數參數化（固定 120／300）。
- 潮汐其他上游或格式的相容層。
- 行情「日曆天」起算點改為「今天」而非最後交易日。
- 前後端日曆天切片邏輯的單一來源（跨前後端語言，弱重複，暫不動）。
- 列表編號以外的其他數字接地防護放寬。
