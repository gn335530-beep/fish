# 02 網域模型

本章定義系統裡有哪些東西、它們的關係、以及不能違反的規則。實作細節（欄位名、API）在 `04`、`05`。

---

## 1. 使用者

一個帳號同時具備買與賣的能力。

| 屬性 | 說明 |
| --- | --- |
| 手機號碼 | 帳號識別，也是登入帳號 |
| 暱稱 | 2–20 字，顯示在對話與商品 |
| 角色標籤 | `BUYER` / `SELLER`，**只影響顯示，不影響權限** |
| 地址 | 縣市、鄉鎮市區、詳細地址；顯示時串接為 `display_address` |
| 所在地區 | 取縣市，作為導購與上架的預設地區 |
| 信用 | `rating_score`（平均星等）、`review_count`、`completed_deals`、`no_show_count`、`is_blacklisted` |

**規則**

- 任何人登入後都可以上架、購買、評價。
- `role` 不得用來阻擋任何操作；未來若要真的分角色，必須另立 ADR。
- 銀行欄位存在但**不對外回傳**（`publicUser` 會移除），本版也沒有提領功能。
- 地址**不用於**面交地點；面交地點由雙方在協議中填寫。

**狀態**：✅ 已實作（密碼明文、Token 只存記憶體，見 `07-roadmap.md` 的已知缺陷）

## 2. 魚種

系統的魚種清單目前有 28 種，作為「已知魚種」的字典。

| 屬性 | 說明 |
| --- | --- |
| 識別碼 | 例如 `grouper`、`amberjack` |
| 名稱 | 例如 玳瑁石斑、紅魽 |
| 別名 | 使用者可能說的說法，例如「石斑」「紅甘」 |
| 拉丁學名 | 顯示用 |
| 料理屬性 | 肉質、刺的粗細、適合的料理法 |
| 示意行情 | `market`，元／台斤。**這是示意資料，不是行情** |

**規則**

- **魚種資料只能有一份真實來源**：放在後端，前端一律由 API 取得。
- **未知魚種可以上架。** 使用者說「鮭魚」時，即使字典裡沒有，仍可完成上架：保留使用者說的名稱、`species_id` 留空；商品照常販售，但沒有料理資料，行情顯示「暫無行情」。
- 不可以用名稱模糊比對把未知魚種硬塞進某個已知魚種。

**狀態**：✅ 已實作（示意行情未標示）

## 3. 商品

一次上架的漁獲批次。

| 概念 | 說明 |
| --- | --- |
| 總重 | 整批公斤數 |
| 尾數 | 整批個體數 |
| 整批售價 | 釣客開的整批總價（元） |
| 每尾均價 | 售價 ÷ 尾數，**衍生值** |
| 平均每尾重 | 總重 ÷ 尾數，**衍生值** |
| 處理方式 | 活體、放血冰鎮、三去處理、冷凍（四選一） |
| 照片 | 一張實拍照片，必填 |
| 地區 | 縣市，用於篩選與導購 |
| 捕獲時間 | 什麼時候釣到的 |

### 3.1 價格只有一種語意

| 欄位 | 意義 | 是否落庫 |
| --- | --- | --- |
| `price` | **整批總價（元）** | 是 |
| `unit_price` | 每尾均價（元） | 否，讀取時算 |
| `avg_weight_kg` | 每尾平均重量（公斤） | 否，讀取時算 |
| 參考價 | 由魚種示意行情換算的整批參考金額 | 是（遲早改為行情快照） |

**這是硬規則**：畫面不得把 `price` 當成單價再乘尾數，也不得把「元／台斤」與「整批總價」混在同一句話裡。台斤只出現在兩個地方：使用者輸入重量時、行情顯示時。

### 3.2 可售尾數與狀態

```
保留       = Σ(進行中訂單中該商品的尾數)      // 進行中 = PENDING_REVIEW 或 NEGOTIATING
可售       = 總尾數 − 已售 − 保留
狀態       = 保留 > 0 → PARTIALLY_RESERVED（畫面顯示「洽談中」）
             可售 ≤ 0 → SOLD_OUT
             否則     → ACTIVE
```

- `DRAFT` 訂單**不**計入保留。
- 有保留就先算「洽談中」，即使可售已經 0（全部尾數都在談，還沒成交）。
- 狀態與可售尾數**即時計算、不落庫**（ADR 0002）。
- 全部售完且沒有保留才是 `SOLD_OUT`；部分售出且還有可售，仍是 `ACTIVE`。

### 3.3 生命週期

```
上架（ACTIVE） → 有人提案（PARTIALLY_RESERVED） → 成交（已售增加）
                     ↑                              ↓
                取消／逾時（釋放）            售完（SOLD_OUT）
```

商品沒有「下架」狀態；本版不提供刪除，商品一旦上架就留在清單上，直到售完。

**狀態**：✅ 已實作（參考價仍是示意行情算出來的，見行情章）

## 4. 房間（對話）

| 類型 | 參與者 | 唯一鍵 | 用途 |
| --- | --- | --- | --- |
| 助手房 | 使用者 + 助手 | 每位使用者 1 間 | 上架、導購、諮詢 |
| 交易房 | 買家 + 釣客 | **買家 + 釣客** | 訊息、訂單、協議、評價 |

**規則**

- 權限一律以「參與者清單」為準；交易房另外記錄買家與釣客是誰，但那是語意標籤，必須與參與者清單一致。
- 交易房建立後，助手不再回覆；房間進入真人對話模式。
- 不同釣客之間互不可見；釣客看不到買家在助手房裡的導購對話。
- 同一組人**永遠只有一間**交易房，即使買了多個商品、成交多次。

**助手房的三種模式**

| 模式 | 意思 | 何時離開 |
| --- | --- | --- |
| `idle` | 沒事，每句話重新判斷意圖 | 進入 listing 或 shopping |
| `listing` | 有進行中的上架草稿，只抽欄位、不判斷意圖 | 發布或使用者取消 |
| `shopping` | 剛查過商品，記住卡片順序供指涉 | 可指涉上一批卡片，或重新判斷 |

**狀態**：✅ 已實作（助手房與交易房；交易房由洽談購買建立）

## 5. 訊息

| 型別 | 內容 |
| --- | --- |
| `text` | 純文字，上限 500 字 |
| `image` | 一張圖片網址 |
| `system` | 系統通知（例：協議逾時已釋放） |
| `card` | 結構化卡片，見下 |

**卡片種類**

| 卡片 | 內容 | 可執行動作 |
| --- | --- | --- |
| 商品卡 | 圖、標題、整批價、每尾均價、可售尾數、地區 | 深入諮詢、（未來）洽談購買 |
| 草稿卡 | 六個欄位摘要 | 確認發布、逐欄修改、重新填寫 |
| 訂單卡 | 多品項、小計 | 展開明細、（未來）送出協議 |
| 協議卡 | 整單金額、地點、時間、狀態 | 同意、退回、取消 |
| 評價卡 | 星等、標籤、評語 | 送出 |

**規則**

- 每則訊息有單調遞增序號，輪詢以序號取增量，不用時間戳（同毫秒會漏訊息）。
- 只有房間參與者能寫入訊息；`sender_type`（自己／助手／系統）只是標記，不是權限依據。
- 助手房以外的房間不得寫入 AI 狀態（`context`）。
- 卡片狀態存在訊息裡，訂單狀態改變時要同步更新，重新載入才不會顯示舊狀態。
- 系統訊息不計入未讀數。
- **訂單摘要不是訊息卡**：`DRAFT`／進行中訂單固定顯示在交易房上方，協議卡才是訊息。

**狀態**：✅ 已實作（文字、圖片、商品卡、草稿卡、協議卡；評價卡沒有渲染器）

## 6. 訂單

一組釣客與買家之間的一筆交易，可含同一位釣客的多個商品。

### 6.1 狀態機

```
[加入商品] → DRAFT ──提案──→ PENDING_REVIEW ──同意──→ CONFIRMED
               ↑                  │  ↑
               │               退回│  │重送（修改條件）
               │                  ↓  │
               └────────────── NEGOTIATING
                                  │
                         取消／逾時 → CANCELLED
```

| 狀態 | 庫存影響 | 可做的事 | 期限 |
| --- | --- | --- | --- |
| `DRAFT` | 不保留 | 加商品、改尾數、刪商品、清空、提案 | 無 |
| `PENDING_REVIEW` | 保留所有項目 | 接收方同意／退回；任一方取消 | 30 分鐘 |
| `NEGOTIATING` | 保留所有項目 | 退回方修改後重送；任一方取消 | 額外 15 分鐘 |
| `CONFIRMED` | 計入已售 | 雙方評價 | — |
| `CANCELLED` | 釋放所有項目 | 唯讀 | — |

### 6.2 不能違反的規則

1. **發起方送出提案即視為自己已簽**；接收方同意即成交。
2. 成交就是「交易完成」，同時寫入交易紀錄。
3. 一個交易房同時最多**一筆草稿 + 一筆進行中訂單**。
4. 同一商品可以同時被多筆進行中訂單保留（不同買家、不同尾數），各自保留自己的數量。
5. 提案時逐項檢查 `尾數 ≤ 可售`，不足要指出是哪個商品。
6. 取消或逾時只釋放該訂單的尾數，不影響其他訂單。
7. **議價以整單金額為準**，不支援逐項改價；逐項單價只作紀錄。
8. 訂單項目是**商品快照**：商品日後改價或售完，都不影響歷史訂單。

### 6.3 逾時

- 沒有背景排程；在讀取商品、對話清單或訂單時順便掃描（惰性掃描）。
- 逾時的進行中訂單轉 `CANCELLED`，原因記為「鎖定逾時」或「協商逾時」，在交易房留一則系統訊息。
- 重複掃描不會重複取消或重複寫入系統訊息。

**狀態**：✅ 已實作（草稿、加購、提案、同意、退回、重送、取消與逾時掃描）

## 7. 評價

- 成交後，買家與釣客各可評價對方**一次**。
- 內容：1–5 星、最多 3 個標籤、100 字內評語。
- 送出後重算對方的平均星等與評價數。
- 標籤含「臨時放鳥」時，對方的未到次數加一；累計 3 次列入黑名單。

**狀態**：✅ 已實作（評價卡、星等與未到次數重算、黑名單、商品詳情評價）

## 8. 行情

### 8.1 單位

| 用途 | 單位 |
| --- | --- |
| 入庫 | 元／公斤 |
| 顯示 | 元／台斤（× 0.6） |

同一畫面不得混用兩種單位。

### 8.2 資料

| 概念 | 說明 |
| --- | --- |
| 交易日期 | 批發市場的交易日，民國年格式需轉西元 |
| 上價／中價／下價／平均價 | 當日該魚種在該市場的最高、中位、最低、加權平均 |
| 市場 | 官方只有簡稱（岡山、新營），需人工對照到縣市 |
| 縣市 | 查詢層級 |
| 全國平均 | 同縣市無資料時的備援，必須標示「全國平均」 |
| 行情快照 | 上架當下引用並凍結，含來源、交易日期、抓取時間 |

### 8.3 查詢順序

1. 同縣市、該魚種、最近交易日 → 標示縣市
2. 無 → 該魚種的全國平均（同日）→ 標示全國平均
3. 無 → 該魚種最近一次有資料的交易日 → 標示日期
4. 仍無 → **暫無行情**，不得填 0 或示意值

### 8.4 規則

- 平均價 ≤ 0 視為無效行情，不寫入。
- 休市日沒有資料是正常情形，取最近交易日並顯示該日期。
- 批發均價是「參考底價」，不得寫成「市價」「保證售價」。
- 示意資料（魚種字典的 `market`）只能標為「參考價（測試資料）」，不得標成「今日行情」。

**狀態**：⬜ 未實作（畫面上目前顯示的是示意資料，且標成「澎湖魚市即時均價」）

## 9. 顯示與文案規則

| 規則 | 說明 |
| --- | --- |
| 單位 | 價格一律「元」，重量一律「公斤」；行情可用「元／台斤」但需標明 |
| 數字 | 每個數字都要帶單位，不得只寫「2800」 |
| 日期 | 行情一律顯示**交易日期**，不是抓取日期 |
| 來源 | 行情必須同時顯示來源（農業部漁業署） |
| 商品標題 | `{魚種}（{總重}kg / {尾數}尾 / {處理方式}）` |
| 禁用詞 | 現流、野生、頂級、職人、大豐收、極鮮、超值、尚青 |
| 助手語氣 | 繁體中文、白話、句子短；不用驚嘆號堆疊，不下評價 |
| 查無資料 | 說「暫無」「目前沒有」，不得用「大約」「應該」帶過 |

## 10. 邊界案例

| 情況 | 預期行為 |
| --- | --- |
| 使用者說一個字典裡沒有的魚 | 仍可上架，`species_id` 留空，料理資料與行情顯示暫無 |
| 同一位買家向同一位釣客買第二次 | 沿用同一間交易房，建立新的訂單草稿 |
| 兩個買家同時要買同一尾 | 各自保留；先成交者計入已售，另一筆提案時會因可售不足被拒 |
| 訂單提案後釣客 30 分鐘沒回應 | 自動取消並釋放尾數，交易房留系統訊息 |
| 退回後 15 分鐘沒重送 | 同上 |
| 商品在洽談中被釣客改價 | 進行中訂單的快照不變，不影響已送出的協議 |
| 買家在協議成立前取消 | 釋放尾數，房間保留對話紀錄 |
| 成交後一方不評價 | 評價非強制；對方信用不變 |
| 休市日查行情 | 取最近交易日，畫面顯示該日期 |
| 魚種無行情（進口鮭魚） | 「暫無行情」，不得出現任何數字 |
| 市場尚未對照到縣市 | 不參與縣市查詢，仍計入全國平均 |
| 價格異常暴漲 | 照實顯示，加註「資料異常，請確認」 |
