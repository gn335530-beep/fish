# 02 網域模型

本章定義系統裡有哪些東西、它們的關係、以及不能違反的規則。實作細節（欄位名、API）在 `04`、`05`。

---

## 1. 使用者

一個帳號同時具備買與賣的能力。

| 屬性 | 說明 |
| --- | --- |
| 手機號碼 | 帳號識別，也是登入帳號 |
| 暱稱 | 2–20 字，顯示在對話與商品 |
| 地址 | 縣市、鄉鎮市區、詳細地址；顯示時串接為 `display_address` |
| 所在地區 | 註冊時填寫縣市；作為導購、上架與行情查詢的預設地區 |
| 販賣確認 | 第一次販賣前點擊「我已了解並確認」的時間；有值就永久跳過法規告知 |
| 信用 | `rating_score`（平均星等）、`review_count`、`completed_deals`、`no_show_count`、`is_blacklisted` |

**規則**

- 任何人登入後都可以上架、購買、評價。
- 使用者是單一帳號型態，買方／釣客由交易推導（ADR-0005）；不再有 `role` 欄位。
- 銀行欄位存在但**不對外回傳**（`publicUser` 會移除），本版也沒有提領功能。
- 地址**不用於**面交地點；面交地點由雙方在協議中填寫。
- 註冊時必須填寫縣市；區與詳細地址可在個人檔案補。既有測試資料沒有縣市時，demo 以隨機縣市補值。
- 縣市比對與回應統一用「台」（例如「台北市」），容納舊資料的「臺」。
- 第一次販賣前必須先確認漁業法與證照告知；確認一次永久有效。未確認者不能進入上架流程；購買、瀏覽與諮詢不受影響。

**狀態**：✅ 已實作註冊、登入、地址、註冊縣市（#32）與販賣確認（#34）。

## 2. 魚種

系統的魚種清單目前有 28 種，作為「已知魚種」的字典。

| 屬性 | 說明 |
| --- | --- |
| 識別碼 | 例如 `grouper`、`amberjack` |
| 名稱 | 例如 玳瑁石斑、紅魽 |
| 別名 | 使用者可能說的說法，例如「石斑」「紅甘」 |
| 拉丁學名 | 顯示用 |
| 料理屬性 | 肉質、刺的粗細、適合的料理法 |
| 行情對應 | 一個主要官方代碼；是否養殖；見行情章 |

**規則**

- **魚種資料只能有一份真實來源**：放在後端，前端一律由 API 取得。
- **未知魚種可以上架。** 使用者說「鮭魚」時，即使字典裡沒有，仍可完成上架：保留使用者說的名稱、`species_id` 留空；商品照常販售，但沒有料理資料，行情顯示「暫無行情」。
- 不可以用名稱模糊比對把未知魚種硬塞進某個已知魚種。

**狀態**：✅ 已實作魚種單一來源與行情對照（28 個主要新鮮代碼、21 個市場；ticket #21）。魚種字典的示意行情不再對外回傳；商品參考價仍待 #24 改用行情快照。

## 3. 商品

一次上架的漁獲批次。

| 概念 | 說明 |
| --- | --- |
| 總重 | 整批公斤數 |
| 尾數 | 整批個體數 |
| 整批售價 | 釣客開的整批總價（元）；可能是折扣 |
| 每台斤售價 | 釣客開的每台斤價格（元）；可選 |
| 每尾均價 | 整批售價 ÷ 尾數，**衍生值** |
| 平均每尾重 | 總重 ÷ 尾數，**衍生值** |
| 處理方式 | 自由文字，最多 20 字；範例：活體、放血冰鎮 |
| 照片 | 一張實拍照片，必填 |
| 地區 | 縣市，用於篩選與導購 |
| 捕獲時間 | 什麼時候釣到的 |

### 3.1 價格有多種單位，必須標清楚

| 欄位 | 意義 | 是否落庫 |
| --- | --- | --- |
| `price` | **上架整批售價（元）**；訂單／協議使用的價格 | 是 |
| `price_per_taijin` | 上架每台斤售價（元）；可為空 | 是 |
| `price_auto` | 整批售價是否由每台斤自動計算 | 是 |
| `unit_price` | 每尾均價（元）= `price ÷ quantity` | 否，讀取時算 |
| `avg_weight_kg` | 每尾平均重量（公斤） | 否，讀取時算 |
| `market_snapshot.price_per_taijin` | 行情平均價（元／台斤） | 是（快照） |

**硬規則**：

- `price` 是整批售價，不是單價；`price_per_taijin` 是每台斤售價，不是整批價。
- 兩個都填時**不檢查一致性**；整批價可以低於「每台斤 × 台斤數」，視為折扣。
- 只填整批時，每台斤留空；只填每台斤時，發布前自動計算整批，並標「自動計算」。
- 訂單與協議一律使用整批價；成交價可以與上架售價不同。
- 畫面必須標明是哪一種價格（上架整批、每台斤、每尾均價、行情均價、成交價），不得把「元／台斤」與「整批總價」混在同一句未標示的文字裡。
- 行情快照是參考價，不是售價、也不是成交價。

### 3.2 可售尾數與狀態

```
保留       = Σ(進行中訂單中該商品的尾數)      // 進行中 = PENDING_REVIEW 或 NEGOTIATING
可售       = 總尾數 − 已售 − 保留
狀態       = 保留 > 0 → PARTIALLY_RESERVED（畫面顯示「洽談中」）
             可售 ≤ 0 → SOLD_OUT
             否則     → ACTIVE
```

- `DRAFT` 訂單**不**計入保留。
- 有保留就先算「洽談中」，即使可售已經 0（全部尾數都在談，還沒成交）。
- 狀態與可售尾數**即時計算、不落庫**（ADR 0002）。
- 全部售完且沒有保留才是 `SOLD_OUT`；部分售出且還有可售，仍是 `ACTIVE`。

### 3.3 生命週期

```
上架（ACTIVE） → 有人提案（PARTIALLY_RESERVED） → 成交（已售增加）
                     ↑                              ↓
                取消／逾時（釋放）            售完（SOLD_OUT）
```

商品沒有「下架」狀態；本版不提供刪除，商品一旦上架就留在清單上，直到售完。

**狀態**：✅ 已實作整批與每台斤售價、自動計算、行情快照；訂單／協議仍使用整批售價。

## 4. 房間（對話）

| 類型 | 參與者 | 唯一鍵 | 用途 |
| --- | --- | --- | --- |
| 助手房 | 使用者 + 助手 | 每位使用者可多間，各自有 id | 上架、導購、諮詢 |
| 交易房 | 買家 + 釣客 | **買家 + 釣客** | 訊息、訂單、協議、評價 |

**規則**

- 權限一律以「參與者清單」為準；交易房另外記錄買家與釣客是誰，但那是語意標籤，必須與參與者清單一致。
- 交易房建立後，助手不再回覆；房間進入真人對話模式。
- 不同釣客之間互不可見；釣客看不到買家在助手房裡的導購對話。
- 同一組人**永遠只有一間**交易房，即使買了多個商品、成交多次。
- 助手房可以有多間；每間有自己的 context 與草稿。收件匣可新增助手房。
- 刪除規則：助手房任何時候都能刪，刪除時移除訊息與 context；交易房必須沒有任何 `CONFIRMED` 訂單，且目前訂單為 `CANCELLED`（取消、逾時；或全部訂單皆 `CANCELLED`）時才能刪。刪除交易房會一併刪除訊息、訂單與訂單項目，交易紀錄不再顯示；有成交歷史或進行中的交易房不可刪。

**助手房的三種模式**

| 模式 | 意思 | 何時離開 |
| --- | --- | --- |
| `idle` | 沒事，每句話重新判斷意圖 | 進入 listing 或 shopping |
| `listing` | 有進行中的上架草稿，只抽欄位、不判斷意圖 | 發布或使用者取消 |
| `shopping` | 剛查過商品，記住卡片順序供指涉 | 可指涉上一批卡片，或重新判斷 |

**狀態**：✅ 已實作多間助手房（各自 context）與前述刪除規則（#30、#31）。

## 5. 訊息

| 型別 | 內容 |
| --- | --- |
| `text` | 純文字，上限 500 字 |
| `image` | 一張圖片網址 |
| `system` | 系統通知（例：協議逾時已釋放） |
| `card` | 結構化卡片，見下 |

**卡片種類**

| 卡片 | 內容 | 可執行動作 |
| --- | --- | --- |
| 商品卡 | 圖、標題、整批價、每台斤售價（可選）、每尾均價、行情快照、可售尾數、地區 | 深入諮詢、洽談購買 |
| 法規告知卡 | 漁業法與證照提醒、罰則、法規連結 | 我已了解並確認、取消 |
| 草稿卡 | 魚種、重量、尾數、處理方式、照片、售價（每台斤／整批／自動計算） | 確認發布、修改草稿、取消上架 |
| 取消上架確認卡 | 確認取消上架並刪除目前對話 | 確定取消、繼續上架 |
| 行情卡 | 平均價、當地縣市近 7／30 個交易日走勢、期間最高／最低、縣市或全國平均、交易日期、來源、養殖價格、參考整批金額、新鮮批發參考 | 7／30 走勢切換；使用者直接回覆售價 |
| 訂單卡 | 多品項、小計 | 展開明細、（未來）送出協議 |
| 協議卡 | 整單金額、地點、時間、狀態 | 同意、退回、取消 |
| 評價卡 | 星等、標籤、評語 | 送出 |

**規則**

- 每則訊息有單調遞增序號，輪詢以序號取增量，不用時間戳（同毫秒會漏訊息）。
- 只有房間參與者能寫入訊息；`sender_type`（自己／助手／系統）只是標記，不是權限依據。
- 助手房以外的房間不得寫入 AI 狀態（`context`）。
- 卡片狀態存在訊息裡，訂單狀態改變時要同步更新，重新載入才不會顯示舊狀態。
- 系統訊息不計入未讀數。
- **訂單摘要不是訊息卡**：`DRAFT`／進行中訂單固定顯示在交易房上方，協議卡才是訊息。

**狀態**：✅ 已實作文字、圖片、商品卡、草稿卡、行情卡、法規告知卡、取消上架確認卡與協議卡。

## 6. 訂單

一組釣客與買家之間的一筆交易，可含同一位釣客的多個商品。

### 6.1 狀態機

```
[加入商品] → DRAFT ──提案──→ PENDING_REVIEW ──同意──→ CONFIRMED
               ↑                  │  ↑
               │               退回│  │重送（修改條件）
               │                  ↓  │
               └────────────── NEGOTIATING
                                  │
                         取消／逾時 → CANCELLED
```

| 狀態 | 庫存影響 | 可做的事 | 期限 |
| --- | --- | --- | --- |
| `DRAFT` | 不保留 | 加商品、改尾數、刪商品、清空、提案 | 無 |
| `PENDING_REVIEW` | 保留所有項目 | 接收方同意／退回；任一方取消 | 30 分鐘 |
| `NEGOTIATING` | 保留所有項目 | 退回方修改後重送；任一方取消 | 額外 15 分鐘 |
| `CONFIRMED` | 計入已售 | 雙方評價 | — |
| `CANCELLED` | 釋放所有項目 | 唯讀 | — |

### 6.2 不能違反的規則

1. **發起方送出提案即視為自己已簽**；接收方同意即成交。
2. 成交就是「交易完成」，同時寫入交易紀錄。
3. 一個交易房同時最多**一筆草稿 + 一筆進行中訂單**。
4. 同一商品可以同時被多筆進行中訂單保留（不同買家、不同尾數），各自保留自己的數量。
5. 提案時逐項檢查 `尾數 ≤ 可售`，不足要指出是哪個商品。
6. 取消或逾時只釋放該訂單的尾數，不影響其他訂單。
7. **議價以整單金額為準**，不支援逐項改價；逐項單價只作紀錄。
8. 訂單項目是**商品快照**：商品日後改價或售完，都不影響歷史訂單。
9. **交易房刪除**：只有當房內沒有任何 `CONFIRMED` 訂單，且目前訂單為 `CANCELLED`（或全部訂單皆 `CANCELLED`）時，才能連同交易房刪除；刪除時對話、訊息、訂單與項目一起移除，交易紀錄不再顯示。有成交歷史或進行中的訂單不可刪。

### 6.3 逾時

- 沒有背景排程；在讀取商品、對話清單或訂單時順便掃描（惰性掃描）。
- 逾時的進行中訂單轉 `CANCELLED`，原因記為「鎖定逾時」或「協商逾時」，在交易房留一則系統訊息。
- 重複掃描不會重複取消或重複寫入系統訊息。

**狀態**：🟡 已實作草稿、加購、提案、同意、退回、重送、取消與逾時掃描；取消後刪除交易房已於 #31 實作。

## 7. 評價

- 成交後，買家與釣客各可評價對方**一次**。
- 內容：1–5 星、最多 3 個標籤、100 字內評語。
- 送出後重算對方的平均星等與評價數。
- 標籤含「臨時放鳥」時，對方的未到次數加一；累計 3 次列入黑名單。

**狀態**：✅ 已實作（評價卡、星等與未到次數重算、黑名單、商品詳情評價）

## 8. 行情

### 8.1 單位

| 用途 | 單位 |
| --- | --- |
| 入庫 | 元／公斤 |
| 行情顯示 | 元／台斤（× 0.6） |
| 上架售價 | 元（整批）或 元／台斤 |

同一筆價格不得混用兩種單位；行情均價與試算總額可以並列，但必須各自標明「元／台斤」「元」。

### 8.2 資料

| 概念 | 說明 |
| --- | --- |
| 交易日期 | 批發市場的交易日，民國年格式需轉西元 |
| 平均價 | 當日該魚種在該市場以交易量加權的平均價；本版只使用平均價 |
| 交易量 | 該市場該日的交易公斤數，用於縣市與全國加權 |
| 市場 | 官方只有簡稱（岡山、新營），已人工對照 21 個市場；未確認縣市者不參與縣市加權 |
| 縣市 | 查詢層級 |
| 全國平均 | 同縣市無資料時的備援，必須標示「全國平均」 |
| 養殖價格 | 行情來源為養殖代碼時的標記 |
| 行情快照 | 上架當下引用並凍結，含平均價、來源、交易日期、抓取時間與是否養殖 |

### 8.3 查詢順序

1. 取該魚種最近有資料的交易日（以該魚種的全國資料判斷；若指定日期，取該日或之前最近交易日）。
2. 該日同縣市有已對照市場 → 以交易量加權平均 → `scope = city`。
3. 無 → 該日全國所有市場加權平均 → `scope = national`，標示「全國平均」。
4. 仍無 → **暫無行情**，不得填 0 或示意值。

縣市平均只納入已對照到該縣市的市場；全國平均納入所有市場，包含尚未對照縣市的市場。

### 8.4 規則

- 平均價 ≤ 0、交易量 ≤ 0、`魚貨名稱 = 休市` 的資料不寫入、不計入平均。
- 休市日沒有資料是正常情形，取最近交易日並顯示該日期。
- 批發均價是「參考底價」，不得寫成「市價」「保證售價」。
- 行情來源為養殖代碼時，畫面與助手回覆必須標示「養殖價格」。
- 行情只抓新鮮資料：排除凍結（`3xxx`）與加工（`6xxx`）；`1xxx` 只允許海鱸、虱目魚、鰻魚；蝦貝類（`4xxx`／`5xxx`）照抓，名稱有「養」者標養殖。
- 每個系統魚種只對一個主要官方代碼，不混養殖與非養殖。
- 沒有每日全量 job；查詢時按需抓單一魚種並快取。最新交易日快取 30 分鐘，過去日期視為不變；查無資料也做短期 negative cache。
- 上游失敗時，有快取就回快取；沒有就回 `found:false`、`reason:"UPSTREAM_UNAVAILABLE"`，不得用舊資料冒充當日行情。
- 示意資料不得再作為行情來源；畫面不得出現「今日行情」「即時均價」等與資料不符的字樣。
- 商品發布時寫入行情快照；快照一旦寫入，行情更新或商品改價都不影響它。

### 8.5 上架行情卡

上架的非價格欄位齊了之後，助手查該魚種在釣客縣市的行情，顯示一張小卡：

- 最新平均價（元／台斤）、當地縣市近 7 或 30 個交易日的走勢、期間最高／最低。
- 縣市或全國平均、交易日期、來源、養殖價格（若）。
- 依重量試算的參考整批金額：`平均價 × (weight_kg ÷ 0.6)`；標示「參考」。

## 9. 顯示與文案規則

| 規則 | 說明 |
| --- | --- |
| 單位 | 價格一律「元」，重量一律「公斤」；行情用「元／台斤」 |
| 價格標籤 | 每種價格都要標明是哪一種：上架整批、上架每台斤、每尾均價、行情均價、成交價 |
| 數字 | 每個數字都要帶單位，不得只寫「2800」 |
| 日期 | 行情一律顯示**交易日期**，不是抓取日期 |
| 來源 | 行情必須同時顯示來源（農業部漁產品交易行情） |

| 助手語氣 | 繁體中文、白話、句子短；不用驚嘆號堆疊，不下評價 |
