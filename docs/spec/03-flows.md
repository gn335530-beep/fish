# 03 使用流程

每條流程都標記狀態。**現況段落描述程式現在真的會做的事**；未實作段落是目標行為。

---

## F1 註冊與登入 ✅

**觸發**：使用者開啟任一頁面，或點導覽列的登入。

**流程**

1. 未登入時，助手面板只顯示登入引導，不建立房間。
2. 登入頁以手機號碼 + 密碼登入，或用手機、密碼、暱稱註冊。
3. 成功後存下 Token 與會員資料，導回原頁面。
4. 任一頁載入時，若有 Token 就向後端確認身分；失敗就登出並回到未登入狀態。
5. 登入後若沒有任何助手房，自動建立一間並載入歷史訊息；已有助手房則開啟最近一間。

**規則**

- 註冊時角色預設 `BUYER`，但角色不影響任何操作。
- 未登入可以瀏覽商品，但**不能開助手房**（與舊計畫書的「未登入可導購」不同，以現況為準）。
- Token 只存在伺服器記憶體，後端重啟後所有人需重新登入。
- 登出會清除本機 Token、會員資料與助手記憶體狀態；重新載入任一頁都維持未登入。

**失敗**：電話重複註冊回 409；密碼錯誤回 401，畫面顯示錯誤訊息。

**目標變更（#30、#31、#32、#34，已完成）**

- 註冊表單新增縣市（必填）；API 驗證並把「臺」正規化為「台」。既有測試資料沒有縣市時，demo 隨機補一個縣市。
- 登入後若沒有任何助手房，建立一間；否則開啟最近一間。收件匣可新增多間助手房，每間有自己的 context 與草稿。
- 登入／註冊頁左側（釣客／買家文案下方）顯示法規告知與「漁業法」連結；兩個 tab 都顯示。
- 左側文案修正：「現流」→「當日漁獲」、「澎湖魚市」→「官方行情」、「下單」→「洽談後成立訂單」；並刪除「隔日清晨低溫直送」。

## F2 對話式上架 ✅

**現況**：處理方式自由文字（#26）、批次追問（#28）、每台斤／整批售價（#27）、行情卡／售價引導（#29）、修改草稿與取消上架（#33）與販賣法規確認（#34）均已完成。

**觸發**：使用者說「我要賣魚」「剛釣到石斑」「出售」等。

**流程**

1. 意圖判斷為「賣」→ 助手房進入上架模式，建立空草稿。
2. 一次抽出句子裡所有能辨識的欄位，缺什麼問什麼，**一次只問一個**。
3. 追問順序：魚種 → 總重 → 尾數 → 處理方式 → 照片 → 整批售價。
4. 照片只能由上傳事件填入，不從文字推測。
5. 六個欄位齊了就出草稿卡（魚種、總重、尾數、處理、售價、照片縮圖）。
6. 草稿卡可按「修改」逐欄重問；只更新該欄位，取消則回到修改前草稿。
7. 使用者按「確認發布」→ 建立商品 → 回覆「已上架：{標題}」。
8. 發布後清空對話，只留下「已上架」那一則，草稿狀態歸零。

**欄位規則**

| 欄位 | 規則 |
| --- | --- |
| 魚種 | 比對名稱與別名；**比對不到就保留原字串**、`species_id` 留空 |
| 總重 | `數字 + 公斤/kg/台斤/斤`；台斤 × 0.6；只回一個數字時視為公斤；無單位小數視為公斤，有尾數時 20 公斤以內的小整數也視為公斤 |
| 尾數 | `數字 + 尾/條/隻/份` |
| 處理方式 | 同義詞對照：活魚／蓄養→活體；放血／碎冰→放血冰鎮；三去／宰殺→三去處理；凍→冷凍 |
| 照片 | 上傳後壓縮（長邊 1280、JPEG 0.75）再送後端 |
| 售價 | 整批總價，必須 > 0 |

**規則**

- 上架地點預設帶入個人檔案的縣市與地址（後端會補）。
- 商品標題由後端產生：`{魚種}（{總重}kg / {尾數}尾 / {處理}）`。
- 使用者說「算了」「不要了」→ 清空草稿、回到閒置。
- 同一句話可以一次補完多個欄位（例：「石斑 4.5 公斤 1 尾 放血冰鎮 2800」）。
- 既有處理方式為「冷凍」的商品與其上架訊息，啟動時改成「放血冰鎮」並重算標題；已成交訂單中的商品快照不變。

**目標變更（#26–#29、#33、#34，已完成）**

0. 若使用者尚未完成販賣確認（`seller_terms_accepted_at` 為空），先顯示法規告知卡；確認後清除先前對話紀錄，只留下「請問想要販售什麼魚類？」；取消則回 idle。確認一次永久跳過。
1. 意圖判斷為「賣」→ 進入上架模式，建立空草稿。
2. 魚種還沒確定時只問魚種；使用者回完魚種後，助手一次問「請問你要販售魚種的重量、處理方式，與一張商品照片（可以一次告訴我）」，**不問價格**，也不再用「還需要」開頭。尾數若仍缺，之後再補問。
3. 使用者可以一次輸入多個欄位；若仍缺，重量、處理方式與照片一起再問，只缺尾數時再單獨問尾數。處理方式為自由文字，助手照使用者說法記錄，不做固定同義詞對照。
4. 非價格欄位齊了 → 查該魚種在釣客縣市的行情，送出一張行情卡：
   - 平均價（元／台斤）、當地縣市近 7 或 30 個交易日的走勢、期間最高／最低。
   - 縣市或全國平均、交易日期、來源、養殖價格（若）。
   - 依重量試算的參考整批金額：`平均價 × (weight_kg ÷ 0.6)`，標「參考」。
5. 若尚未提供售價，助手接著問：「請問要販賣多少錢？（可回覆每台斤價格或整批價格）」；若使用者已提供售價，直接顯示草稿卡／確認發布，不重問。
6. 售價規則：
   - 只填整批 → 每台斤留空。
   - 只填每台斤 → 發布前自動計算整批，標「自動計算」。
   - 兩者都填 → 都保留，不檢查一致性；整批可低於每台斤 × 台斤數，視為折扣。
7. 草稿卡顯示魚種、重量、尾數、處理方式、照片、上架售價（每台斤／整批／自動計算）。
8. 「修改草稿」→ 助手問「請問要修改哪個選項？」→ 選項：魚種、重量、尾數、處理方式、照片、售價（每台斤／整批）；使用者可用選項或打字 → 助手問新值 → 更新該欄位；中途取消則回到修改前草稿。
9. 「取消上架」→ 助手問「確定取消上架？此對話會一併刪除」→ 確認後取消草稿並刪除目前這間 AI 對話。
10. 「確認發布」→ 後端再查行情並寫入快照 → 建立商品 → 回覆「已上架：{標題}」。

**目標欄位規則**

| 欄位 | 規則 |
| --- | --- |
| 魚種 | 比對名稱與別名；比對不到保留原字串、`species_id` 留空 |
| 總重 | 同現況 |
| 尾數 | 同現況 |
| 處理方式 | 自由文字，最多 20 字；提示詞只舉例「活體、放血冰鎮」，不列「冷凍」「三去處理」；釣客自己打「冷凍」仍可成立 |
| 照片 | 同現況 |
| 售價 | 每台斤或整批（可擇一或都填）；每台斤 → 自動算整批並標「自動計算」；兩者都填不檢查一致性 |

## F3 導購與找魚 🟡

**觸發**：使用者說「今天有什麼魚」「有沒有石斑」「新北市有什麼」「適合長輩煮湯」等。

**流程**

1. 意圖判斷為「買」→ 進入導購。
2. 從句子抽出：魚種、縣市、料理情境（清蒸／煮湯…／刺少／長輩）。
3. 抓可售尾數 > 0 的商品（上限 100 筆），依條件過濾。
4. 最多回 5 張商品卡，先說「找到 N 筆商品」。
5. 記住這批卡片的順序，供下一句指涉。
6. 使用者說「第 2 個」「這尾」「最後一個」時，對到卡片並接續該商品的諮詢；選取結果寫入 context。

**規則**

- 只推薦**還有可售尾數**的商品。
- 沒指定地區時，一律用個人檔案的縣市，並在回覆中說明「依你的地區」；句子明確提到其他縣市才改變範圍。
- 個人檔案沒有縣市時改為全省查詢，並在回覆中說明目前採用全省。
- 料理情境的判斷依據是魚種字典的「刺的粗細」與「適合料理」。
- 查無結果時回「目前沒有符合條件的商品，可以換個魚種或地區」，並說明目前查的是哪個地區；不編造商品。

**已知缺口**

- 行情意圖已於 #25 實作；助手會依魚種與地區查詢行情並回平均價、日期與來源。

## F4 商品諮詢 ✅

**觸發**：使用者在商品卡按「深入諮詢」。

**流程**

1. 取得商品詳情。
2. 回覆兩段：①魚種的肉質、刺、適合料理；②這批的重量、尾數、整批價、可售尾數與保存建議。
3. 若魚種不在字典裡，只回「目前沒有這魚種的料理資料」加上商品資訊。

**規則**：回覆只能引用商品與魚種字典的資料，不得自行評價「很新鮮」「超值」。

## F5 洽談購買與交易房 ✅

**觸發**：使用者在商品卡按「洽談購買」（或在對話中說「我要 2 尾石斑」，後者尚未實作）。

**流程**

1. 檢查登入；未登入先導去登入頁。
2. 由商品的釣客找出（或建立）「買家 + 釣客」的交易房。
3. 房間進入真人模式，插入系統訊息「已進入交易洽談」。
4. 找出或建立該房的一筆訂單草稿，把商品與尾數加進去。
5. 面板切換為交易房視圖：電話橫幅、訂單摘要、訊息流、輸入框。

**規則**

- 電話在交易房建立後直接顯示完整號碼，附 `tel:` 連結，不做遮蔽。
- 同一釣客的多個商品進同一間房、同一筆訂單。
- 不同釣客 → 另一間房、另一筆訂單。
- 交易房裡的訊息**不會**觸發助手回覆。
- 已有一筆草稿時再加購 → 直接加進該草稿。
- 訂單已送出提案 → 加購停用，需先取消或等對方回應。
- 已成交 → 建立新的草稿訂單，同一間房。

**現況**：2026-10-25 已完成開房與加購。`POST /api/deals/initiate-channel` 建立或沿用交易房與 `DRAFT` 訂單；商品卡與詳情頁都能選 1 到可售尾數。交易房的系統訊息計入未讀，對方輪詢時會看到紅點與新訊息。

## F6 訂單草稿與加購 ✅

**目標流程**

1. 交易房上方顯示訂單摘要：`N 項 · M 尾 · NT$X`，可展開。
2. 展開後可改尾數、刪除項目、清空。
3. 「＋ 加購」列出該釣客其他可售商品，選尾數後加入同一訂單。
4. 尾數只能 1 到可售尾數。
5. 草稿不保留庫存；同一筆草稿的累計尾數不得超過目前可售，送出提案時再依當下可售檢查一次。

**規則**

- 草稿可以為空（全部刪光），不自動取消。
- 沒有項目時「協商完畢」不可按。
- 小計 = Σ(每尾均價 × 尾數)；整單金額預設等於小計，可議價。

**現況**：2026-10-25 已完成。訂單摘要可展開；買家可加購同一釣客其他可售商品、用加減鈕改尾數、刪除單項或清空訂單。釣客看到的是唯讀明細。

## F7 協議與簽核 ✅

**觸發**：買家（或釣客）按「協商完畢」，填整單金額、面交地點、面交時間。

**流程**

1. 驗證：參與者、至少一個項目、逐項尾數 ≤ 可售。
2. 草稿 → 待回覆，鎖定 30 分鐘。
3. 發起方自動視為已簽，交易房插入協議卡。
4. 對方按「同意」→ 成交：各項目計入已售、雙方完成數 +1、插入評價卡。
5. 對方按「退回」→ 協商中，保留 15 分鐘，退回方修改條件後重送。
6. 任一方可取消，需選原因（釣客缺貨、買家改變心意、條件不合、其他）。

**規則**

- 只能改整單金額，不能逐項改價。
- 可售不足時回 409 並指出是哪個商品。
- 協議卡狀態要跟著訂單狀態更新（待回覆／已退回／已成交／已取消／已逾時）。

**現況**：2026-10-25 已完成同意、退回、重送與取消。同意即成交並更新已售與完成數；退回方可以改條件重送；取消必須選原因並立即釋放保留。評價卡尚未實作（ticket 19）。

## F8 逾時釋放 ✅

**觸發**：讀取商品清單、商品詳情、對話清單或訂單明細。

**流程**

1. 掃描所有進行中訂單。
2. 待回覆且鎖定過期 → 取消，原因「鎖定逾時」。
3. 協商中且保留過期 → 取消，原因「協商逾時」。
4. 同步協議卡狀態、插入系統訊息、釋放尾數。
5. 商品狀態自動重算。

**現況**：`GET /api/products`、`GET /api/products/:id`、`GET /api/conversations` 與 `GET /api/deals/:id` 都會先掃描；重複掃描不會重複取消或重複留言。

## F9 評價與交易紀錄 ✅

**流程**

1. 成交後，雙方在交易房看到評價卡。
2. 選 1–5 星、最多 3 個標籤、100 字內評語，送出。
3. 每人每筆訂單限評一次；重複送出回 409。
4. 送出後重算對方平均星等與評價數；含「臨時放鳥」標籤時未到次數 +1，累計 3 次列入黑名單。
5. 個人抽屜的「交易紀錄」列出所有訂單：多品項、成交金額、商品快照、評價狀態。

**現況**：2026-10-25 已完成。評價卡只顯示在已成交的訂單；個人抽屜的「交易紀錄」可看列表與單筆快照、面交資訊；商品詳情頁讀 `GET /api/reviews` 顯示釣客的真實評價。

## F10 行情查詢與上架引用 🟡

**現況**：按需抓取、30 分鐘快取、21 市場對照、查詢 API、商品行情快照與助手行情問答已完成（#21～#25）；上架行情卡仍待 #29。

**目標流程**

1. 查詢時按需抓取單一魚種（新鮮代碼、最近交易日或指定日期），正規化後 upsert；沒有每日全量 job。
2. 上架的非價格欄位齊了 → 查行情 → 行情卡（平均價、走勢、縣市／全國、日期、來源、養殖、參考整批）→ 問售價。
3. 商品發布 → 後端再查一次並寫入行情快照（平均價、日期、來源、抓取時間、養殖）。
4. 商品卡與詳情頁顯示快照：平均價、縣市或全國平均、交易日期、來源、養殖價格；不顯示上價／中價／下價。
5. 使用者問「石斑現在多少錢」→ 助手查詢後回答平均價、縣市或全國、日期、來源、養殖；數字只能來自查詢結果。
6. 查無資料 → 「目前沒有今天的行情」或「暫無行情」；上游失敗 → 「暫時無法取得行情」。

**規則**

- 行情是批發平均價，不是售價；上架售價與成交價是另外兩個價格。
- 快照一旦寫入，商品改價不影響快照。
- 抓取失敗不得覆蓋既有資料；有快取就回快取，沒有就回 `found:false`／`UPSTREAM_UNAVAILABLE`。
- 行情只抓新鮮資料：排除 `3xxx`／`6xxx`；`1xxx` 只允許海鱸、虱目魚、鰻魚；`4xxx`／`5xxx` 照抓，名稱有「養」者標養殖。
- 查詢 API 支援 `include=history&days=7|30`，供行情卡走勢；商品快照不存歷史。

## F11 收件匣、未讀與輪詢 🟡

**流程**

1. 面板開啟時載入對話清單與當前房間訊息。
2. 每 3 秒輪詢增量訊息；分頁切到背景時暫停。
3. 收到新訊息 → 更新未讀數，顯示在右下角按鈕上。
4. 點收件匣 → 列出進行中與歷史房間，顯示對方、最後訊息、未讀、訂單摘要。
5. 進入房間即標記已讀。
