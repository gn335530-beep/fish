# 06 介面規格

本章描述實際畫面：頁面、助手面板、交易房、卡片、顯示規則與空狀態。資料與 API 見 `04`、`05`。

## 1. 頁面

| 頁面 | 用途 | 狀態 |
| --- | --- | --- |
| `pages/index.html` | 首頁、今日漁獲、助手功能範例 | ✅ |
| `pages/products.html` | 漁獲列表與篩選 | ✅ |
| `pages/login.html` | 登入與註冊 | ✅ |
| `pages/profile.html` | 公開個人資訊（他人與自己）；商品區與角色評價已接上 | 🟡 |
| `pages/settings.html` | 個人設定：頭像、暱稱、電話、地址 | ✅ |
| `pages/cart.html` | 已移除；交易改走交易房 | 已移除 |
| `pages/seller.html` | 已移除；上架改走助手房 | 已移除 |
| `pages/product-detail.html` | 已移除；商品卡直接顯示完整資訊 | 已移除 |
| `pages/report.html` | 已移除；舊驗證報告 | 已移除 |

**導覽列**：所有頁面共用，包含首頁、漁獲、登入與個人抽屜。登入後「我的」選單順序為：個人資訊（自己的公開頁）、設定、交易紀錄、上架紀錄、登出。

**商品詳情頁已刪除**：全站不再有 `product-detail.html` 連結或「查看詳情」按鈕。`GET /api/products/:id` 仍保留供對話與內部使用，但沒有對應頁面。商品詳情頁上的釣客評價與今日其他漁獲一併移除；評價改放在個人資訊頁、交易紀錄與評價卡。

### 1.1 個人資訊頁（🟡 商品區與角色評價）

- 標題列：頭像、名字、角色評分 chips、地區、成交數、驗證標章；右側動作。
- 自己的頁面：動作「編輯個人資訊」→ 設定頁；別人的頁面：動作「聊聊」。
- 評分 chips 只顯示有評價的角色，順序固定為「買家給的評價」在前、「釣客給的評價」在後；只有一種就顯示一個，沒有就「尚無評價」。
- 商品區：別人的頁面只顯示可購買商品；自己的頁面顯示全部商品（上架中／洽談中／已售出／已下架）。
- 商品卡沿用第 2 節直式卡；個人資訊頁隱藏「釣客資訊」。
- 自己的頁面不顯示「洽談購買」；正常模式顯示狀態徽章，管理模式顯示管理動作。
- 商品區標題列有「管理商品」／「完成」切換；管理模式動作見第 2.1 節。
- 評價區：角色 tabs（需要時）、平均分＋星等＋總數、5→1 分布、排序、星等篩選、評價卡、載入更多；詳細見第 11.2 節。
- 桌面商品 4 欄、評價 3 欄；手機 1 欄。商品多時換行，不做橫向捲動。
- 空狀態：別人「目前沒有上架商品」、自己「你還沒有上架商品」、評價「尚無評價」、找不到使用者「找不到這個使用者」。

### 1.2 設定頁（✅）

- 需登入；未登入導到登入頁。
- 表單：頭像（上傳／移除）、暱稱、電話、縣市、鄉鎮市區、詳細地址、儲存變更。
- 頭像上傳沿用商品照片的上傳端點；沒有頭像顯示名字首字。
- 暱稱 2–20 字；電話 `09xxxxxxxx`、全站唯一；縣市必填；區與地址選填。
- 電話修改不要求目前密碼、不強制重新登入；成功後更新本機會員資料與導覽列。
- 銀行欄位不做。
- 錯誤顯示在對應欄位；儲存中停用按鈕；成功 toast「已儲存設定」。
- 頁面可提供「回到我的個人資訊」連結。

## 2. 商品卡面（首頁、今日漁獲）

首頁的今日漁獲與 `products.html` 的漁獲列表共用同一種直式大卡。

- 外觀：米色底（`#EFEBE3`）、圓角與柔和陰影，取消卡片最外層框線；照片框也取消框線，以圓角與淡陰影呈現。圖片在上，`aspect-ratio: 3/2`、`object-fit: contain`（完整顯示不裁切），留白以同一張照片模糊填滿；內容在下。
- 版面：商品區內容最大寬度 `1280px`，卡片最大寬度 `430px`，卡片間距 `20px`（手機 `18px`）。
- 內容順序：
  1. 魚種（大字，`fish_species`）
  2. 處理方式橢圓徽章（與卡面同色的底、1px 深墨框；與魚種同一列，標「處理方式」＋`condition`）
  3. `共 N 尾`（商品 `quantity`）
  4. `每台斤售價：NT$X`（`price_per_taijin` 有值才顯示）
  5. `整批售價：NT$X`（`price`）
  6. 地區＋地點（`region`＋`location`；缺漏顯示「地區未提供」）
  7. 按鈕列：`釣客資訊`、`洽談購買` 等寬並排；`釣客資訊` 為白底（`var(--surface)`）＋暖灰細框，`洽談購買` 為深海藍綠底（`var(--accent)`），`洽談購買` 為主要按鈕
- 處理方式文字較長時縮小字級；超過 6 字改用膠囊形狀，避免文字超出框線。
- 移除：重量、每尾均價、釣獲／上架日期、`查看詳情`、數量下拉、`自動計算` 標記。
- 可售狀態：
  - `available > 0`：顯示 `釣客資訊` 與 `洽談購買`。
  - `available <= 0` 且 `reserved_quantity > 0`：保留 `釣客資訊`，`洽談購買` 換成「洽談中，暫無法購買」。
  - `available <= 0` 且沒有保留：保留 `釣客資訊`，`洽談購買` 換成「已售出」。
  - `status = DELISTED`（舊卡片或單筆資料）：優先顯示「已下架」；公開列表不會出現此狀態。
- `洽談購買` 以 `data-deal-product` 啟動交易，預設數量 1；數量在發送交易面板調整。
- `釣客資訊` 是連到個人資訊的連結（帶 `seller_id`），不是沒有行為的按鈕；在個人資訊頁不顯示。
- 個人資訊頁的商品卡隱藏 `釣客資訊`；別人的頁面可顯示 `洽談購買`；自己的頁面不顯示 `洽談購買`。
- 用語：骨架的「每斤售價」一律寫成「每台斤售價」；「共 N 尾」使用「尾」。

### 2.1 個人資訊頁的商品管理（✅）

- 自己的頁面顯示全部未刪除商品與狀態徽章；別人的頁面只顯示可購買商品。
- 自己的頁面正常模式：商品卡只有狀態徽章，沒有購買或管理按鈕。
- 按「管理商品」→ 管理模式；標題列按鈕變「完成」。
- 管理模式動作：
  - 上架中／洽談中：下架。
  - 已下架：重新上架、刪除（沒有未售尾數時只有刪除）。
  - 已售出：刪除。
- 下架／刪除確認文案沿用 4.3 上架紀錄；重新上架不跳確認。
- 操作後卡片留在原位，更新狀態徽章；下架後自己的頁面仍看得到，別人的頁面立即消失。
- 不做 tabs；狀態徽章取代上架紀錄的三個 tabs。

## 3. 助手面板外殼

### 3.1 尺寸

| 視窗 | 面板 |
| --- | --- |
| 桌機 | 寬 `clamp(320px, calc((100vw - 64px) / 3), 400px)`，高 `min(520px, calc(100vh - 120px))` |
| ≤ 760px | 全螢幕 |

助手房與交易房使用相同尺寸；不再有 `fm-panel--wide` 或 440×760 的寬版交易房。

### 3.2 標題列

| 視圖 | 內容 |
| --- | --- |
| 助手房 | 頭像、`AI 聊天小幫手`、`☰`、`─`、`✕` |
| 交易房 | 頭像、對方名稱（連個人資訊）、名稱下方五顆角色評價星星、`撥打電話`＋電話號碼、`☰`、`─`、`✕` |
| 收件匣 | 沿用助手房標題 |

- 面板採圓角外框，沿用原本的紙張、白底與深海藍綠配色，不加墨線框；標題列與頁尾圖示使用線條圖示。
- 移除 `v7` 版本標記與狀態副標。
- 交易房標題列依目前交易角色顯示對方評價：買家看到對方的釣客評價（買家給的評價），釣客看到對方的買家評價（釣客給的評價）；純聊天房顯示整體評價。
- 對方評價星星依 `peer.rating_score` 顯示 5 顆，半星以 0.5 為單位。
- `review_count` 為 0 或 `rating_score` 為 0 時顯示空心星＋`尚無評價`；角色評價 0 則時不退回整體平均。
- 星星不可點；`aria-label` 為「評價 X 分，Y 則」。
- 電話使用 `tel:` 連結，文字「撥打電話」＋號碼；沒有電話時顯示「電話未提供」，不可點。純聊天房也顯示電話。

### 3.3 訊息區與頁尾

- 訊息區背景為 `paper-2`（`#EFEBE3` 米色）；標題列、頁尾、卡片、按鈕仍可使用品牌色。
- 頁尾由左至右：語音輸入、相機、文字輸入框、送出圖示。
- 送出是圖示按鈕，`aria-label="送出"`；不再顯示「送出」文字。
- 文字輸入上限 500 字。
- 語音輸入使用 `window.SpeechRecognition || window.webkitSpeechRecognition`，語言 `zh-TW`，單次辨識，結果附加到輸入框。
- 按下語音時按鈕顯示錄音中狀態（`aria-pressed`）。
- 不支援或權限被拒時顯示提示，不送出空訊息。

## 4. 三種視圖

| 視圖 | 內容 |
| --- | --- |
| 助手房 | 訊息流＋輸入框；上架、導購、諮詢 |
| 收件匣 | 房間清單（對方、最後訊息、未讀、訂單摘要）＋新增 AI 對話＋刪除 |
| 交易房 | 浮動購物車（有商品時）、訊息流、輸入框；對方資訊在標題列 |

**收件匣**：頂部有「新增 AI 對話」；每張 AI 對話卡片右上角有 X，點擊先問「確定刪除助手房？」。交易房只有在沒有 `CONFIRMED` 歷史、且目前訂單 `CANCELLED` 時顯示 X，點擊先問「確定刪除交易房？」；沒有任何訂單的純聊天房可隨時顯示 X，點擊先問「確定刪除對話？」。刪除交易房會一併移除訂單與項目，交易紀錄不再顯示。刪到最後一間助手房時顯示「目前沒有 AI 對話」與「新增 AI 對話」，不自動補一間。

**交易房**：不再有電話橫幅、可展開的訂單摘要或狀態說明文字。對方名稱、角色評價星星與電話只在標題列；訂單內容只在浮動購物車與協議卡。對方沒有商品時不顯示浮動購物車，只顯示訊息流與輸入框。

### 4.1 未登入

- 面板可以開，但只顯示登入引導，不能送出訊息。
- 未登入不能導購，因為助手房需要登入才能建立。
- 個人抽屜未登入時顯示「請先登入」與登入連結。

### 4.2 個人抽屜

| 視圖 | 內容 |
| --- | --- |
| 交易紀錄 | 所有訂單的狀態、時間、對方、品項數、金額與評價狀態 |
| 訂單詳情 | 多品項快照（照片、品名、尾數、單價）、面交資訊、評價狀態 |
| 上架紀錄 | 上架中／已下架／已售出三個 tabs；商品列與下架、重新上架、刪除動作 |

- 抽屜不再提供個人資訊編輯；抽屜只保留交易紀錄與上架紀錄。個人資訊與設定是獨立頁面。
- 導覽列的「我的」順序為：個人資訊（自己的公開頁）、設定、交易紀錄、上架紀錄、登出。
- 列表依建立時間由新到舊；沒有訂單時顯示「目前沒有交易紀錄。」
- 已取消交易房若被刪除，交易紀錄不再顯示該筆。
- 未登入時顯示登入引導。

### 4.3 上架紀錄

- 標題「上架紀錄」；左上角「← 我的」返回抽屜入口。
- 三個 tabs：上架中、已下架、已售出；預設上架中；每個 tab 顯示商品數量。
- 載入中顯示「載入中…」；載入失敗顯示錯誤與「重新載入」按鈕。
- 空狀態：上架中「目前沒有上架中的商品。」、已下架「目前沒有已下架的商品。」、已售出「目前沒有已售出的商品。」
- 每列顯示：縮圖、魚種＋處理方式、狀態徽章（上架中／洽談中／已售出／已下架）、`共 N 尾 · 已售 M 尾`（`保留 R 尾` 只在 R > 0 時顯示）、`整批 NT$X`、`NT$Y／台斤`（有 `price_per_taijin` 時）、`上架：MM/DD HH:mm`、`下架：MM/DD HH:mm`（只在已下架時顯示）。
- 動作依 tab：
  - 上架中（`ACTIVE`／`PARTIALLY_RESERVED`）：下架。
  - 已下架（`DELISTED`）：有未售尾數時顯示重新上架，另有刪除；沒有未售尾數只顯示刪除。
  - 已售出（`SOLD_OUT`）：刪除。
- 下架與刪除點擊後使用 `window.confirm` 確認一次：
  - 下架：「確定下架？下架後買家將看不到此商品。等待確認的訂單仍會繼續；洽談中的訂單會自動取消。」
  - 刪除：「確定刪除？刪除後商品與上架紀錄將永久消失，已成交訂單仍保留。等待確認的訂單仍會繼續；洽談中的訂單會自動取消。」
- 重新上架不跳確認。
- 成功 toast：下架「已下架」、重新上架「已重新上架」、刪除「已刪除」。
- 動作成功後重新載入 `/api/products/mine`、更新 tabs 數量，並觸發 `haisen:products-changed`；失敗顯示後端錯誤訊息並重新載入列表。
- 目前 tab 若已無資料，顯示該 tab 的空狀態，不自動切換 tab。
- 行動版導覽選單要完整顯示，不可被 `.nav__right` 壓成窄欄。

## 5. 交易房浮動購物車

- 位於訊息區頂端，`position: sticky; top: 0`，有背景與陰影。
- 訊息往上捲時購物車固定在最上方；訊息從下方通過。
- 購物車與展開後的面板同屬一個置頂容器；面板展開時取代購物車，訊息仍在下方捲動。
- 再次洽談購買會把商品加入或累加進同一筆草稿，不清空其他商品；因此購物車可能出現多列。
- 多商品時每個商品一列。
- 每列內容：魚種、處理方式（若有）、`剩 N 尾`、`N 元/台斤`、數量控制與 `移除`。
  - `剩 N 尾` 使用該商品目前可售尾數。
  - `N 元/台斤` 優先使用 `price_per_taijin`；沒有時顯示 `整批 NT$X`。
- 右側動作：空車顯示 `選購`，有商品顯示 `加購`，另有 `發送交易`。
- 發送交易面板內提供 `收起`；選購／加購面板底部提供 `取消` 與 `確認`。
- 對方有商品但草稿為空時顯示「尚未加入商品」、`選購` 與停用的 `發送交易`。
- 對方完全沒有商品時不顯示浮動購物車；房間只顯示訊息流與輸入框。草稿存在但對方商品已全數下架或刪除時，也視為沒有商品而隱藏空購物車。
- 買家可以逐項 `移除`、直接改數量；釣客唯讀。
- UI 不提供「清空全部」；要清空就逐項移除。
- 移除與改數量不留系統訊息；加購留一則。
- 進行中、已成交、已取消訂單維持唯讀，不提供移除或改數量。
- 購物車不顯示 `協商完畢`、`修改條件並重送`、狀態 pill、項目數／總尾數／小計摘要列。

## 6. 發送交易面板

- 由購物車的 `發送交易` 展開，展開後取代購物車，位於訊息區頂端。
- 面板右上提供 `收起`；按 `收起` 只收合面板，不送出。
- 排版：上方商品摘要（魚種、處理方式（若有）、`剩 N 尾`、每台斤或整批價格），接著 `數量`／`售價` 並排，下方 `面交時間`／`面交地點` 在左、`確認` 在右。
- 欄位：
  1. `數量`：只有一個商品時可編輯，範圍 1 到該商品可售尾數；多個商品時唯讀，顯示整單總尾數。
  2. `售價`：整單總價，預填目前訂單小計（`items_total`），可修改。
  3. `面交時間`：`datetime-local`。
  4. `面交地點`：文字，最多 100 字。
  5. `確認`：送出協議。
- 沒有 `取消` 按鈕；按 `收起` 離開。
- 驗證：數量必須是正整數且不超過可售；售價必須大於 0；面交地點必填；面交時間必填且有效。
- 送出流程：
  1. 若只有一個商品且數量有變，先 `PATCH /api/deals/items/:itemId` 更新數量。
  2. `POST /api/deals/propose`，帶 `final_price`、`meetup_location`、`meetup_time`。
  3. 收起面板，重新載入房間。
  4. 協議卡出現在訊息流；發起人看到無按鈕版本。
- 面板草稿值在收起後保留，送出成功或切換房間後清空。

## 7. 選購／加購面板

- 由購物車的 `選購`（空車）或 `加購`（有商品）展開，展開後取代購物車，位於訊息區頂端。
- 面板底部提供 `取消` 與 `確認`；`取消` 只收合面板，不送出。
- 清單：同一位釣客的公開商品（`listProducts({ seller_id, limit: 100 })` 只回 `ACTIVE`／`PARTIALLY_RESERVED`），**包含已加入訂單的商品**；`SOLD_OUT`／`DELISTED` 不會出現在清單。
- 每列內容：魚種、處理方式（若有）、`剩 N 尾`、價格（沒有每台斤時顯示整批價）、數量數字輸入與 `尾` 單位。
- 加購列不顯示 `weight_kg`（legacy）；舊資料的重量欄位保留在資料中，但不出現在畫面。
- 可再加購尾數 = 商品可售 − 該商品已在草稿中的尾數；0 時停用輸入。
- 底部：`取消`、`確認`。
- `取消`：收起面板，不改訂單。
- `確認`：收集所有數量大於 0 的列，呼叫批次端點一次加入，只留一則系統訊息；收起面板並重新載入房間。
- 沒有可選購商品時顯示「目前沒有可選購的商品」。
- 對方完全沒有商品時，購物車本身不顯示，因此也不會打開這個面板。

## 8. 協議卡

- 外觀沿用推薦卡：白底、16px 圓角、淡灰邊框與陰影；標題置中，魚種大字，狀態為右上圓形徽章，主要動作使用藍色按鈕。
- 卡片標題：`協議`。
- 狀態徽章：
  - `等待確認`（coral）
  - `已確認`（accent）
  - `已取消`（muted）
  - `已逾時`（muted）
- 內容：
  - 魚種：每個項目一行；單項顯示一個魚種，多項逐行顯示。
  - `販售數量：N 尾`（整單總尾數）。
  - `最終價格：NT$X`（`final_price`）。
  - `面交時間：…`
  - `面交地點：…`
- 按鈕權限：
  - 收件方（`initiator_id !== user.id`）且狀態為等待確認：`取消`、`確認`。
  - 發起人：不顯示按鈕。
  - 已確認／已取消／已逾時：雙方都不顯示按鈕。
- `確認` 呼叫 `POST /api/deals/respond`，`action: "AGREE"`；雙方輪詢後看到徽章 `等待確認` → `已確認`。
- `取消` 不直接送出，而是在協議卡位置換成「確認取消」卡。
- 卡片狀態文案 `CARD.confirmed` 為「已確認」；訂單列表仍使用「已成交」。
- 舊資料若已有 `rejected` 狀態，仍可顯示「已退回」，但新流程不再產生。
- 移除 `退回`、`NEGOTIATING` 重新送出流程與行內取消原因下拉選單。

## 9. 確認取消卡與取消訊息卡

**確認取消卡**（本地狀態，不是訊息）：

- 外觀沿用協議卡，輸入框與按鈕同樣使用圓角與藍色主要動作。
- 按下協議卡 `取消` 後，在協議卡位置顯示。
- 內容：標題 `確認取消`、提示 `請填寫取消原因`、textarea（必填，最多 200 字）、`取消`、`送出`。
- `取消`：移除確認取消卡，回到原本協議卡；協議卡仍可正常操作。
- `送出`：原因空白時顯示提示，不送出；呼叫 `POST /api/deals/cancel`，帶 `deal_id` 與 `note`。
- 後端設定 `cancel_reason: "OTHER"`、`cancel_note: note`、`deal_status: CANCELLED`，同步最新協議卡為 `cancelled`，並新增一張 `deal_cancelled` 卡片訊息。
- 確認取消卡只對按取消的人顯示；對方在看到取消訊息卡前不會看到這個本地卡片。

**取消訊息卡**：

- 外觀沿用協議卡，取消原因放在淡灰圓角區塊。
- 卡片型別：`deal_cancelled`。
- 標題：`協議已被取消`。
- 內容：`取消原因`＋自由文字；空白時顯示「未填寫」。
- 雙方都看得到，顯示在協議卡之後，作為這次取消的紀錄。

## 10. 重新發起協議

- 取消後畫面留在交易房。
- 購物車顯示最後一筆訂單的商品（魚種、剩餘尾數、每台斤價格）。
- 按 `發送交易` 時：
  - 若目前沒有進行中的草稿，呼叫 `POST /api/deals/reinitiate`，帶最後一筆已取消訂單的 `deal_id`。
  - 後端在同一間交易房建立新的 `DRAFT` 訂單，複製原項目與數量。
  - 每項數量上限為目前可售；可售 0 的項目略過並提示。
  - 只留一則系統訊息；建立成功後展開發送交易面板。
- 若沒有任何項目可重新發起，顯示「目前沒有可重新發起的商品」。
- 只有使用者自行取消（`cancel_reason = OTHER`）的訂單可以重新發起；逾時取消不提供。

## 11. 評價

### 11.1 交易房評價小卡

- 卡片標題：`評價`。
- `整體評分`＋五顆可點星星：預設 5 顆，點擊設定 1–5 星，可用鍵盤操作。
- 四個標籤，2×2 排列：`魚貨新鮮`、`準時守約`、`溝通良好`、`臨時放鳥`；最多選 3 個。
- 評語 textarea，placeholder `留下你的評價吧！`，最多 100 字。
- `確認` 送出。
- 移除 `已評價／待評價` pill 與 `包裝完善` 標籤。
- 已送出後：顯示「你已經送出評價。」；對方已評顯示「雙方都完成了。」；對方未評顯示「等待對方評價。」
- 前端與後端標籤清單同步為四個；`臨時放鳥` 仍是 `NO_SHOW_TAG`。

### 11.2 個人資訊頁的評價區（✅ 角色列表）

- 角色 tabs：兩種評價都有時顯示「買家給的評價」與「釣客給的評價」；只有一種時直接顯示該種，不顯示 tab。預設買家給的評價（釣客的評價）；沒有才切到釣客給的評價。
- 每個 tab 的摘要：平均分、五顆星、總數；分布 5→1，顯示數量與比例。少於 3 則不顯示分布。
- 分布長條可點擊篩選星等；再次點同一星等可清除；分布本身仍顯示全部，列表只顯示選取的星等。
- 排序以 `<select>` 提供最新（預設）、最高、最低。
- 每個 tab 各自保留排序與星等篩選；換排序或篩選時 offset 重設；重新載入頁面回到預設。
- 每頁 6 則；底部「載入更多」，沒有更多時不顯示。
- 評價卡：評價者頭像（沒有時首字）、名字（連個人資訊）、日期、星等、標籤、評語、商品照片。
- 商品照片：該筆訂單最多 3 張，超過顯示 `+N`；沒有照片顯示 placeholder；照片下方顯示魚種／商品名；不連商品頁、不做 lightbox。
- 日期：30 天內相對時間，超過 `YYYY/MM/DD`。
- 評價者只顯示名字與頭像，不顯示電話或地址。
- 桌面 3 欄、手機 1 欄；卡片高度自然，不強制等高。
- 空狀態「尚無評價」；星等篩選無結果顯示「沒有 N 星的評價」與清除入口；載入失敗顯示錯誤與重試。

## 12. 助手房小卡

### 12.1 詢價推薦小卡

- 橫式卡片：左側縮圖（約 155×90、圓角 10px），右側魚種；尾數與處理方式膠囊靠右並排。
- 卡片為白底、圓角 16px、淡灰描邊與柔和陰影；上下以淡灰分隔線切開。
- 下區左側直排 `整批售價`、`每台斤售價`（若有）與地區，右側藍色 `洽談購買`。
- 移除：重量、`深入諮詢`、每尾均價、數量下拉、`自動計算` 標記。
- 可售狀態：`available > 0` 顯示 `洽談購買`；`available <= 0` 顯示「洽談中，暫無法購買」或「已售出」；若舊訊息卡片帶 `status = DELISTED` 則顯示「已下架」，都不顯示按鈕。
- 推薦小卡沒有 `釣客資訊` 按鈕。
- `洽談購買` 以 `data-action="start-deal"` 啟動交易，預設數量 1。

### 12.2 行情小卡

- 助手房查詢行情成功時直接回傳行情卡，不再另回文字；查無行情或需要追問魚種時才回文字。
- 卡片標題：`行情卡`。
- 主資訊：魚種（`species_name`）＋平均價（`price_per_taijin` 元／台斤）。
- 範圍：縣市平均或全國平均（沿用 `marketScope`）。
- 走勢切換：`7日`／`30日`。
- 走勢圖：顯示最高／最低標記。
- 日期：交易日期＋`近 7／30 個交易日`；切換 7／30 日後分別顯示「近7個交易日」與「近30個交易日」。
- 重量試算：
  - 重量輸入框（數字，可空白）。
  - 單位切換：`台斤`／`公斤`，預設台斤。
  - `參考價格 = round(平均價 × 重量台斤)`。
  - 重量空白或非正數時，參考價格顯示 `—`。
  - 切換單位不改變重量數字，只以新單位重新計算參考價格（例如 2 台斤 NT$400 ↔ 2 公斤 NT$667）。
  - 即時計算，不打 API。
  - 標籤 `參考價格`，下方小字 `（依重量計算整批價格）`。
- 底部右下：`資料來源：農業部 漁業署`。
- 移除：`行情價參考`、`養殖價格`、官方名稱獨立行、`參考整批` 標籤。
- 每個訊息各自保存重量與單位，切換 7／30 日不重置。

### 12.3 草稿卡

- 內容：魚種、尾數、處理方式、整批售價、每台斤售價（若有）、照片縮圖。
- 不再顯示重量與 `自動計算`。
- 動作：`確認上架`、`修改草稿`、`取消上架`。
- 修改草稿以文字指定欄位；一次只改一個欄位，中途取消回到修改前草稿。

### 12.4 法規告知卡與取消上架確認卡

- 法規告知卡：漁業法與證照提醒、罰則、法規連結；動作 `我已了解並確認`、`取消`。
- 取消上架確認卡：`確定取消上架？此對話會刪除，並開啟新的 AI 對話。`；動作 `確定取消`、`繼續上架`。

## 13. 顯示規則

| 規則 | 內容 |
| --- | --- |
| 價格 | 一律「元」，千分位；商品卡標明 `每台斤售價`、`整批售價`；交易房、發送交易、選購只顯示每台斤價格（沒有時顯示整批價） |
| 重量 | 上架不填重量；`weight_kg` 為選填／legacy，舊資料保留但不顯示（商品卡、購物車、發送交易與選購列皆同）。行情卡的重量是使用者即時試算，不是商品重量 |
| 行情 | 行情卡只顯示平均價（元／台斤）、交易日期、來源、縣市或全國平均、7／30 交易日走勢與最高／最低；不顯示上價／中價／下價；商品卡不顯示行情 |
| 售價與成交 | 上架售價是釣客開價；成交價是協議金額；兩者可以不同，不得混用 |
| 商品標題 | `{魚種}（{尾數}尾 / {處理}）`；商品卡、推薦卡、交易房、協議卡只顯示魚種，長標題只留在系統訊息與訂單摘要 |
| 時間 | 訊息顯示相對時間或 `MM/DD HH:mm`；評價 30 天內相對、超過 `YYYY/MM/DD` |
| 狀態用語 | 上架中／洽談中／已售出／已下架；訂單用等待確認／已確認／已取消／已逾時，列表用「已成交」 |
| 個人資訊 | 公開頁只顯示名字、頭像、地區、成交數、驗證與角色評分；不顯示電話、地址 |
| 評價方向 | 「買家給的評價」是釣客的信用；「釣客給的評價」是買家的信用；不可寫成單獨的「買家評價」 |
| 購物車 | UI 可像購物車，但資料叫訂單草稿；「移除」不用「取消」 |
| 商品管理 | 自己的個人資訊頁可管理全部商品；別人的頁面只顯示可購買商品 |
| 查無 | 「暫無行情」「目前沒有符合條件的商品」，不得留空或填 0 |

## 15. 無障礙與互動細節

- 面板使用 `aria-live="polite"`，新訊息會被打字機唸出。
- 浮動按鈕有 `aria-expanded`、`aria-controls`、`aria-label`。
- 語音、相機、送出圖示都有 `aria-label`。
- 星星有 `aria-label`；不可點時使用 `role="img"`。
- 協議卡按鈕有明確文字；確認取消卡的 textarea 有 label。
- 浮動購物車不遮住焦點元素；鍵盤 Tab 可依序到購物車按鈕與訊息。
- 開啟面板時焦點移到輸入框；`Esc` 關閉。
- 法規告知的「漁業法」連結另開新視窗，有可讀的連結文字與 focus 樣式。
- 助手一次回覆多則訊息時，以該批第一則為滾動錨點；整批放得下才滾到底部。
